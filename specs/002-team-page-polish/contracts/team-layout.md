# Contract: Team 页布局行为（team-layout）

**Date**: 2026-10-12（rev：纳入 GitHub 标签规则与数据层最小改动口径） | **Spec**: [spec.md](../spec.md) | **消费方**: Team 页实现与验收（quickstart.md）、主页回归验证

本特性对外契约对象有二：① **Team 页（/team/）的布局行为**——"UI 契约"（界面在不同视口下 MUST 呈现的排布规则），也是后续任何样式改动的回归基线；② **维护者数据契约的一处最小扩展**（`students` / `graduates` 新增可选 `github` 字段 + 学生 `url→github` 迁移，字段约定见 [data-model.md](../data-model.md)）。

## 1. 视口行为矩阵（MUST）

| 视口 | Faculty 教师网格 | 在读学生分组 | Graduates 列表 |
| ---- | ---- | ---- | ---- |
| ≥ ~900px（含 1024 / ≥1280 验收档） | 两列（每列 ≥420px，恰好容器不足时自动单列） | 两组并排（PhD 左 / Master 右，每组 ≥320px） | **三列对齐生效**：姓名 / 学位·年份 / 去向各对齐到一致的列位置 |
| 768px | 单列（轨道贴合容器宽度） | 两组并排或堆叠由容器宽度自然决定（auto-fit） | 三列对齐生效（对齐下限即 768px） |
| < 768px（含 375px 验收档） | 单列，卡片完整可见 | 两组纵向堆叠 | **降级**为紧凑流式布局（不对齐三列，同类字段位置仍跨行一致），不溢出、不截断 |
| ≤ 640px | 教师卡片头纵向堆叠：照片在上、姓名/职称/方向在下（既有行为，保持） | 同上 | 同上 |

GitHub↗ 标签（`github` 非空时）在上述各档均随所在条目行内流动，不单独占轨道、不溢出。

## 2. 对齐规则（Graduates，≥768px）

- 同类字段的起始位置在所有行完全一致：第 1 列姓名、第 2 列学位·年份、第 3 列去向。
- 第 1、2 列为内容无关的固定宽度（按最宽实际内容 + 余量），第 3 列弹性吸收剩余宽度。
- `year` 缺失的行：第 2 列仅显示学位（如 `Master`），**列仍占位**，不影响其他行对齐，无多余分隔符。
- 去向文字过长：在第 3 列内换行，不溢出容器、不破坏其他列位置。
- **GitHub↗ 标签**（FR-010）：内联于第 3 列去向文字之后，不引入第 4 条轨道——前两列固定轨道与第 3 列起始位置不受任何影响；<768px 降级布局中随行内流动。`github` 为空的行不渲染标签、无占位残留。

## 3. 空白判定（四档验收视口）

设计意图（FR-004）：保持合理信息密度与视觉平衡——留白仅用于分组、层级、呼吸与聚焦；由固定尺寸、内容缺失或未自适应造成的大面积无意义空白视为缺陷。

判定口径（FR-004，分档）：视口 < 1280px 的各档（含 375 / 768 / 1024px），任一条目/卡片**内容右端的连续空白**超过其所在区域宽度的 FR-004 比例阈值即不达标；视口 ≥ 1280px（超宽屏）时，连续空白超过 FR-004 像素阈值即不达标（固定像素口径，不随区域宽度放大）。分档阈值的具体数值以 spec FR-004 为唯一规范源，本契约引用不复述。

- 在读学生条目：行采用两端分布（姓名居左、`Since 年份` 与备注居右），内容右端贴合分组列右缘 → 无右端空白；两端分布为合规形态，中间间隙同步判定（分档阈值见 FR-004），间隙过大同样不达标。
- 教师卡片：研究方向标签横向流式换行，填满卡片信息列；末行残余空白按上述分档口径实测验收（所在区域＝方向标签所在的研究方向信息列，即照片右侧 `.teacher-identity` 区域，FR-004）。
- 无年级（`grade` 为空）的学生条目：仅左侧姓名，不算违规。
- **GitHub↗ 标签计入条目内容**（FR-010 不破坏 FR-004）：学生条目标签属左簇（姓名后），中间间隙自左簇末端（含标签）起算；毕业生行标签在第 3 列内，右端空白自标签（如有）或去向文字末端起算。

## 4. 溢出保证（全视口）

- 四档验收视口 375 / 768 / 1024 / ≥1280px 下，Team 页无横向滚动、无内容裁切（教师卡片右侧完整可见）。
- 教师网格最小列宽 MUST NOT 超过容器可用宽度（`min(420px, 100%)` 语义）；方向标签优先整标签换行、单标签超长时标签内文字换行（FR-005），MUST NOT 依赖 `nowrap` 防溢出。
- 布局破损判定沿用 001：元素重叠、文字截断、内容溢出容器、非预期换行（另含"内容横向超出页面（视口）宽度范围"）。

## 5. 共享组件回归范围（FR-009）

`TeacherCard.astro` 同时服务于 Team 页（detailed）与主页 Team 概览区块（compact）：

- compact 模式样式行为不变（方向标签本就横向换行）；
- 主页（`index.astro`）四档视口下 MUST 无新增布局破损；
- `StudentGroup.astro` 仅 Team 页使用，无外部回归面。

## 6. 不变量（本特性 MUST NOT 改变）

- 数据层改动仅限：`students` / `graduates` 新增可选 `github` 字段、学生既有 GitHub 链接 `url→github` 迁移（FR-006）；`teachers` 数据、其余字段定义与数据内容、构建配置、CI 流程零改动；
- 页面展示的信息集合：教师（照片/姓名/职称/方向/邮箱/主页/bio）与学生（姓名/Since/备注/个人主页链接）不变；学生与毕业生新增 `GitHub↗` 标签（`github` 非空时，FR-010）；
- 视觉基调不变（色板、卡片风格、正文字号 ≥18px）；
- 零新增 JS 与运行时依赖。
