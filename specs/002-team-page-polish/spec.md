# Feature Specification: Team 页布局优化与移动端修复（Team Page Polish）

**Feature Branch**: `002-team-page-polish`

**Created**: 2026-10-11

**Status**: Clarified（2026-10-12）

**Input**: User description: "优化重建后的主页 Team 界面：1) 布局对齐优化（Graduates 部分年份、去向等排列对齐；消除 PhD Candidates 部分右侧（Since xxx 之后大片空白）、教师卡片右侧（研究方向右边空白）的大片空白）2) 修复移动端老师介绍卡片右侧内容超出屏幕、不能完整显示的 bug"

## Clarifications

### Session 2026-10-11

- Q: 可空字段（毕业生 year、在读学生 grade/note、教师 photo）值为空时如何展示？缺失字段的占位如何判定？ → A: 展示一律留空、缺失不填——不渲染任何占位文本或符号；既有列占位与布局保持规则不变。(CHK018；2026-10-12 CHK017 问询为同一问题，答案一致，已合并)
- Q: 学生或毕业生名单为空时如何处理？ → A: 保持既有友好占位文案行为，不隐藏区块（维持现状）。(CHK020)
- Q: 超宽屏（≥1280px 视口）下大片空白的像素阈值是多少？ → A: 内容右端连续空白 > 320px 即不达标（约一条学生分组最小宽度的空白）。(CHK021)
- Q: 320px 像素口径的适用范围？ → A: 仅 ≥1280px 超宽屏档采用像素判定；1024px–<1280px 档维持区域宽度 50% 比例判定。(CHK021)
- Q: 空白的设计原则（留白仅用于分组、层级、呼吸和聚焦，不应由固定尺寸、内容缺失或未自适应造成大面积无意义空白）如何定位？ → A: 作为 FR-004 的设计意图与缺陷成因判定，量化验收对象维持学生条目与教师卡片方向区不变。（2026-10-12 更新：量化验收对象已拓展至 Team 页内容区全部内容容器，见 Session 2026-10-12）
- Q: 教师研究方向标签的换行收纳规则？ → A: 优先整标签换行（标签内文字不断开）；仅当单个标签宽度超过可用宽度放不下时，才允许该标签内文字换行（列内换行兜底）；任何情况下不得溢出或截断。(CHK019)
- Q: 两端分布学生行的中间间隙（姓名与右侧 Since/备注之间）如何判定？ → A: 中间间隙过大同样视为大片空白不达标；阈值为对应档位右端口径的 1.25 倍（1024px–<1280px 档 ≤ 区域宽度 62.5%；≥1280px 档 ≤ 400px）；两端分布本身为合规形态。(CHK025)
- Q: 语义化 HTML/基础无障碍是否作为本次需求？ → A: 不作为需求：spec 不含且不新增无障碍要求（Constitution v2.0.0 已移除无障碍底线）。(CHK023)

### Session 2026-10-12

- Q: 四档视口下三个区块的期望布局是否形成完整矩阵？ → A: 毕业生去向列表在所有分辨率下都需要尽量对齐；两个空间利用问题（在读学生条目、教师卡片）在四档分辨率下都需保证无大量空白。(CHK002)
- Q: <768px 移动端 Graduates 如何保持排列整齐？ → A: 移动端可换用新的布局方式，保证内容整齐（同类字段位置仍跨行一致）。(CHK003)
- Q: 共享组件回归约束是否作为正式需求？ → A: 是。(CHK004)
- Q: 当前数据条目是否为正式需求内容？ → A: 当前条目仅为正式部署前测试视觉效果的占位数据，不作为正式需求；上线前将导入完整名单；本特性需确保各信息字段的完整性。(CHK005)
- Q: 改动范围边界？ → A: 仅改动 Team 页与主页的教师卡片（共享组件）。(CHK006)
- Q: "对齐"的可验证定义？ → A: 左对齐＝同类字段的起始位置跨行一致；居中对齐＝条目中心在一条直线上；右对齐＝同类字段的结束位置一致。(CHK008)
- Q: 布局破损判定口径？ → A: 沿用 001 四项口径，并新增"内容长度超过页面（视口）宽度范围"。(CHK009)
- Q: 移动端"完整显示"口径？ → A: 是——同时排除内容裁切不可见与横向滚动。(CHK010)
- Q: 空白判定是否同等适用于学生条目与教师卡片？ → A: 是；具体判定数值为默认口径，后续可能进一步调整。(CHK013)
- Q: "零数据改动"与按当前最宽取值定列宽的关系？ → A: 声明列对齐判定与具体数据取值无关——列宽按当前最宽值设计仅为实现选择，更长姓名/单位名出现时 MUST 在列内换行收纳且保持跨行对齐，未来导入完整名单后规则仍有据可依。(CHK014)
- Q: 优先级定级是否自洽？ → A: 经复核自洽（US1 P1 功能缺陷 > US2/US3 P2 > US4 P3，理由可复述）。(CHK015)
- Q: SC 是否全部客观可验？ → A: 是；US4 验证口径中的主观表述"卡片内无明显空旷区域"移除，统一引用 FR-004 判定，并新增 SC-006。(CHK016)
- Q: 学生（含毕业生）的 GitHub 链接如何展示与承载？ → A: 如有自己的 GitHub 链接，须单独以标签列出（如 `GitHub↗`）；数据层新增专用可选字段 `github` 承载，学生现有 GitHub 链接自 `url` 迁移（`url` 仅保留个人主页），学生与毕业生机制统一。
- Q: 空白判定适用范围是否拓展？ → A: 是——拓展至 Team 页内容区内的所有内容容器（含 Graduates 列表行、教师卡片内部各子容器、各区块/分组容器等嵌套容器）；判定基准为容器内最右内容元素右端至该容器右边缘的连续空白，阈值沿用分档口径；主页仅共享教师卡片组件随组件同规则判定，其余区域维持 FR-009 回归约束。
- Q: 页面级版式留白是否豁免？ → A: 豁免——主容器 max-width 1180px 居中在超宽屏两侧留出的版式边距（如 1920px 视口下每侧约 370px）属有意版式设计，不视为大片空白缺陷。
- Q: 毕业生个人主页链接如何承载与展示？ → A: graduates 数据新增可选 `url` 字段（与学生字段命名一致）；Graduates 列表行设独立链接列（姓名 / 学位 / 毕业年份 / 去向 / 链接五列），`Homepage↗` 与 `GitHub↗` 标签集中于链接列；有主页则展示、无则留空占位不渲染；三个主页取值经源页面核实：佀庆一→https://phoebussi.github.io/、杨泽娴→https://ccds.fzu.edu.cn/info/1204/11629.htm、刘源鑫→https://llyx97.github.io/（谭宇彤、温哲暂无）。
- Q: 毕业时间是否单独成列、排序规则？ → A: 是——学位与毕业年份拆为两列；排序：毕业年份降序，同年份内 PhD 在 Master 之前，无年份条目排在最后（同样 PhD 在 Master 之前）；同排序键条目保持数据文件相对顺序（稳定排序）；排序在渲染时完成，与数据文件条目顺序无关。
- Q: Graduates 列表满宽后的行内排布（第三轮用户裁定）？ → A: 列表采用满宽形态（不再按内容收缩），避免右侧无意义空白与因空间不足导致的文字换行：① 行左右 padding 对称（姓名距表格左缘＝链接标签距表格右缘）；② 姓名、学位、毕业年份左对齐，链接列标签右对齐（贴行右缘），去向列居中对齐且左右留较大间距（部分去向名称较长）；③ 各字段间 column-gap 适当加大。配套豁免：无任何外链标签的毕业生行（链接列空置系 FR-011 规格要求的内容缺失）在去向居中排布下产生的行右侧空白，豁免 FR-004 大片空白判定（类比学生无年级行既有豁免；详见 FR-004 豁免条款与 Edge Cases）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 移动端完整浏览教师卡片 (Priority: P1)

访客使用手机（竖屏，视口宽约 375px）打开 Team 页浏览 Faculty 部分：每张教师卡片（照片、姓名、职称、研究方向、邮箱、个人主页链接）完整显示在屏幕可视宽度内，卡片右侧内容不被截断，页面也无需横向滚动。当前缺陷：手机上教师卡片右侧无法全部显示。

**Why this priority**: 教师卡片在手机上右侧被裁切、信息不可见，属于内容不可达的功能性缺陷，对移动端访客构成可用性阻断；修复缺陷的优先级高于视觉打磨。

**Independent Test**: 在 375px 宽视口（及 768px 视口）下打开 Team 页，逐张核对教师卡片的照片、姓名、职称、研究方向标签、邮箱与主页链接均完整可见，页面无因内容过宽导致的横向溢出或裁切。

**Acceptance Scenarios**:

1. **Given** 移动端访客打开 Team 页， **When** 页面加载完成， **Then** 每张教师卡片完整落在屏幕可视宽度内，卡片右边缘及右侧内容（研究方向标签、链接等）均可见、无截断。
2. **Given** 375px 视口， **When** 从上到下浏览整个 Team 页（Faculty、在读学生、Graduates）， **Then** 所有区块无布局破损（无元素重叠、文字截断、内容溢出容器、非预期换行、内容横向超出页面（视口）宽度范围——沿用 001 规格的布局破损判定并按 CHK009 扩展）。
3. **Given** 768px 视口（平板竖屏）， **When** 浏览教师卡片， **Then** 卡片同样完整显示，无右侧截断。

### User Story 2 - 毕业生去向列表列对齐与排序 (Priority: P2)

访客浏览 Graduates 部分时，每行毕业生的姓名、学位、毕业年份、去向、链接五类字段分别按列纵向对齐：所有行的姓名起始位置一致、学位起始位置一致、毕业年份起始位置一致、去向中心位置一致（居中对齐）、链接列标签结束位置一致（右对齐、贴行右缘）——≥768px 视口采用混合对齐口径（2026-10-12 第三轮裁定，见 FR-003），访客可以按列纵向扫描（例如按年份比较毕业去向），而不是看到参差不齐的错位排列。列表整体按毕业年份降序排列（同年份内博士在前、硕士在后；无年份条目排在最后，同样博士在前），访客自上而下读到的是最新毕业在前、学位层次清晰的名单。该对齐要求在所有分辨率下均须满足：≥768px 视口采用五列列对齐形态；<768px 视口可换用更适合移动端的布局形态，但同类字段位置仍须跨行一致，保持内容整齐。

**Why this priority**: 毕业生去向是招生访客关注的核心信息之一，列对齐直接提升可读性与信息获取效率；这是用户本次布局优化的首要明确诉求，但属视觉质量问题，优先级次于移动端缺陷。

**Independent Test**: 在各档验收视口（375px / 768px / 1024px / ≥1280px）打开 Team 页 Graduates 部分，任取两行，核对同类字段（姓名 / 学位 / 毕业年份 / 去向 / 链接列）的位置跨行一致——≥768px 视口下按混合口径核对：姓名 / 学位 / 毕业年份起始位置处于同一水平位置、去向中心位置在同一直线上、链接列标签结束位置一致；<768px 视口下在窄屏布局形态中同类字段位置同样跨行一致。同时自上而下核对列表顺序满足 FR-012（年份降序 → 同年 PhD 在前 → 无年份最后）。

**Acceptance Scenarios**:

1. **Given** Graduates 列表含多条记录， **When** 在任一档验收视口（375 / 768 / 1024 / ≥1280px）浏览， **Then** 同类字段的位置跨行一致：≥768px 视口下每行的姓名、学位、毕业年份、去向、链接列分别对齐到一致的列位置（姓名 / 学位 / 毕业年份起始位置相同，去向中心位置相同（居中），链接列标签结束位置相同（右对齐）——FR-003 混合口径）；<768px 视口下采用窄屏整齐布局，同类字段位置同样跨行一致，不出现参差错位。
2. **Given** 某毕业生无毕业年份（如数据中 year 为空的条目）， **When** 该行展示， **Then** 学位照常显示（如 Master）、毕业年份列留空占位，年份缺失不影响本行及后续行的列对齐，也不出现多余分隔符或占位残留，且该行按 FR-012 排在列表最后。
3. **Given** 某毕业生去向文字较长（如"北京大学（攻读博士）"）， **When** 该行展示， **Then** 去向文字在本列内正常换行，不破坏整行结构与其他列的对齐，也不溢出容器。
4. **Given** 某毕业生有 GitHub 链接（`github` 字段非空）， **When** 该行展示， **Then** 以独立标签（如 `GitHub↗`）列出于链接列，且不破坏本行及跨行对齐（FR-010/FR-011）。
5. **Given** 某毕业生有个人主页（`url` 字段非空）， **When** 该行展示， **Then** 以独立标签（如 `Homepage↗`）列出于链接列；无主页的毕业生链接列留空占位、不渲染该标签（FR-011）。
6. **Given** Graduates 列表含不同年份与学位的条目， **When** 页面渲染， **Then** 列表顺序满足 FR-012：毕业年份降序，同年份内 PhD 在 Master 之前，无年份条目排在最后（组内同样 PhD 在前），渲染顺序与数据文件条目顺序无关。

### User Story 3 - 在读学生列表空间利用 (Priority: P2)

访客浏览 PhD Candidates 与 Master's Students 部分时，每个学生条目（姓名、Since 年份、备注、GitHub 标签如有）之后的右侧不再出现大片连续空白；分组区域的宽度与其内容相称，页面整体紧凑均衡，而不是每行 "Since xxx" 之后直到分组右边缘全部空置。该要求在四档验收视口（375px / 768px / 1024px / ≥1280px）下均须满足。

**Why this priority**: 大片空白使页面显得空旷、不均衡，削弱学术主页的专业观感；与 Story 2 同属用户明确提出的布局问题，但只影响观感不影响信息获取。

**Independent Test**: 在四档验收视口（375px / 768px / 1024px / ≥1280px）浏览学生分组，检查任一学生条目内容末端至其所在分组区域右边缘的连续空白：视口 < 1280px 的各档（含 375 / 768 / 1024px）不超过分组区域宽度的 50%，≥1280px 档不超过 320px；两端分布行的中间间隙 < 1280px 的各档不超过分组区域宽度的 62.5%、≥1280px 档不超过 400px（"大片空白"判定标准，见 FR-004）。

**Acceptance Scenarios**:

1. **Given** 在任一档验收视口（375 / 768 / 1024 / ≥1280px）浏览 PhD Candidates / Master's Students， **When** 查看任一学生条目， **Then** 条目内容右侧的连续空白与两端分布中间间隙均满足 FR-004 判定（右端：< 1280px 各档 ≤ 分组区域宽度的 50%、≥1280px 档 ≤ 320px；中间间隙：< 1280px 各档 ≤ 分组区域宽度的 62.5% / 400px）。
2. **Given** 某学生无年级信息（数据中 grade 为空、不显示 Since）， **When** 该条目展示， **Then** 行内布局依然整齐，无异常空白或错位。

### User Story 4 - 教师卡片空间利用 (Priority: P3)

访客浏览 Faculty 教师卡片时，卡片内部横向空间利用合理：照片与姓名/职称/研究方向区域的排布与卡片宽度相称，研究方向区域右侧不再留大片空白，卡片整体视觉均衡。该要求在四档验收视口（375px / 768px / 1024px / ≥1280px）下均须满足。

**Why this priority**: 教师卡片内的空白只影响观感、不阻断任何信息获取，问题颗粒度也最细，优先级最低。

**Independent Test**: 在四档验收视口（375px / 768px / 1024px / ≥1280px）浏览教师卡片，核对研究方向区域右侧的连续空白满足 FR-004 判定（< 1280px 各档 ≤ 研究方向信息列宽度的 50%；≥1280px 档 ≤ 320px）。

**Acceptance Scenarios**:

1. **Given** 在任一档验收视口（375 / 768 / 1024 / ≥1280px）浏览教师卡片， **When** 查看任一卡片的研究方向部分， **Then** 研究方向区域右侧的连续空白满足 FR-004 判定（< 1280px 各档 ≤ 研究方向信息列宽度的 50%；≥1280px 档 ≤ 320px）。
2. **Given** 某老师研究方向标签文字较长， **When** 桌面端展示， **Then** 标签按 FR-005 规则收纳：优先整标签换行，单标签超长时该标签内文字换行；不溢出、不截断。

### Edge Cases

- 可空字段值为空时展示一律留空，不渲染占位文本或符号（如 N/A、— 等）；各字段既定的占位对齐与布局保持规则不变。
- 毕业生无毕业年份（year 为空）：学位照常展示、毕业年份列留空占位并保持跨行对齐，不显示多余分隔符；排序时该条目置于列表最后（FR-012）。
- 毕业生去向单位名较长或中英混排：列内正常换行，不破坏对齐、不溢出容器。
- 在读学生无年级（grade 为空、无 Since）：行内布局保持整齐。
- 在读学生带备注（note 字段非空）：备注展示不破坏行内布局与空间利用。
- 教师无照片（photo 为空）：卡片布局正常，不因缺图产生异常空白或错位。
- 教师研究方向标签文字过长：优先整标签换行；仅当单个标签宽度超过卡片可用宽度时，允许该标签内文字换行（字符级断行）收纳。桌面端与移动端同规则，绝不溢出屏幕、不截断。
- 学生或毕业生名单为空：保持既有友好占位文案行为，不隐藏区块。
- 学生或毕业生带 GitHub 链接（`github` 字段非空）：以独立标签（如 `GitHub↗`）展示（毕业生置于链接列），不破坏所在行的对齐、换行与空间利用判定；桌面端与移动端同规则（FR-010/FR-011）。
- 毕业生带个人主页（`url` 字段非空）：以 `Homepage↗` 标签展示于链接列（FR-011）；同时有主页与 GitHub 的毕业生两标签并列；无主页的毕业生链接列留空占位，不渲染占位文本或符号。
- 毕业生行无任何外链标签（`url` 与 `github` 均为空，如谭宇彤、温哲）：链接列空置系 FR-011 规格要求的内容缺失；满宽 + 去向居中排布下该行右侧空白豁免 FR-004 大片空白判定（2026-10-12 用户裁定，类比"学生无年级"既有豁免）。有外链标签的行仍照常受 FR-004 约束。
- 同年份且同学位的毕业生条目：保持数据文件中的相对顺序（稳定排序，FR-012）。
- 超宽屏（≥1280px）下页面主容器居中版式的两侧边距：属有意版式设计，豁免于 FR-004 大片空白判定（见 FR-004 豁免条款）。
- 更长姓名或去向单位名（如未来导入完整名单后出现）：在所在列内换行收纳，不破坏跨行对齐（列对齐判定与具体数据取值无关，FR-003）。
- 超宽屏（≥1280px）：对齐与空白判定标准同样适用，空白按 320px 像素口径判定（FR-004），不因容器变宽重新出现大片空白。
- 窄视口（<768px）下 Graduates 换用窄屏友好的整齐布局形态（同类字段位置仍跨行一致），以避免小屏幕溢出，不退化为参差错位的排布。
- 共享的教师卡片组件同时服务 Team 页与主页概览区块：主页教师卡片属于本次改动范围（随共享组件改动同步更新展示），主页四档视口下 MUST NOT 出现新的布局破损（FR-009）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Team 页 MUST 在 375px 与 768px 视口下无布局破损——无元素重叠、文字截断、内容溢出容器、非预期换行、内容横向超出页面（视口）宽度范围（沿用 001 规格的四项判定口径，并新增"内容长度超过页面范围"一项）；特别是每张教师卡片 MUST 完整显示在可视区域内，右侧内容（研究方向标签、邮箱、主页链接等）不被截断。
- **FR-002**: Team 页全部区块 MUST 随视口宽度流式自适应，在四档验收视口（375px / 768px / 1024px / ≥1280px）下均不因内容过宽出现横向滚动或内容裁切。
- **FR-003**: Graduates 列表 MUST 在全部四档验收视口（375px / 768px / 1024px / ≥1280px）下实现同类字段对齐。对齐判定口径：左对齐＝同类字段的起始位置跨行一致；居中对齐＝条目中心在一条直线上；右对齐＝同类字段的结束位置一致。本列表 ≥768px 视口采用混合对齐口径（2026-10-12 第三轮用户裁定）：姓名、学位、毕业年份左对齐（起始位置跨行一致）；去向居中对齐（各行中心点在同一直线上，左右留较大间距——部分去向名称较长）；链接列标签右对齐（结束位置跨行一致、贴行右缘 padding）；<768px 窄屏形态维持同类字段位置跨行一致。≥768px 视口下所有行的姓名、学位、毕业年份、去向、链接五类字段分别对齐到一致的列位置（毕业年份单独成列；链接列为集中放置外链标签的独立列，见 FR-011）；<768px 视口下 MUST 换用窄屏友好的整齐布局形态，同类字段位置仍跨行一致，不得退化为参差错位的排布。字段缺失（如无年份、无链接）时 MUST 保持列占位（缺失字段不填，不渲染占位文本或符号），不影响其他行的列位置；文字过长时 MUST 在本列内换行，不破坏对齐。列对齐判定与具体数据取值无关：更长姓名/单位名（如未来导入完整名单后出现）按列内换行收纳，不破坏跨行对齐。
- **FR-004**: Team 页内容区内的所有内容容器 MUST NOT 在四档验收视口（375px / 768px / 1024px / ≥1280px）任一档下出现"大片空白"——设计意图：保持合理信息密度与视觉平衡，留白仅用于分组、层级、呼吸与聚焦；由固定尺寸、内容缺失或未自适应造成的大面积无意义空白视为缺陷。判定基准：任一容器内最右内容元素的右端至该容器右边缘的连续空白。判定标准：视口 < 1280px 的各档（含 375 / 768 / 1024px），超过该容器宽度的 50% 即视为大片空白；视口 ≥ 1280px（超宽屏）时，超过 320px 即视为大片空白（固定像素口径，不随容器宽度比例放大）。两端分布的条目（如学生行姓名居左、Since 年份与备注居右）为合规形态，其中间间隙同步判定：视口 < 1280px 的各档中间间隙超过容器宽度 62.5%、视口 ≥ 1280px 时超过 400px（右端口径的 1.25 倍）即视为大片空白。适用范围：Team 页内容区内的所有内容容器——含学生分组条目、教师卡片及其内部各子容器、Graduates 列表行、各区块与分组容器等，嵌套容器逐层适用；共享教师卡片组件在主页的实例随组件同规则判定，主页其余区域维持 FR-009 回归约束。豁免：页面主容器居中版式（max-width 1180px）在超宽屏两侧留出的版式边距属有意设计，不视为缺陷；无任何外链标签的毕业生行在去向居中排布下的行右侧空白系链接列空置（内容缺失，FR-011 规格要求）所致，不视为缺陷（2026-10-12 用户裁定，类比学生无年级行豁免）；导航栏、页脚等页面框架级元素不属于本特性改动范围。各阈值具体数值为默认验收口径，后续可调整（见 Assumptions）。
- **FR-005**: 教师卡片内全部内容（照片、姓名、职称、研究方向标签、邮箱、主页链接）MUST 随卡片可用宽度自适应收纳，MUST NOT 在任何视口下溢出卡片或屏幕。研究方向标签的收纳规则：优先以整个标签为单位换行（标签之间断行、标签内文字不断开）；仅当单个标签自身宽度超过卡片可用宽度时，采用该标签内文字换行（字符级断行）收纳。
- **FR-006**: 本次优化以表现层（页面模板与样式）为主；数据层改动 MUST 限定为链接展示与毕业生信息结构所需的最小调整——(a) 为学生（students）与毕业生（graduates）新增可选 `github` 字段，并将学生现有 `url` 字段中的 GitHub 链接取值迁移至 `github`（`url` 此后仅承载个人主页链接）；(b) 为毕业生（graduates）新增可选 `url` 字段（个人主页链接，与学生字段命名一致），并在当前占位数据中填入三个已核实的主页取值：佀庆一→`https://phoebussi.github.io/`、杨泽娴→`https://ccds.fzu.edu.cn/info/1204/11629.htm`、刘源鑫→`https://llyx97.github.io/`（谭宇彤、温哲暂无主页，留空）。除此以外 MUST NOT 修改任何其他字段定义与数据内容（teachers 数据维持现状），MUST NOT 改变页面展示的其他信息内容（Constitution 原则 II）。
- **FR-007**: 布局优化 MUST 保持既有信息完整展示：毕业生仍展示姓名、学位、毕业年份（如有，单独成列）、去向、GitHub 链接与个人主页链接（如有，按 FR-010/FR-011 以独立标签集中于链接列展示）；在读学生仍展示姓名、Since 年份（如有）、备注（如有）、个人链接及 GitHub 链接（如有，按 FR-010 独立标签展示）；教师卡片仍展示照片、姓名、职称、研究方向、邮箱、主页链接与简介（bio）。各信息字段 MUST 结构完整（可空字段允许为空、缺失不填）；当前数据条目仅为测试视觉效果所用、不作为正式需求内容（见 Assumptions）。
- **FR-008**: 视觉风格 MUST 保持简洁学术化，MUST NOT 引入装饰性动效或新的运行时依赖（Constitution 原则 IV/V）。
- **FR-009**: 变更后站点 MUST 仍通过既有构建与 CI 门禁（数据校验 + 构建检查）并正常部署；若共享组件的修改波及主页等其他页面，受影响页面 MUST 保持无布局回归。
- **FR-010**: 学生（含在读学生与毕业生）如有自己的 GitHub 链接（`github` 字段非空），MUST 单独以标签列出（如 `GitHub↗`，链接指向其 GitHub 页面）；标签展示 MUST 不破坏所在条目的空间利用（FR-004）判定——毕业生行的标签集中于链接列（FR-011）、并作为链接列内容参与 FR-003 跨行对齐；在读学生条目的标签随行内流动、不破坏行内布局（FR-002）；桌面端与移动端同规则；`github` 字段为空时 MUST 不渲染该标签。
- **FR-011**: Graduates 列表行 MUST 设独立的链接列（位于去向列右侧），集中放置毕业生的外链标签：个人主页（`url` 字段非空）以 `Homepage↗` 标签展示，GitHub（`github` 字段非空）以 `GitHub↗` 标签展示（FR-010）；对应字段为空的行 MUST 不渲染相应标签、链接列保留空占位。链接列 MUST 作为独立列参与 FR-003 跨行对齐，标签展示 MUST 不破坏 FR-004 空白判定，桌面端与移动端同规则。
- **FR-012**: Graduates 列表 MUST 按以下顺序渲染：毕业年份（`year`）降序；同年份内 PhD 在 Master 之前；无年份（`year` 为空）的条目排在全部有年份条目之后，组内同样 PhD 在 Master 之前；同排序键（年份与学位均相同）的条目保持数据文件中的相对顺序（稳定排序）。排序 MUST 在渲染时完成，与 graduates.json 中的条目顺序无关（Constitution 原则 II）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四档验收视口（375px / 768px / 1024px / ≥1280px）下 Team 页布局破损数为 0（判定口径：元素重叠、文字截断、内容溢出容器、非预期换行、内容横向超出页面（视口）宽度范围）。
- **SC-002**: 移动端（375px 与 768px 视口）下教师卡片完整可见率达 100%——无右侧截断、无横向滚动。
- **SC-003**: 全部四档验收视口下 Graduates 列表 100% 的行满足同类字段位置跨行一致（≥768px 视口为姓名 / 学位 / 毕业年份 / 去向 / 链接列五列按 FR-003 混合口径对齐，<768px 视口为窄屏整齐布局下的位置一致；含字段缺失的行保持占位对齐）。
- **SC-004**: 四档验收视口下 Team 页内容区全部内容容器（含学生分组条目、教师卡片及其子容器、Graduates 列表行、各区块/分组容器）满足 FR-004 空白判定标准的比例达 100%（版式级豁免与无外链标签毕业生行豁免除外；右端：< 1280px 各档按容器宽度 50%、≥1280px 档按 320px 像素；两端分布行中间间隙按 62.5% / 400px）。
- **SC-005**: 变更合入后构建与部署流程通过率 100%，线上 Team 页及受波及页面渲染正常。
- **SC-006**: 有 GitHub 链接（`github` 非空）的学生与毕业生条目 100% 以独立标签（如 `GitHub↗`）展示，且不引入 FR-003 对齐或 FR-004 空白判定违规；`github` 为空的条目不出现该标签。
- **SC-007**: 有个人主页（`url` 非空）的毕业生条目 100% 以独立标签（如 `Homepage↗`）展示于链接列，且不引入 FR-003 对齐或 FR-004 空白判定违规；`url` 为空的条目不出现该标签、链接列留空占位。
- **SC-008**: Graduates 列表 100% 按 FR-012 规定顺序渲染（毕业年份降序 → 同年份 PhD 在前 → 无年份条目最后），渲染顺序与数据文件条目顺序无关。

## Assumptions

- 本特性改动范围为 Team 页（/team/）与主页的教师卡片（共享 TeacherCard 组件，允许随组件改动同步更新展示）；主页其余区域与其他页面不在改动范围，且不得出现布局回归（FR-009）。
- 沿用 001 规格的多设备验收约定：四档视口 375px / 768px / 1024px / ≥1280px，及布局破损判定口径（元素重叠、文字截断、内容溢出容器、非预期换行，另按 CHK009 新增"内容横向超出页面（视口）宽度范围"）。
- "大片空白"的量化判定（FR-004 分档阈值）为本次设定的默认验收口径，后续可能进一步调整具体数值（CHK013）；FR-004 为该阈值的唯一规范表述，contract / quickstart / tasks 等下游文档一律引用 FR-004、不复述具体数值。
- 外链标签呈现文本沿用组件既有模式：`Homepage ↗` / `GitHub ↗`（文本与箭头间含一个空格）；spec 全文 `Homepage↗` / `GitHub↗` 为等价简称，字符间距不作规范性验收项，标签的规范性要求以 FR-010 / FR-011 的语义、链接指向与布局约束为准。
- 窄视口（<768px）下 Graduates 采用窄屏友好的整齐布局形态（同类字段位置仍跨行一致），优先保证不溢出（CHK002/CHK003）。
- 当前数据条目（教师 5 人、在读学生若干、毕业生 5 条）仅为正式部署前测试视觉效果的占位数据，不作为正式需求内容；上线前将导入完整名单。本特性保障各信息字段的完整性与布局规则的健壮性——列对齐判定与具体数据取值无关，更长内容按列内换行收纳、不破坏对齐（CHK005/CHK014）。
- 数据层改动仅限链接展示与毕业生信息结构所需：为学生与毕业生新增可选 `github` 字段并迁移学生现有 GitHub 取值；为毕业生新增可选 `url` 字段并填入三个已核实的主页取值（FR-006）；除此以外数据文件字段与内容不变，其余优化仅通过模板与样式实现（Constitution 原则 II）。
- 三个毕业生主页 URL 已对照源页面核实归属（2026-10-12）：佀庆一→phoebussi.github.io、杨泽娴→ccds.fzu.edu.cn/info/1204/11629.htm、刘源鑫→llyx97.github.io；谭宇彤、温哲暂无主页。
- Graduates 排序在渲染时完成（FR-012），与数据文件条目顺序无关；「列对齐判定与具体数据取值无关」的既有约定同样适用于毕业年份列与链接列。
- 站点技术栈、构建流程与部署方式不变（Constitution 原则 III）。
- 重排版不引入语义化 HTML 结构与基础无障碍（a11y）要求：spec 不含且不新增此类需求（Constitution v2.0.0 已移除无障碍底线）。
