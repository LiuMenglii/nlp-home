# Quickstart: Team 页布局优化验证指南

**Date**: 2026-10-12（rev2：纳入五列对齐、链接列、FR-012 排序与 FR-004 全容器空白判定验证；rev3（同日第三轮用户裁定）：Graduates 满宽形态、混合对齐口径与无外链行豁免验证） | **Spec**: [spec.md](./spec.md) | **布局契约**: [contracts/team-layout.md](./contracts/team-layout.md)

模板/scoped CSS 改动 + 最小数据层扩展（学生 4 条 GitHub 链接 `url→github` 迁移已合入；毕业生新增 `url` 字段与 3 条主页取值）；无新依赖、无新 JS。验证 = 机器门禁（check + build）+ 浏览器手动视口矩阵。"大片空白"判定的分档阈值以 spec FR-004 为唯一规范源，本文引用不复述具体数值。

## 前置条件

- Node.js ≥ 22，仓库根目录已 `npm install`
- 浏览器 DevTools 响应式模式（或等价的视口宽度调节）

## 启动

```bash
npm run dev        # http://localhost:4321/team/
```

构建产物验证（最终验收前执行一次）：

```bash
npm run check && npm run build && npm run preview
```

## 验证矩阵

对照布局契约 [team-layout.md](./contracts/team-layout.md) 的视口行为矩阵逐项核对。

### 1. 移动端缺陷修复（Story 1 / FR-001、FR-002）— 视口 375px 与 768px

1. 打开 `/team/`，Faculty 部分每张教师卡片**完整落在可视宽度内**：研究方向标签、邮箱、Homepage 链接均可见，右边缘无截断。
2. 整页从上到下（Faculty → PhD/Master → Graduates）无横向滚动条、无内容被裁切。
3. 布局破损检查（001 口径 + CHK009 扩展）：无元素重叠、文字截断、内容溢出容器、非预期换行、内容横向超出页面（视口）宽度范围。

### 2. Graduates 五列对齐与排序（Story 2 / FR-003 / FR-011 / FR-012）— 视口 ≥768px

1. 任意两行毕业生对比：姓名、学位、毕业年份的起始位置分别处于同一水平位置，去向中心位置一致（居中对齐），链接列标签结束位置一致（右对齐、贴行右缘）——混合对齐口径见 FR-003（学位与毕业年份已拆列）。
2. 无年份条目（谭宇彤、温哲）：学位照常显示 `Master`、毕业年份列留空占位，其他行对齐不受影响、无多余分隔符，且按 FR-012 排在列表最后。
3. 长去向（"北京大学（攻读博士）"）：在第 4 列（去向列）内正常换行，不溢出、不错位。
4. 视口调至 <768px：列表降级为窄屏整齐布局（五字段逐行堆叠，同类字段位置仍跨行一致；有标签的链接行右对齐贴右缘），不溢出。
5. 排序核对（FR-012 / SC-008）：自上而下顺序为 杨泽娴（2025·PhD）→ 佀庆一（2024·PhD）→ 刘源鑫（2021·Master）→ 谭宇彤、温哲（无年份组，保持数据文件相对顺序）；可临时打乱 `graduates.json` 条目顺序后重新构建核对——渲染顺序不变（验证后还原）。
6. 链接列（FR-011）：佀庆一、杨泽娴、刘源鑫的链接列显示 `Homepage↗` 标签（分别指向 phoebussi.github.io / ccds.fzu.edu.cn/info/1204/11629.htm / llyx97.github.io，新标签打开）；谭宇彤、温哲链接列留空占位、不渲染占位文本或符号；当前数据均无 `github` 值，全部行不渲染 `GitHub↗` 标签（如本地验证标签形态，可临时给某条加 `"github": "https://github.com/octocat"` 后核对：标签与 `Homepage↗` 并列于链接列、不破坏五列对齐——验证后还原）。

### 3. 学生列表空白（Story 3 / FR-004）— 视口 375 / 768 / 1024 / ≥1280px

1. PhD Candidates / Master's Students 每行：姓名居左，`Since 年份`（及备注如有）靠右，两侧内容朝中间收拢（姓名自分组左缘内收、`Since`/备注自分组右缘内收，收拢量按四档视口实测校准）——中间间隙与收拢产生的两端空白均须满足 FR-004 分档口径（分档阈值见 spec FR-004）。
2. 无年级条目（李江楠）：仅左侧姓名（及其 GitHub↗ 标签），行整齐不错位。

### 4. 教师卡片空白（Story 4 / FR-004）— 视口 375 / 768 / 1024 / ≥1280px

1. 每张卡片：研究方向标签横向流式排布（优先整标签换行，单标签超长时标签内文字换行），标签区域右侧无大片空白（分档阈值见 spec FR-004；所在区域＝研究方向信息列，即照片右侧 .teacher-identity）。
2. 教师无照片时（可临时注释 `photo` 字段于本地验证）：卡片头排布正常，无异常空白或错位。

### 4'. 全容器空白判定（FR-004 适用范围拓展 / SC-004）— 视口 375 / 768 / 1024 / ≥1280px

1. 逐层检查 Team 页内容区全部内容容器：学生分组条目、教师卡片及其内部子容器（方向标签区、链接区、bio 区）、Graduates 列表行、各区块与分组容器——任一容器内最右内容元素右端至该容器右边缘的连续空白满足分档阈值（Graduates 列表满宽；有外链标签的行自链接列最右标签起算——标签右对齐后右端空白 ≈ 行右 padding）。
2. 豁免项核对：主容器 max-width 1180px 居中版式在超宽屏两侧的边距不计为缺陷；无任何外链标签的毕业生行（谭宇彤、温哲）右侧空白不计为缺陷（链接列空置属 FR-011 规格要求的内容缺失，2026-10-12 用户裁定）；导航栏、页脚等页面框架级元素不在判定范围。

### 5. GitHub / Homepage 标签（FR-010 / FR-011 / SC-006 / SC-007）— 视口 375 / 768 / 1024 / ≥1280px

1. 带 GitHub 链接的学生（李江楠、张瀚文、郑明钰、刘正宵）：姓名后显示 `GitHub↗` 标签，链接指向其 GitHub 个人页（新标签打开）；姓名本身不再可点击（`url` 已迁移置 null）。
2. 杨晨旭：无 `GitHub↗` 标签，姓名仍链接到个人主页（`url` 保留）。
3. 季慧山、刘曦雨、顾佴彬：无 `GitHub↗` 标签、无占位残留。
4. 毕业生 `Homepage↗` 标签见 §2.6；标签不破坏所在条目的对齐（FR-003/FR-011）与空白判定（FR-004）：学生行标签计入左簇、中间间隙仍达标；毕业生行标签集中于链接列、右端空白自最右标签起算。
5. 375px 视口：标签随行内流动，不溢出、不截断。

### 6. 主页回归（FR-009）— 视口 375 / 768 / 1024 / ≥1280px

1. 打开 `/`（主页）：Team 概览区块的 compact 教师卡片在四档视口下无新增布局破损（对比改动前行为；共享卡片实例同 FR-004 空白判定规则）。
