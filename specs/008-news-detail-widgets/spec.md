# Feature Specification: 新闻详情页重点控件与三论文解读新闻（News Detail Widgets）

**Feature Branch**: `008-news-detail-widgets`

**Created**: 2026-10-23

**Status**: Clarified

**Input**: User description: "增加一些新闻详细页的控件，同时写一篇详细的 news 来展示这些控件。这篇详细的 news 是对三篇论文的解读（一个新闻解释三篇相关的论文），Self-distilled rlvr、Near-Future Policy Optimization、Co-Evolving Policy Distillation。需要增加的控件包括：- 高亮块：一个圆角矩形框，有底色，用于展示某些重点；- （类似于）代码块：用来展示 bib 引用条目，可以一键复制；这个块可以横向滚动。这些控件要可以被一些命令调用，让后续的维护者可以直接通过写 markdown 来调用这些格式。记得同时写一个 markdown 的编辑文档来解释这些控件的用法。"

**参考资料**: 用户提供的参考文章 [《让大模型学会「自己教自己」！京东&中科院信工所连发三篇论文定义Self-Taught RLVR》](https://mp.weixin.qq.com/s/YsyfW-FMGJ-p5mrEBKA_1g)（量子位 QbitAI，2026-05-19）。该文解读的正是本次三篇论文，可作为写作结构、比喻与横向对比方式的参考；论文事实仍以论文原文为准。按用户决定，本站不设“参考解读”署名或链接。

## 目标与范围

本特性交付三部分内容：

1. **新闻详情页新增三种可复用内容控件**：
   - **高亮块**：圆角矩形、带底色的重点内容容器，带左侧强调竖线，用于在长文中突出关键结论、定义或提示。
   - **BibTeX 引用块**：类似代码块的等宽展示区，专门承载论文 BibTeX 条目；提供固定尺寸的图标复制按钮，内容超宽时在块内横向滚动。
   - **表格块**：用 `:::table[可选标题]` 包裹标准 Markdown 表格，带可选标题/图注；在窄视口下表格于容器内横向滚动，页面本身不出现横向滚动。
2. **新增一篇详细新闻**：一篇中文长文，以“一个新闻解读三篇相关论文”的形式，解读 Self-Distilled RLVR（RLSD）、Learning from the Near Future: Temporal Self-Distillation for RLVR（NPO 机制）、Co-Evolving Policy Distillation（CoPD）。文章以参考文章的“模型自己教自己（Self-Taught RLVR）”为统一叙事，采用“总—分—总”结构，在文中实际使用三种控件作为示范，并为每篇论文各配一张主图。
3. **新增维护者编辑文档**：一份 Markdown 文档，说明三种控件的调用命令、可写内容、示例、限制与排错方式，以及新闻配图的标准 Markdown 写法、存放位置、图注、许可与来源标注约定，使后续维护者无需修改模板或样式即可在任意新闻中使用控件与配图。

**范围之外**：

- 新闻列表页卡片（标题、摘要、封面）的版式调整；
- 首页、Team、Publications 等其他页面的内容控件；
- 将对比表渲染为图片、构建期表格截图、图片放大/灯箱脚本；
- 富文本编辑器、评论、分享、目录、阅读进度条等额外功能；
- 站点导航、搜索、构建部署流程的变更；
- 为控件引入第三方前端框架或重型运行时。

## 参考文章与写作取向

用户提供的参考文章 [《让大模型学会「自己教自己」！京东&中科院信工所连发三篇论文定义Self-Taught RLVR》](https://mp.weixin.qq.com/s/YsyfW-FMGJ-p5mrEBKA_1g)（量子位 QbitAI，2026-05-19）与本次三篇论文完全对应，文章约 3,500 字、配十余张示意图，未使用表格。可借鉴之处：

- **统一叙事**：把三篇工作归入 Self-Taught RLVR，即让模型自己为自己提供贴合当前能力、更易吸收的学习信号；三篇分别回答“老师从哪里来”。
- **总—分—总结构**：开篇提出大模型如何自我指导、迭代演化的问题；中段三个平行小节；结尾回收共同结论。
- **平行比喻**：三个小节分别用“看见答案的自己”“短暂未来后的自己”“走另一条路的自己”来指代教师信号来源，降低理解门槛。
- **论证节奏**：每篇按“问题 → 方法 → 结论”展开，并给出横向对比与统一视角。
- **关键量直觉化**：用少量公式配合直觉解释，如 RLSD 的 evidence ratio、NPO 的 S=Q/V、CoPD 的 a_P/b_P。

借鉴边界：

- MUST NOT 逐字复制参考文章段落、标题或整段比喻；本站新闻应为原创解读。按用户决定，正文不设“参考解读”署名或链接。
- 参考文章只作为写作参考，不作为事实来源；论文标题、作者、机构、指标与实验数字 MUST 以论文原文或官方页面核实为准。
- 参考文章配图较多；本站为三篇论文的小节各配一张论文主图，其余示意图允许用文字、公式与对比表替代，不追求与参考文章同等配图量。
- 参考文章未使用表格；本站使用表格块做横向对比，表格在容器内横向滚动，不将表格转为图片。

## Clarifications

### Session 2026-10-23

- Q: 你说的“每篇文章的主图”，具体指哪一种？ → A: 三篇论文的主图插入正文——为 RLSD、NPO、CoPD 各配一张主图，分别放在各自小节中。
- Q: 三篇论文的主图从哪里获取、如何存放？ → A: 论文官方主图并本地存放——从论文 arXiv/官方页面获取，图片文件存入仓库 `src/content/news/` 并以相对路径引用，图注标注论文标题与公开链接。
- Q: 三篇论文各自选哪一张图作为主图？ → A: 统一用方法框架图——取论文中展示方法/框架总览的示意图，不限定图号。
- Q: 主图在详情页如何展示，是否需要放大能力？ → A: 同宽静态展示 + 可打开论文页——图片与正文同宽（不放大超过固有尺寸）、保持比例；点击图片或图注中的论文链接在新标签页打开论文页，不新增放大脚本。
- Q: 这次配图是否要沉淀为可复用的编辑约定？ → A: 文档补充“新闻配图”章节——用标准 Markdown 图片语法配图，并在编辑文档说明图片存放、命名、图注、许可与来源标注约定；不新增专用配图命令。
- Q: 正文“不少于 2,500 个中文字符”的口径与六段式要求是什么？ → A: 维持 ≥2,500 CJK；仅统计 CJK 统一表意文字，排除 frontmatter、BibTeX/围栏代码块与行内代码，包含图注与表格文字；删除 FR-025 的六段式要求，每篇按“问题—方法—结论”展开即可。
- Q: 三篇论文的标题、机构与版本如何写？ → A: 章节标题保留方法名，正文首段写真实论文标题；BibTeX 用真实标题；机构写 IIE, CAS / UCAS / JD.COM；NPO 以 arXiv v2 为准。
- Q: 对比表是否渲染为图片并按图片逻辑放大？ → A: 不渲染为图片；新增 `:::table[可选标题]` 表格控件，表格在容器内横向滚动，页面不横向溢出；不引入构建期截图、灯箱或图片放大脚本。
- Q: 三条 BibTeX 条目采用什么格式？ → A: 三条统一用 arXiv `@misc` + `eprint`/`archivePrefix`/`primaryClass` + `url`；均全列作者并用花括号保护标题大小写。NeurIPS 2026 接收信息 MUST NOT 出现在 BibTeX 或正文中（2026-10-23 决议：完全删去接收表述）；正式 proceedings 发布后再评估更新。（同日后续决议：原“RLSD/CoPD 用 `@inproceedings`”方案因正式版尚未发布而调整为上述 arXiv 方案。）
- Q: 构建期如何处理控件语法错误？ → A: 硬错误（未闭合 `:::highlight`/`:::table`、非小写 `bibtex` 语言标记）MUST 构建失败并给文件/行号；软问题（未知容器、空块、表格尾行缺空行、同名嵌套）MUST 输出受控 warning；FR-036 改为“除已声明的控件诊断外，无新增警告”。
- Q: SC-001/SC-005/SC-011 如何验收？ → A: 降级为非门禁质量目标，发布后抽查，不作为合并前通过条件。
- Q: 论文配图的许可与署名如何标注？ → A: 图注统一写“图源：论文标题（arXiv:ID，CC BY 4.0）；图片未修改，仅按页面宽度缩放”，并链接许可文本。
- Q: 无标题高亮块如何满足“不得仅靠颜色”的要求？ → A: 保留无标题用法；所有高亮块 MUST 有左侧 3–4px 强调竖线与边框等结构线索，标题可选。
- Q: 复制成功/失败反馈如何避免布局位移？ → A: 复制入口改为固定尺寸图标按钮（≥32×32），成功/失败用带颜色图标表示，文字反馈只写入固定状态区；状态区单独播报，按钮图标不进入 live region。
- Q: 是否写“参考解读”署名？ → A: 不写参考解读，不设署名或链接；参考文章仅作写作参考，正文仍须原创且不得逐字照搬。
- Q: 新闻配图是否提供 `<figure>`/`<figcaption>` 语义？ → A: 新闻配图保持标准 Markdown 图片 + 紧随其后的普通段落图注，不提供 figure/figcaption 语义；替代文本承担图片内容描述，图注承担出处与许可说明。表格块自身使用 `<figure>`/`<figcaption>`。
- Q: 横向溢出与 `overflow-x: hidden` 如何处理？ → A: 保留块内滚动：BibTeX 的 `pre` 与表格的 `.news-table__scroll` 使用 `overflow-x: auto`；全局 `body { overflow-x: hidden }` 在本特性内移除（已实测全站 18 个页面 × 320–1440px 无横向溢出），验收直接测 `scrollWidth` 并逐元素检查 `getBoundingClientRect()`，不再依赖临时禁用。
- Q: 真实读屏播报是否属于本特性的验收门禁？ → A: 不属于。Constitution v2.0.0（commit e3cf68e）已移除原则 IV 的无障碍 MUST 条款，项目既有口径（001/002/004）均不设无障碍合规要求；本特性保留 `aria-live`/`aria-hidden` 作为实现细节，但 T045/T052 的真实读屏播报验收予以豁免，不作为发布门禁，也不得以「未测」阻塞交付。

## 术语与编辑命令

- **高亮块（Highlight）**：新闻正文中的重点提示容器，视觉上为带圆角、底色与左侧强调竖线的矩形块，可选标题。
- **BibTeX 引用块（Bib Block）**：新闻正文中的引用条目展示块，内容按原文逐字保留，带固定尺寸图标复制按钮，长行在块内横向滚动。
- **表格块（Table Block）**：新闻正文中的对比表容器，由 `:::table[可选标题]` 包裹标准 Markdown 表格；可选标题渲染为图注，表格在容器内横向滚动。
- **新闻配图（News Figure）**：新闻正文中通过标准 Markdown 图片语法插入的论文主图；图注与出处、许可以紧随图片的普通段落书写，不引入专用命令。
- **编辑命令（Authoring Command）**：维护者在 Markdown 源文件中书写、由新闻详情页识别并渲染为控件的固定语法。本特性约定三种命令：

  **高亮块**（容器命令，正文支持普通 Markdown）：

  ```markdown
  :::highlight[可选标题]
  这里是需要强调的内容，可以包含 **加粗**、[链接](https://example.com) 与列表。
  :::
  ```

  **BibTeX 引用块**（以 `bibtex` 为语言标记的围栏代码块）：

  ````markdown
  ```bibtex
  @misc{example2026,
    title         = {{Example Paper}},
    author        = {Example Author},
    year          = {2026},
    eprint        = {2604.00000},
    archivePrefix = {arXiv},
    primaryClass  = {cs.LG},
    url           = {https://arxiv.org/abs/2604.00000}
  }
  ```
  ````

  **表格块**（容器命令，正文为一至多张标准 Markdown 表格；建议结尾 `:::` 前留一个空行，缺失时自动修正并 warning）：

  ```markdown
  :::table[可选标题]
  | 维度 | 论文 A | 论文 B |
  | --- | --- | --- |
  | 教师信号来源 | …… | …… |
  :::
  ```

- **编辑文档**：仓库根目录下的 `docs/news-markdown-guide.md`，面向非前端背景的维护者，使用中文书写；MUST 能从维护者入口（根 README 或 `src/data/README.md`）被发现。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 维护者用 Markdown 插入高亮块 (Priority: P1)

维护者在任意一篇新闻的 Markdown 源文件中，用 `:::highlight[可选标题]` 与结尾 `:::` 包住一段内容。构建后的新闻详情页出现一个圆角、带底色与左侧强调竖线的高亮块；框内文字、链接与列表按普通 Markdown 正常排版，标题可选，未写标题时不出现空标题行。

**Why priority**: 高亮块是最基础的内容表达控件，维护者只需要写 Markdown 就能使用，且不依赖任何交互脚本；它先于 BibTeX 引用块可用，单独实现即可交付价值。

**Independent Test**: 新建一篇临时新闻，正文分别放入带标题与不带标题的高亮块，构建后在详情页观察两种形态均正确渲染，且新闻列表页不出现控件样式。

**Acceptance Scenarios**:

1. **Given** 新闻源文件包含一个带标题的高亮块，**When** 打开该新闻详情页，**Then** 正文出现一个圆角矩形、带底色与左侧强调竖线的容器，标题与正文按层级排版，容器上下与正文保持合理间距。
2. **Given** 高亮块未写标题，**When** 渲染，**Then** 容器直接展示正文，左侧强调竖线与边框仍在，不出现空标题占位或多余留白。
3. **Given** 高亮块正文包含段落、加粗、斜体、行内代码、链接与列表，**When** 渲染，**Then** 这些内容按站点既有 Markdown 样式正常呈现。
4. **Given** 高亮块正文包含超长链接或无空格长字符串，**When** 在 375px 视口浏览，**Then** 内容在块内折行或断行，不撑破容器、不造成页面横向滚动。
5. **Given** 同一篇新闻包含多个高亮块，**When** 渲染，**Then** 每个块独立呈现，样式一致，互不影响。
6. **Given** 新闻列表页，**When** 浏览该新闻的卡片，**Then** 卡片只展示摘要，不出现高亮块内容或控件样式。

### User Story 2 - 维护者用 Markdown 插入可复制的 BibTeX 引用块 (Priority: P1)

维护者在新闻中加入一个语言标记为 `bibtex` 的围栏代码块，填入论文引用条目。详情页将其渲染为类似代码块的等宽区域，右上角提供固定尺寸的图标复制按钮；点击一次即把该条目的原始文本完整复制到剪贴板，按钮图标变为带颜色的成功态，邻近状态区显示“已复制”。条目很长时，代码区域内部横向滚动，页面本身不出现横向滚动。

**Why priority**: 论文解读新闻必须展示可复用的引用条目，一键复制是这类内容的核心价值；它与高亮块共同构成本次新闻的展示基础。

**Independent Test**: 在临时新闻中放入三条不同长度的 BibTeX 条目（含一条刻意超过容器宽度的长行），在桌面与 375px 视口下分别点击复制，粘贴到文本编辑器核对内容逐字一致；确认页面无横向滚动、块内可横向滚动。

**Acceptance Scenarios**:

1. **Given** 新闻中的 `bibtex` 代码块，**When** 详情页渲染，**Then** 该块以等宽字体、代码块外观展示，缩进、换行与花括号原样保留。
2. **Given** 一个 BibTeX 引用块，**When** 读者点击复制图标按钮，**Then** 剪贴板内容与该块内的 BibTeX 原文完全一致（含换行与缩进），按钮图标变为带颜色的成功态，状态区出现“已复制”。
3. **Given** 复制成功，**When** 约 2 秒后，**Then** 按钮图标与状态区恢复为可再次复制的初始状态，反馈文案消失。
4. **Given** 同一篇新闻含多个 BibTeX 引用块，**When** 点击任意一个块的复制按钮，**Then** 只复制该块自身的内容，不影响其他块。
5. **Given** 单条 BibTeX 含超长行（如长作者列表或长 URL），**When** 在 375px、768px、1024px 与 ≥1280px 视口浏览，**Then** 超宽内容仅在引用块内部横向滚动，复制按钮始终可见可用，页面不出现横向滚动。
6. **Given** 浏览器拒绝剪贴板访问或成功反馈异常，**When** 读者点击复制，**Then** 按钮图标变为带颜色的失败态，状态区出现“复制失败，请手动选择”，引用文本仍可被选中并手动复制。
7. **Given** 浏览器禁用 JavaScript，**When** 打开新闻详情页，**Then** BibTeX 内容完整可见、可选中，复制按钮不出现或明确不可用，版面不塌陷、不重叠。
8. **Given** 读者仅使用键盘，**When** 按 Tab 聚焦复制按钮并按 Enter 或空格，**Then** 复制执行，焦点样式清晰可见，结果通过无障碍状态区播报。
9. **Given** 读者仅使用键盘，**When** 按 Tab 聚焦 BibTeX 内容区并按方向键，**Then** 内容区可横向滚动，焦点样式清晰可见，不被复制按钮遮挡。

### User Story 3 - 读者阅读三论文解读新闻 (Priority: P2)

读者在 News 列表打开新增长文，读到一篇结构完整的中文解读：以“模型如何自己教自己（Self-Taught RLVR）”为主线，采用“总—分—总”结构，先交代三篇工作共同关注的后训练问题，再分别介绍 Self-Distilled RLVR（RLSD）、Learning from the Near Future: Temporal Self-Distillation for RLVR（NPO 机制）与 Co-Evolving Policy Distillation（CoPD）的出发点、方法、关键机制与主要结论，最后以横向对比和统一视角比较三者的差异与联系，并给出对后续研究的启示。文中重点结论以高亮块呈现，每篇论文的方法框架主图以正文配图呈现，引用以可复制的 BibTeX 块呈现，横向对比以表格块呈现。

**Why priority**: 这篇新闻既是内容交付物，也是三种控件的真实使用范例；没有它，控件缺少可验证的落地场景。

**Independent Test**: 打开该新闻详情页，核对三篇论文各有独立小节、每节均有一张方法框架主图与一个 BibTeX 块、全文至少有两个高亮块、至少有一张表格块对比表；逐条核对论文标题、图片与引用信息能对应到公开论文页面，且文中没有无法溯源的数字或结论。

**Acceptance Scenarios**:

1. **Given** News 列表，**When** 按日期倒序浏览，**Then** 该新闻出现在列表顶部区域，标题、日期与摘要完整可读，摘要为 80–200 字（按 Unicode code point 计）。
2. **Given** 新闻详情页，**When** 通读全文，**Then** 文章采用“总—分—总”结构，依次覆盖：问题背景与统一叙事、三篇论文各一节、横向对比与综合讨论、对研究的启示。
3. **Given** 三篇论文小节，**When** 逐节阅读，**Then** 每节按“问题 → 方法 → 结论”展开，说明该工作的真实论文标题、作者或研究机构（IIE, CAS / UCAS / JD.COM）、公开论文链接与版本，并指出它与另外两篇的关系。
4. **Given** 全文控件使用，**When** 统计，**Then** 至少包含 3 个 BibTeX 引用块（每篇论文一个）、至少 2 个高亮块与至少 1 个表格块；高亮块用于突出核心洞察而非装饰。
5. **Given** 任一 BibTeX 引用块，**When** 复制并粘贴到支持 BibTeX 的工具，**Then** 条目结构完整、可直接解析；三条均为 arXiv `@misc` 条目，均包含标题、全部作者、年份、`eprint` 与公开链接。
6. **Given** 文中任一事实性陈述或实验数字，**When** 对照论文原文或官方摘要页，**Then** 可以找到对应来源；NPO 数字 MUST 以 arXiv v2 为准；无法核实的细节不写入正文。
7. **Given** 读者在移动端阅读，**When** 浏览全文，**Then** 正文单列、字号与行距可读，长文中的高亮块、BibTeX 引用块与表格块均不造成布局破损。
8. **Given** 文章的对比章节，**When** 阅读，**Then** 表格块按“教师信号来源、是否引入额外信息、核心代价与风险、适用阶段”等维度并列三篇工作；在 375px 视口下表格只在容器内横向滚动，页面无横向滚动。
9. **Given** 文章对关键指标的解释，**When** 阅读，**Then** RLSD 的 evidence ratio、NPO 的 S=Q/V、CoPD 的 a_P/b_P 均给出符号含义与一句直觉解释，且与论文定义一致。
10. **Given** 文章与参考文章，**When** 对比，**Then** 不存在逐字照搬的整段文字；正文不设“参考解读”署名或链接。
11. **Given** 三篇论文小节，**When** 阅读各节，**Then** 每节均有一张展示方法/框架总览的主图，图下有可见图注、论文标题、公开链接与 CC BY 4.0 许可说明，替代文本能说明图片内容。
12. **Given** 任一主图，**When** 在 375px 视口浏览，**Then** 图片按比例缩放、不超出正文容器、页面无横向滚动；点击图片或图注中的论文链接能在新标签页打开论文页。
13. **Given** 表格块，**When** 使用键盘 Tab 聚焦表格滚动容器并按方向键，**Then** 表格可横向滚动，焦点样式清晰可见。

### User Story 4 - 维护者用 Markdown 插入可横向滚动的表格块 (Priority: P2)

维护者在新闻中加入 `:::table[可选标题]` 容器，容器内写一至多张标准 Markdown 表格。构建后的详情页出现带站点样式的对比表；每张表各自成为独立的表格块，有标题时第一张表显示图注，无标题时不出现空图注。窄视口下表格在自身容器内横向滚动，页面本身不出现横向滚动；键盘用户可聚焦表格容器并用方向键滚动。

**Why priority**: 列数较多（如 5 列）的对比表在 375px 下必然超宽；没有表格控件，维护者只能把表格转成图片（牺牲可检索与无障碍）或接受页面横向溢出。表格控件是 FR-037 对比表的必要载体。

**Independent Test**: 新建一篇临时新闻，放入一个带标题、一个不带标题的表格块，分别含 3 列与 5 列；在 375px、768px、1024px 与 ≥1280px 视口检查表格内滚动、页面无横向滚动、标题与无标题形态、键盘滚动与焦点样式。

**Acceptance Scenarios**:

1. **Given** 新闻源文件包含 `:::table[对比表标题]`，**When** 打开详情页，**Then** 表格上方出现可见图注，表格按站点样式渲染。
2. **Given** 表格块未写标题，**When** 渲染，**Then** 直接展示表格，不出现空图注或额外留白。
3. **Given** 表格块含 5 列，**When** 在 375px 视口浏览，**Then** 表格仅在容器内横向滚动，单元格文字不被截断，页面 `scrollWidth` 不超过视口宽度。
4. **Given** 表格块，**When** 读者用 Tab 聚焦表格容器并按方向键，**Then** 表格横向滚动，焦点样式清晰可见。
5. **Given** 同一篇新闻包含多个表格块，**When** 渲染，**Then** 每个块独立呈现，样式一致，互不影响。
6. **Given** 表格块内为空或缺少表头，**When** 构建，**Then** 输出受控 warning，不生成空白表格控件。
7. **Given** 普通 Markdown 表格未包在 `:::table` 中，**When** 渲染，**Then** 保持既有渲染结果，不被自动升级为表格控件。

### User Story 5 - 维护者查阅编辑文档并复用控件 (Priority: P3)

后续维护者打开编辑文档，能在一个页面内查到三种控件与新闻配图的完整用法：调用命令或 Markdown 写法、可放什么内容、复制粘贴示例、渲染效果说明、常见错误与排查方法、构建期诊断规则，以及本地预览/构建验证步骤。维护者照文档操作即可在任意新闻中加入控件与配图，不需要阅读模板代码或修改样式。

**Why priority**: 文档决定控件能否被长期复用；它不阻塞控件与新闻的首次交付，但必须在本次一并完成。

**Independent Test**: 请一位未参与本次开发、无前端经验的维护者仅依据文档，在临时新闻中成功添加一个高亮块、一个 BibTeX 块、一个表格块与一张配图并本地预览成功；记录其遇到的歧义并回补文档。

**Acceptance Scenarios**:

1. **Given** 编辑文档，**When** 查找高亮块用法，**Then** 文档给出命令模板、带标题与不带标题两个示例、支持的内容类型与注意事项。
2. **Given** 编辑文档，**When** 查找 BibTeX 块用法，**Then** 文档给出完整围栏代码块示例、语言标记必须为小写 `bibtex` 的说明、复制与横向滚动行为说明、arXiv `@misc` 条目完整示例。
3. **Given** 编辑文档，**When** 查找表格块用法，**Then** 文档给出 `:::table[可选标题]` 模板、标题可选、结尾前留空行、容器内滚动与键盘操作说明。
4. **Given** 维护者按文档粘贴示例，**When** 本地预览，**Then** 三种控件均正确渲染，无需修改任何模板或样式文件。
5. **Given** 常见错误（如漏写结尾 `:::`、语言标记拼错、空块、表格后未留空行、块内嵌套代码块），**When** 查阅文档，**Then** 文档说明现象、构建结果是硬错误还是受控 warning，以及修复方法。
6. **Given** 维护者想给新闻配图，**When** 查阅文档，**Then** 文档给出标准 Markdown 图片写法、图片存放位置与命名、图注与论文出处链接写法、CC BY 4.0 许可与“未修改”声明、替代文本要求、宽高与体积建议。
7. **Given** 图片路径写错或文件缺失，**When** 构建，**Then** 文档说明构建会失败并指出缺失文件，而不是上线破图。
8. **Given** 文档读者不知道如何验证，**When** 查阅文档，**Then** 文档给出本地启动、预览与构建检查的步骤，以及应观察的页面位置与四档视口外的 320px、200% 缩放抽查项。
9. **Given** 维护者从仓库入口查找文档，**When** 打开根 README 或 `src/data/README.md`，**Then** 能找到指向 `docs/news-markdown-guide.md` 的链接。

### Edge Cases

- **高亮块未闭合**：缺少结尾 `:::` 时，构建 MUST 失败并指出文件与行号；不得静默降级或吞掉后续正文。
- **表格块未闭合**：缺少结尾 `:::` 时，构建 MUST 失败并指出文件与行号。
- **高亮块为空**：只有命令与结尾、没有正文时，输出受控 warning，并移除空块，不留下突兀的空色块或大段留白。
- **BibTeX 块为空**：无任何条目时输出受控 warning；保留空代码块外观，不生成工具栏或复制按钮。
- **BibTeX 含超长单行**：长作者列表、长 URL 或连续无空格字符串不得撑破页面；仅块内横向滚动。
- **BibTeX 含特殊字符**：花括号、反斜杠、`&`、`%`、下划线、中文与 HTML 样文本必须按纯文本显示，不得被当作标记解析或执行；字段中的 `&`/`%` 由维护者按 LaTeX 规则转义为 `\&`/`\%`。
- **多个控件相邻**：连续两个高亮块、BibTeX 引用块或表格块之间保持可辨识的间距，不粘连、不合并。
- **控件嵌套在列表或引用中**：本特性不支持在列表项、引用块等嵌套语境中使用高亮块或表格块；编辑文档 MUST 说明只建议放在顶层段落。
- **复制失败**：剪贴板权限被拒、非安全上下文或浏览器不支持时，按钮图标变为失败态，状态区给出“复制失败，请手动选择”，文本仍可手动选择。
- **无脚本环境**：禁用 JavaScript 时正文完整可读，复制入口保持隐藏，不造成空白按钮或布局错位。
- **复制反馈导致布局抖动**：按钮为固定尺寸图标按钮，成功/失败图标切换不改变按钮尺寸，不推动周围内容或造成换行。
- **超长标题**：高亮块与表格块标题过长时在块内折行，不截断、不溢出。
- **新闻摘要超长**：新新闻摘要超过既有 200 字上限时应在构建阶段被拒绝，而不是截断上线。
- **同一新闻多次使用控件**：任意数量的高亮块、BibTeX 引用块与表格块均能独立工作，无重复标识或事件串扰。
- **主图缺失或路径错误**：构建 MUST 失败并指出缺失文件，不得上线破图；不得以空白占位或缩小尺寸掩盖问题。
- **主图极宽或极高**：超宽图按比例缩放至内容区宽度，超长竖向图不得撑破版面或造成页面横向滚动。
- **主图文字密集**：缩放到移动端宽度后图内文字可能偏小，必须可通过点击图片或图注中的论文链接打开论文页查看，不得因此截断图注或隐藏图片。
- **表格块无标题**：不生成空图注，表格直接展示。
- **表格块单元格超长**：单元格内容在单元格内折行，表格容器可横向滚动，页面不横向溢出。
- **表格块列数过多**：五列及以上时，表格在容器内横向滚动，表头与首列不截断。
- **表格块为空**：无表格行时输出受控 warning，不生成空表格控件。

### 控件边界行为

> 权威定义见 `contracts/markdown-authoring.md` 的 DF-01；本表仅为摘要，若二者不一致以 DF-01 为准。

| 输入 | 构建期处理 | 页面表现 |
|---|---|---|
| 未闭合 `:::highlight` / `:::table` | 硬错误，构建失败，给文件/行号 | 不生成页面 |
| ` ```BibTeX `、` ```bib ` 等非小写标记 | 硬错误，构建失败，给文件/行号 | 不生成页面 |
| 空高亮块 | 受控 warning | 移除，不留空块 |
| 空 `bibtex` 块 | 受控 warning | 保留空代码块外观，不生成工具栏/按钮 |
| 未知容器 `:::foo` | 受控 warning | 展开为普通内容 |
| 同名高亮嵌套 | 受控 warning | 降级并保留正文，可能残留 `:::` 文本 |

## Requirements *(mandatory)*

### Functional Requirements

**A. 编辑接口与文档**

- **FR-001**: 任意新闻 Markdown 源文件 MUST 能通过 `:::highlight[可选标题]` 开始、`:::` 结束的容器命令声明高亮块；维护者 MUST NOT 需要修改页面模板、组件或样式文件。
- **FR-002**: 任意新闻 Markdown 源文件 MUST 能通过语言标记为小写 `bibtex` 的围栏代码块声明 BibTeX 引用块；除该语言标记外，维护者 MUST NOT 需要额外标记或配置。
- **FR-003**: 仓库 MUST 提供 `docs/news-markdown-guide.md` 编辑文档，使用中文说明三种控件与新闻配图的命令/写法、示例、可写内容、行为、限制、构建期诊断、常见错误与本地验证步骤；文档 MUST 能从根 README 或 `src/data/README.md` 被发现。
- **FR-004**: 编辑文档 MUST 明确区分“普通代码块”与“BibTeX 引用块”、“普通 Markdown 表格”与“表格块”：只有语言标记为小写 `bibtex` 的围栏代码块启用复制按钮与专用样式；只有 `:::table` 容器内的表格启用表格控件样式与容器滚动；其他代码块与未包裹的表格保持既有渲染行为。
- **FR-005**: 编辑文档 MUST 给出三种控件可直接复制粘贴的完整示例，并说明标题可选、结尾 `:::` 不可省略、`bibtex` 大小写、表格结尾前建议留空行等易错点。
- **FR-043**: 编辑文档 MUST 新增“新闻配图”章节，说明：使用标准 Markdown 图片语法；图片与新闻源文件同目录存放并以文件名相对引用；图片命名、图注、论文出处链接、CC BY 4.0 许可与“未修改，仅按页面宽度缩放”声明；替代文本要求；宽高与体积建议；MUST NOT 外链图片或使用参考文章配图。

**B. 高亮块**

- **FR-006**: 高亮块 MUST 呈现为圆角矩形（圆角不小于 8px）、带与页面底色可区分的浅色背景、左侧 3–4px 强调竖线与边框，并保留足够内边距与上下外边距，使其在长文中可被一眼识别。
- **FR-007**: 高亮块 MUST 支持可选标题；未提供标题时 MUST NOT 渲染空标题占位、空行或额外留白，左侧强调竖线与边框 MUST 仍然存在。
- **FR-008**: 高亮块正文 MUST 支持段落、加粗、斜体、行内代码、链接与列表，并按既有正文样式排版；块内引用、代码块与表格 MUST 至少有可读的最小排版，不撑破容器。
- **FR-009**: 高亮块在 375px、768px、1024px 与 ≥1280px 视口下 MUST 自适应内容区宽度；长文本与长链接 MUST 在块内折行或断行，MUST NOT 溢出容器或造成页面横向滚动。
- **FR-010**: 高亮块 MUST 通过左侧强调竖线、边框与内边距等非颜色结构线索体现强调，不得仅靠背景色；标题可选，无标题块同样 MUST 满足此要求；正文文字与背景对比度 MUST 不低于 4.5:1。

**C. BibTeX 引用块**

- **FR-011**: BibTeX 引用块 MUST 以等宽字体与代码块式外观展示，完整保留原始缩进、换行、空格与花括号，不得重排或格式化条目内容。
- **FR-012**: 每个 BibTeX 引用块 MUST 提供一键复制入口；一次操作 MUST 将该块原始 BibTeX 文本逐字写入剪贴板，不附加标题、按钮文案或额外空行。
- **FR-013**: 复制入口 MUST 为固定尺寸的图标按钮（不小于 32×32 CSS 像素），带可读名称（如“复制引用”）；复制成功后 1 秒内图标变为带颜色的成功态（如对勾），状态区显示“已复制”，约 2 秒后图标与状态区恢复初始状态；反馈期间 MUST NOT 引起周围布局位移或换行。
- **FR-014**: 复制失败时 MUST 将按钮图标变为带颜色的失败态（如叉号或警示），状态区给出明确失败反馈（如“复制失败，请手动选择”），并保证引用文本仍可被鼠标或键盘选中手动复制。
- **FR-015**: BibTeX 引用块 MUST 在内容宽度超出容器时于块内横向滚动；滚动 MUST 支持鼠标、触控板与触摸手势，MUST NOT 引发页面级横向滚动。
- **FR-016**: 复制入口 MUST 在块内所有滚动位置保持可见或可到达，MUST NOT 遮挡 BibTeX 文本的首行或关键内容。
- **FR-017**: 同一新闻中的多个 BibTeX 引用块 MUST 各自独立复制自身内容，复制入口 MUST NOT 使用重复标识或相互串扰。
- **FR-018**: BibTeX 内容 MUST 按纯文本渲染，其中的尖括号、`&`、反斜杠等字符 MUST NOT 被解释为 HTML 或脚本执行；字段中的 `&`/`%` MUST 由维护者按 LaTeX 规则写成 `\&`/`\%`，渲染器逐字保留。

**D. 交互、无障碍与降级**

- **FR-019**: 复制入口 MUST 可通过键盘 Tab 聚焦，并可通过 Enter 或空格触发；BibTeX 内容区 MUST 可通过 Tab 聚焦，并可用方向键横向滚动；两处焦点状态 MUST 清晰可见。
- **FR-020**: 复制成功与失败反馈 MUST 只通过无障碍状态区向辅助技术播报一次，按钮图标与图标变化 MUST NOT 进入 live region；播报不得打断读者当前阅读位置。（验证口径：按 Constitution v2.0.0，真实读屏播报不作为验收门禁，见 Clarifications 2026-10-25；`aria-live`/`aria-hidden` 结构保留为实现细节。）
- **FR-021**: 禁用 JavaScript 时，三种控件的正文内容 MUST 完整可见、可选择；复制入口 MUST 隐藏或明确不可用，版面 MUST NOT 塌陷、重叠或出现无意义空白按钮。
- **FR-022**: 复制入口 MUST 在触屏设备上易于点击；点击目标尺寸与固定布局要求见 FR-013，本条不重复规定尺寸。

**E. 新闻内容**

- **FR-023**: 新增新闻 MUST 使用标题、日期、摘要与正文的既有字段约定；slug 固定为 `self-taught-rlvr-2026`；标题不超过 40 个 CJK 统一表意文字（英文、数字与标点不计）且不得与参考文章标题相同；日期为 2026-10-23；摘要 80–200 字，按 Unicode code point 计（中文、英文、标点各计 1，不含 Markdown 标记），且 MUST NOT 包含 `:::highlight`、`:::table` 或 ```` ```bibtex ```` 等控件语法；正文使用中文（论文标题、术语与 BibTeX 条目保留英文）。
- **FR-024**: 新闻正文 MUST 采用“总—分—总”结构，以“模型自己教自己（Self-Taught RLVR）”为统一叙事，依次覆盖：三篇工作共同面对的后训练问题与背景；Self-Distilled RLVR（RLSD）独立小节；Learning from the Near Future: Temporal Self-Distillation for RLVR（NPO 机制）独立小节；Co-Evolving Policy Distillation（CoPD）独立小节；横向对比、联系与综合讨论；对后续研究或实践的启示。
- **FR-025**: 每篇论文小节 MUST 按“问题 → 方法 → 结论”展开，说明该工作的真实论文标题、作者或研究机构（IIE, CAS / UCAS / JD.COM）、公开论文链接与版本、所针对的问题、核心方法与主要结论，并指出它与另外两篇工作的关系；MUST NOT 把机制名（如 NPO）当作论文标题。
- **FR-026**: 新闻 MUST 使用至少 3 个 BibTeX 引用块（每篇论文至少一个）；三条 MUST 均为 arXiv `@misc` 条目（`eprint`、`archivePrefix = {arXiv}`、`primaryClass = {cs.LG}`），citation key 分别为 `yang2026rlsd`、`qin2026npo`、`gu2026copd`；三条 MUST 全列作者、用花括号保护标题大小写、包含标题、年份与可公开访问的 HTTPS 链接；条目 MUST 能被标准 BibTeX 工具解析。三条统一按 arXiv 预印本呈现：NeurIPS 2026 接收状态 MUST NOT 出现在 BibTeX 条目或正文中；正式 proceedings 发布后再以正式版更新。每篇论文小节 MUST 至少给出论文公开链接；若论文页提供官方代码或模型链接（RLSD 的 GitHub 仓库等），MUST 一并列出。
- **FR-027**: 新闻 MUST 使用至少 2 个高亮块，用于突出全文层面的关键洞察、方法要点或对比结论；每个高亮块至少包含一个可独立成立的结论、定义或风险提示，并与相邻正文形成“提出—强调”关系，而非重复标题或装饰性短句。
- **FR-028**: 新闻正文 MUST 足够详细以支撑“解读三篇论文”的目标：全文正文（仅统计 CJK 统一表意文字，排除 frontmatter、BibTeX/围栏代码块与行内代码，包含图注与表格文字）不少于 2,500 个中文字符，每篇论文小节均有实质展开而非摘要复述。
- **FR-029**: 新闻中的事实性陈述、实验设置与数字 MUST 可追溯到论文原文或官方公开页面；NPO 的数字与结论 MUST 以 arXiv v2 为准；参考文章中的机构归属、指标与数字 MUST 经论文页面复核后方可写入；无法核实的内容 MUST 省略或明确标注不确定性，MUST NOT 虚构作者、机构、指标或结论。
- **FR-030**: 新闻 MUST 在 News 列表按既有日期倒序规则展示，列表卡片只显示标题、日期与摘要，不渲染正文控件。
- **FR-037**: 新闻 MUST 至少包含一个表格块，按“教师信号来源、是否引入额外信息、核心代价与风险、适用阶段（训练期间/训练之后）”等维度并列三篇工作，使读者能一眼看出三者的定位差异。
- **FR-038**: 新闻 MUST 对三篇论文各自的关键量给出符号含义与直觉解释：RLSD 的 evidence ratio、NPO 的 S=Q/V、CoPD 的 a_P/b_P（P 表示 policy）；解释 MUST 与论文定义一致，MUST NOT 只罗列公式而不解释其作用。
- **FR-039**: 新闻 MUST 为原创解读，MUST NOT 逐字复制参考文章的段落、标题或整段比喻；正文 MUST NOT 设置“参考解读”署名或链接。
- **FR-040**: 三篇论文小节 MUST 各配一张论文主图，主图内容 MUST 为该论文展示方法或框架总览的示意图（不限定图号）；图片 MUST 取自论文官方公开页面（arXiv 或项目页）并以文件形式存放于仓库、通过相对路径引用；MUST NOT 截用参考文章配图，MUST NOT 热链外部图片。每张主图 MUST 有中文替代文本（一句话说明该图展示的方法/流程，不要求逐字翻译图内标签）与可见图注；图注 MUST 标注论文标题、公开链接、`CC BY 4.0` 许可与“图片未修改，仅按页面宽度缩放”声明，并链接许可文本。图注为紧随图片的普通段落，不要求 `<figure>`/`<figcaption>` 语义。
- **FR-041**: 主图 MUST 在正文内容区内以不超过正文内容宽度的尺寸展示，按原始宽高比缩放，MUST NOT 放大超过图片固有尺寸；在 375px、768px、1024px 与 ≥1280px 视口下 MUST NOT 溢出容器、MUST NOT 造成页面横向滚动。点击图片，或点击图注中的论文链接，MUST 能在新标签页打开论文公开页面；该链接 MUST 可由键盘聚焦并有可见焦点。
- **FR-042**: 主图 MUST 随新闻资源一同存放并接受构建期存在性校验，文件缺失时 MUST 构建失败而非上线破图；图片 MUST 经过压缩/尺寸优化，单张文件不超过 500KB，且不阻塞正文首屏阅读。

**F. 表格块**

- **FR-044**: 任意新闻 Markdown 源文件 MUST 能通过 `:::table[可选标题]` 开始、`:::` 结束的容器命令声明表格块；容器内 MUST 为一至多张标准 Markdown 表格；结尾 `:::` 前 SHOULD 留一个空行，缺失时按边界行为自动修正并输出受控 warning（不使构建失败）。
- **FR-045**: 表格块 MUST 为容器内每张表格分别生成语义化 `<figure class="news-table">`；有标题时仅第一张表的 figure 生成可见 `<figcaption class="news-table__caption">`，其余表 MUST NOT 生成 `<figcaption>`；无标题时所有表 MUST NOT 生成空图注；表格本体 MUST 为真实 HTML `<table>`，内容可选中、可检索；多张表格 MUST 按源顺序排列为独立表格块。
- **FR-046**: 表格块 MUST 将每张 `<table>` 分别包在可聚焦的滚动容器内（`tabindex="0"`、`role="region"`、可读 `aria-label`）；当表格宽度超过内容区时，MUST 在容器内横向滚动，MUST 支持鼠标、触控板、触摸与键盘方向键，MUST NOT 引发页面级横向滚动；焦点状态 MUST 清晰可见。
- **FR-047**: 表格块 MUST 复用站点设计语言提供最小表格样式：表头、边框、字号、单元格内边距与行距清晰可读，表头与首列不截断；MUST NOT 依赖浏览器默认表格样式直接上线；MUST NOT 将表格转为图片。

**G. 工程与一致性约束**

- **FR-031**: 控件 MUST 仅在新闻详情页生效；新闻列表、首页、Team、Publications 等其他页面 MUST NOT 出现新控件样式或行为。当前只有 news collection 渲染 Markdown，因此语法级启用等价于详情页生效；构建后 MUST 检查其他页面不含 `news-highlight`、`news-bib`、`news-table` 类名。
- **FR-032**: 未使用控件的既有新闻 MUST 保持原有渲染结果；普通代码块、标题、列表、链接与图片的既有样式 MUST NOT 发生非预期变化；实现前 MUST 记录 `dist/news/*/index.html` 关键片段或页面 hash 作为基线并在改动后 diff。
- **FR-033**: 上述页面在 375px、768px、1024px 与 ≥1280px 视口下 MUST 无布局破损（元素重叠、文字截断、内容溢出容器、非预期换行、页面横向溢出）；BibTeX 块与表格块的容器内横向滚动为已声明交互，不视为破损，但 MUST NOT 影响页面宽度；全局 `body { overflow-x: hidden }` MUST 在本特性内移除（页面级裁剪属 Constitution VI 禁止的掩盖手段）；移除后验收直接测 `document.documentElement.scrollWidth ≤ window.innerWidth`，并逐元素检查 `getBoundingClientRect()`。
- **FR-034**: 实现 MUST 保持静态站点交付，MUST NOT 引入第三方前端框架或后端运行时；新增客户端逻辑仅限复制交互所需的最小脚本，且不得影响页面首屏阅读；表格滚动为纯 CSS。
- **FR-035**: 控件的样式 MUST 复用站点既有设计语言（颜色、圆角、字体与间距体系），不得引入与站点整体风格冲突的视觉元素或动效。
- **FR-036**: 除已声明的控件诊断外，构建 MUST NOT 引入新增 warning 或静默降级；硬错误 MUST 使构建失败，软问题 MUST 输出带文件/行号的受控 warning。
- **FR-048**: 构建期 MUST 对控件语法执行校验：未闭合 `:::highlight`/`:::table`、非小写 `bibtex` 语言标记等硬错误 MUST 构建失败并给出文件与行号；未知容器、空块、表格尾行缺空行、同名嵌套等软问题 MUST 输出受控 warning 并记录基线数量；MUST NOT 静默吞掉错误。

### Key Entities *(include if feature involves data)*

- **新闻条目（News Entry）**：一篇 Markdown 新闻，包含标题、日期、摘要、可选封面与正文；本特性新增一篇三论文解读长文。
- **高亮块（Highlight Block）**：正文中的重点容器，包含可选标题、左侧强调竖线与 Markdown 正文；由维护者在 Markdown 中声明。
- **BibTeX 引用块（Bib Block）**：正文中的引用展示单元，包含一条或多条 BibTeX 原文、固定尺寸图标复制入口、状态区与内部滚动区域。
- **表格块（Table Block）**：正文中的对比表容器，包含可选图注、真实 HTML 表格与可聚焦的横向滚动容器；由 `:::table` 声明。
- **论文引用（Paper Reference）**：被解读论文的公开身份信息，包括真实标题、全部作者、年份、机构、版本、公开链接与发表状态（统一按 arXiv 预印本呈现，不写会议接收状态）；每篇论文对应一条 BibTeX 条目。
- **论文主图（Paper Figure）**：每篇论文小节配一张取自论文官方页面的方法框架图，含中文替代文本、可见图注、论文链接、CC BY 4.0 许可与修改声明；图片文件随新闻资源一同存放在仓库内。
- **参考文章（Reference Article）**：用户提供的量子位解读长文，仅作为写作结构、比喻与对比方式的参考，不作为事实来源，也不在正文中设署名或链接。
- **编辑文档（Authoring Guide）**：面向维护者的中文 Markdown 文档，是控件命令、新闻配图与构建期诊断的权威说明。

## Success Criteria *(mandatory)*

- **SC-010**: 编辑文档覆盖三种控件与新闻配图约定的命令/写法、示例、限制、构建期诊断、常见错误与验证步骤；抽查 5 个易错点均能在文档中找到明确答案。
- **SC-011**: （非门禁，发布后抽查）新闻与参考文章的连续重合文本不超过 30 字（论文标题、术语、公式与必要引语除外）。
