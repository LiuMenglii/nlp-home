# Feature Specification: Team 页 Master's Students 双栏布局

**Feature Branch**: `011-team-master-two-column-layout`

**Created**: 2026-11-21

**Status**: Clarified

**Input**: User description: "同上一个 feature，将硕士也写成两栏。"

## 目标与范围

本特性把 010 在 PhD Candidates 上落地的双栏规则同样应用到 Team 页的 Master's Students 分组。当前 11 位硕士同学以单列铺满内容区，横向留白与 PhD 改造前相同；本特性将其改为左右两栏（每栏内部按入学年份从低到高的顺序逐条排列），并把每行内部的信息位置调整为与 PhD 一致：

1. **姓名**固定在行首（第一列）；
2. **Since 年份**移到第二列，同一栏内各行左缘对齐；姓名列随视口变宽弹性增长，带动 Since 列整体右移，并与右侧链接保持固定 8px 间隙；Since 字号与姓名、链接正文一致（18px）；
3. **成员链接**（Homepage / GitHub / Scholar 中按既有规则选出的唯一标签，若存在）贴齐所在栏的右缘。

名单顺序同时改为按入学年份从低到高（2024 → 2026；无年级排最后，同级保持数据文件顺序），并对 PhD Candidates 与 Master's Students 两个在读分组一致生效。两个在读分组的 Since 列也统一改为随视口变宽整体右移（有链接时保持 8px 间隙），Since 字号统一为 18px。

视口 ≥768px 为两栏；<768px 退回单栏，其中 480–767px 仍为横向三列行，<480px 沿用 PhD 的竖排条目（第 1 行姓名与 Since，第 2 行链接）。

**范围之外**：

- PhD Candidates 分组的版式（010 已完成双栏，本特性不得回退其双栏结构；其名单顺序随 FR-003 改为年份升序、Since 字号随 FR-013 调整、第二列随 FR-005 弹性右移，均不属于版式回退）；
- Graduates 名单、Faculty 卡片、站点导航、页脚与首页的任何版式；
- 学生数据本身（姓名、level、grade、url / github / scholar）、链接标签映射与文案；本次仅移除未使用的 `note` 字段（见 Clarifications），不改动任何成员内容；Graduates 名单的排序规则；
- 增删成员、修改 "Since" 文案、修改配色、字体族、分隔线风格；除 Since 字号（见 FR-013）外的字号调整；
- 新增折叠、筛选、分页、动效等交互；
- 列标题行（如 Name / Since 表头）、列间竖线或其他额外装饰。

## Clarifications

### Session 2026-11-21

- Q: 工作区 `src/data/students.json` / `graduates.json` 已有的数据更新是否属于本特性范围？ → A: 明确排除：该更新（新增 11 位硕士、15 位博士，5 位原 PhD 转入 Graduates）不属于本特性，本特性不修改、不提交数据文件；该更新已在特性开始前作为独立 commit `54f3b81` 提交，验收以该提交后的名单为只读基准，范围核对以该提交为起点基线；2026-11-22 澄清的唯一例外是移除全为 null 的 `note` 字段。
- Q: 新的“入学年份从低到高”排序应用于哪些在读学生分组？ → A: PhD Candidates 与 Master's Students 两个分组统一改为入学年份升序（2024 → 2026）；无年级成员仍排最后，同级保持数据文件顺序；Graduates 名单排序不在本特性范围。
- Q: Since 列随视口变宽时应如何右移，以避免与右侧链接之间出现大空隙？ → A: 姓名列弹性吸收多余宽度，Since 保持 5.5em 固定槽（99px）并整体右移；有链接时 Since 与链接保持 8px 列间隙，链接仍贴齐栏右缘；无链接时不渲染占位。
- Q: Since 字号调整为与其他文本一致，应覆盖哪些范围？ → A: PhD Candidates 与 Master's Students 的 Since 统一改为 18px（与正文一致）；其他文本字号不变。
- Q: Since 列随宽度右移的规则应同时应用到 PhD 与 Master's，还是只改 Master's？ → A: PhD Candidates 与 Master's Students 共用同一套弹性姓名列与第二列右移规则；PhD 的 Since 位置随之调整，双栏断点、栏距与三槽结构不变。
- Q: 「三槽结构不变」应如何理解？ → A: 指槽位数量与顺序不变；FR-005 要求的姓名轨弹性与第二列右移属于本特性允许的调整，不构成 PhD 版式回退。
- Q: Since 列定位以哪一处为准？ → A: 以 FR-005 为唯一规范源（5.5em 固定槽、8px 间隙、无链接尾隙 ≤8px）；Assumptions 仅保留引用。
- Q: FR-008 的「24px 对称内距」适用于所有视口吗？ → A: 行内 24px 对称内距不变；容器内距按全站断点，≤480px 为 16px；跨区块姓名左缘仍须对齐。
- Q: 文档中的槽、轨、栏、列如何统一？ → A: 槽位 = 行内语义位置；轨道 = CSS 网格列宽；栏 = 两栏布局的左右栏；行内「第二列 / 第三列」指槽位。
- Q: 同一栏内「Since 左缘同线」在 PhD 同时存在有链接行与无链接行时如何判定？ → A: 仅在链接槽占用一致的行组内判定同线（≤1px）；有链接行的 Since 随该行链接宽度左移并与链接保持 8px，无链接行 Since 右缘靠近行右缘（≤8px 尾隙）；Master's 当前 11 行全无链接，11 行 Since 左缘 MUST 全同线。
- Q: Since 字号 18px 下 5em 槽宽处于临界（文本约 90px）时如何处理？ → A: 第二列固定槽由 5em 调整为 **5.5em（99px）**；18px 下 `Since YYYY` 单行容纳并留约 9px 余量；768px 最紧档按 4em 姓名下限计的最小需求 295.16px ≤ 296px（余 0.84px）；实际姓名轨 181px（无链接）/ 72.84px（最大链接）。
- Q: Since 字号 18px 与站点 `rem` 的关系是什么？ → A: 站点根字号为浏览器默认 16px（`body` 的 18px 不改变 `rem` 基准），实现 MUST 使用显式 `18px`（或等价的 `1.125rem`），MUST NOT 通过修改 `html` 根字号达成（会放大全站 rem 尺寸）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 宽屏下 Master's Students 呈左右两栏 (Priority: P1)

访问者在视口宽度 ≥768px 打开 Team 页时，Master's Students 的 11 位同学分布在左右两栏：两栏等宽、顶线一致，每栏各占约半个内容区宽；分组标题仍横跨整个内容区，位于两栏上方。单条记录不再横跨整行，信息密度与相邻的 PhD Candidates 分组一致。

**Why this priority**: "将硕士也写成两栏"是本特性的直接诉求；两栏结构是用户点名要的结果，也是让两个学生分组视觉统一的核心。

**Independent Test**: 在 1440 / 1280 / 1024 / 768px 四档视口打开 Team 页，测量 Master's Students 两栏宽度、条数分布与顶线位置；即使行内列顺序尚未调整，也能独立确认两栏结构成立。

**Acceptance Scenarios**:

1. **Given** 视口宽度 ≥768px，**When** 浏览 Team 页 Master's Students 区域，**Then** 11 条记录按入学年份升序排列后，以 6 条左栏、5 条右栏分成两栏，两栏宽度差 ≤1px。
2. **Given** 视口宽度 ≥768px，**When** 对比两栏容器，**Then** 两栏顶线一致（差值 ≤1px），栏间保留固定间隔（实现值 32px），任何一条记录都不再横跨整个内容区。
3. **Given** 分组标题 "Master's Students"，**When** 页面渲染，**Then** 标题只出现一次，横跨内容区全宽并位于两栏上方，不随栏数变化而复制。
4. **Given** 同一页面中的 PhD Candidates 两栏，**When** 对比两个分组的栏宽与栏间距，**Then** 两组的双栏结构视觉一致，不出现一套宽一套窄。

### User Story 2 - 每行按「姓名 → Since → 右侧链接」分层 (Priority: P1)

访问者浏览任一栏时，每行的信息从左到右依次为姓名、Since 年份、成员链接；Since 在第二列，各行左缘对齐；若成员有链接，链接贴齐所在栏右缘。当前 11 位硕士均有年级（2024–2026）、均无链接，因此每行显示姓名与 Since，右侧留空且不出现占位内容。

**Why this priority**: 用户要求"同上一个 feature"，010 的行内分层是双栏可读性的组成部分；只分栏而不重排行内信息，会让硕士分组与 PhD 分组的行结构不一致。

**Independent Test**: 在 1440px 视口逐行检查 11 条记录：确认视觉顺序为姓名 → Since →（链接，若有）；抽查无链接行与未来有链接行的表现；用元素外接矩形核对 Since 左缘与姓名左缘的对齐关系。

**Acceptance Scenarios**:

1. **Given** 任一硕士成员（当前 11 人均有年级），**When** 该行渲染，**Then** 显示顺序为姓名、`Since <年份>`（2024–2026），Since 位于姓名右侧的第二列位置。
2. **Given** 同一栏内的两位成员，**When** 比较其 Since 文本元素，**Then** 两者左缘水平差值 ≤1px（第二列对齐）。
3. **Given** 当前无链接的硕士成员，**When** 该行渲染，**Then** 右侧区域为空，不出现空链接、隐藏链接文本、破折号或其他伪造内容；姓名仍为纯文本。
4. **Given** 未来某位硕士成员填写了唯一链接，**When** 该行渲染，**Then** 成员链接标签贴齐所在栏右缘（扣除固定内距），文案仍为 Homepage / GitHub / Scholar 之一。
5. **Given** 姓名，**When** 检查可点击区域，**Then** 姓名仍为纯文本，唯一链接出口仍为右侧标签（若有）。
6. **Given** 视口从 768px 增宽到 1440px，**When** 检查同一栏，**Then** 姓名列吸收多余宽度，Since 左缘随之单调右移（容器达到 1180px 上限、内容区 1132px 后保持不变）；有链接时 Since 右缘与链接左缘保持 8px（±1px）间隙，且不出现随视口增大的空白。

### User Story 3 - 页面收窄时退化为单栏与竖排条目 (Priority: P2)

访问者在窄屏（手机）打开 Team 页时，Master's Students 退回单栏，退化规则与 PhD 完全一致：480–767px 保持横向行（姓名 → Since → 右侧链接），每条记录横跨内容区；<480px 为竖排条目——第 1 行姓名居左、Since 右对齐，第 2 行链接独占一行（当前无链接则不渲染第 2 行）。两种窄屏形态都不出现半栏、空白第二栏或横向滚动。

**Why this priority**: 两栏在窄屏会挤压信息；退化规则保证移动端可读性，并与 PhD 分组保持同一套响应式行为。

**Independent Test**: 在 767 / 576 / 481 / 480 / 375 / 320px 六档视口检查：仅一栏、11 条记录顺序不变；481 / 480px 为横向行且 Since 位于第二列；375 / 320px 为竖排（姓名与 Since 同行、Since 右对齐）；无重叠、截断、溢出与页面横向滚动。

**Acceptance Scenarios**:

1. **Given** 视口宽度 <768px，**When** 浏览 Master's Students，**Then** 11 条记录以单栏、自上而下呈现；不渲染空的第二栏，也不出现两栏压缩后的半宽列。
2. **Given** 480px ≤ 视口宽度 < 768px，**When** 检查任一行，**Then** 姓名居左、Since 位于第二列且左缘对齐，并随行宽变宽整体右移；有链接时与链接保持 8px 间隙，每条记录横跨内容区整宽。
3. **Given** 视口宽度 <480px，**When** 检查任一行，**Then** 第 1 行姓名居左、Since 右对齐（右缘与内容区右缘扣除固定内距的差值 ≤1px）；无链接成员不渲染第 2 行，不渲染占位。
4. **Given** 320px 最窄视口，**When** 浏览整页，**Then** 无元素重叠、文字截断、内容溢出、非预期换行或页面横向滚动。

### Edge Cases

- **Master's 名单为空**：沿用既有 "Master's students coming soon." 占位文案，占满内容区整行，不渲染空的第二栏。
- **仅 1 条记录**：单栏呈现且记录占满内容区整宽（≥768px 时同样不得只占半栏），不为了凑两栏而渲染空栏。
- **记录数决定两栏分布**：n 为偶数时均分（如 n=6 → 3 + 3）；n 为奇数时左栏比右栏多 1 条，即左栏 floor(n/2)+1、右栏 floor(n/2)（如 n=5 → 3 + 2；当前 n=11 → 6 + 5）；n=1 时仅左栏 1 条并占满内容区整宽，不渲染空栏。
- **排序边界**：两个在读分组均按入学年份从低到高排列；无年级成员排在最后，同年级成员保持数据文件顺序；排序只影响展示顺序，不改写数据文件。
- **成员无年级**（当前 11 人均有年级）：横向行中第二列留空，不渲染 "Since" 或破折号占位；竖排态第 1 行仅姓名、不渲染占位；行高与同形态其他行一致。
- **成员无链接**（当前 11 人均无链接）：横向行中右侧区域留空；竖排态不渲染第 2 行；不渲染链接锚点、隐藏文案或占位符。
- **姓名或标签超长**：姓名（含无空格拉丁字符串）MUST 在所属栏的姓名槽内换行收纳，不得越入 Since 列、溢出栏边界、相互重叠或撑宽页面；链接标签本身保持单行。
- **单栏连续列表**：<768px 时两栏合并为一条连续列表，不得在栏接缝处出现双分隔线、额外留白或重复顶线。
- **断点边界**：视口 768px 按两栏呈现，767px 及以下按单栏呈现；480px 及以上为横向行，479px 及以下为竖排条目；按整数视口宽度验收，不考虑次像素级别的边界行为。
- **容器被 1180px 上限约束（内容区 1132px）**：超宽视口下两栏宽度不再继续增大，仍等宽、顶线一致；Since 左缘达到该上限后不再继续右移。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 视口宽度 ≥768px 时，Master's Students 名单 MUST 以左右两栏呈现；两栏 MUST 等宽（宽度差 ≤1px），顶线一致（差值 ≤1px），并保留明确栏间距（实现值 32px）。分组标题 MUST 只出现一次、横跨内容区全宽并位于两栏上方。该阈值与 PhD 分组、教师名片变为单列（每行一张）的断点一致。
- **FR-002**: 视口宽度 <768px 时，同一名单 MUST 退化为单栏；其中 480px ≤ 视口 < 768px 时每条记录横跨内容区整宽并保持横向行；视口 <480px 时 MUST 采用与 PhD 一致的竖排条目（第 1 行姓名居左、Since 右对齐，第 2 行链接独占一行、靠左，若有链接）。两种形态 MUST NOT 保留空栏、半宽列或双分隔线。边界按整数视口宽度验收，不考虑次像素级别的行为。
- **FR-003**: 名单 MUST 先按入学年份从低到高排序（grade 升序，2024 → 2026），无年级成员排最后，同级保持数据文件顺序；再按该顺序切分：n ≥ 2 时 n 为偶数两栏各 n/2 条，n 为奇数左栏 floor(n/2)+1 条、右栏 floor(n/2) 条（向下取整）；左栏先排列前 floor(n/2)+1 条（n 为偶数时为前 n/2 条），其余按同一顺序进入右栏。当前 11 条 MUST 按左栏 6 条（朱祉同、张蓓泽、叶振雷、艾明旭、刘润泽、刘梦犁）、右栏 5 条（张蓬月、顾树焕、温泽林、李佳睿、毛乐平）呈现。n=1 时仅左栏 1 条并占满内容区整宽，不渲染空栏。该排序对 PhD Candidates 与 Master's Students 一致生效；本特性 MUST NOT 改变数据文件中的条目顺序，排序仅为展示层派生。
- **FR-004**: 信息视觉顺序 MUST 为「姓名 → Since 年份 → 成员链接」。横向行（≥480px）中：姓名在最左侧，`Since <年份>` 位于第二列，成员链接贴齐所在栏右缘；竖排态（<480px）中：第 1 行为姓名（左）与 Since（右对齐），第 2 行为链接（左对齐，若有）。
- **FR-005**: 横向行中，同一栏内**链接槽占用一致**的行，其 Since 文本 MUST 左对齐到同一条竖直线（水平差值 ≤1px；PhD 混排栏中有链接行与无链接行分别成组判定，见 Clarifications），且第二列（实现值 5.5em 固定槽，99px，两栏态与 480–767px 单栏横向态一致）MUST 随视口变宽整体右移（容器达到 1180px 上限、内容区 1132px 后保持不变）：姓名列 MUST 以 4em 为弹性基准宽度增长并吸收多余宽度（两栏态同时作为最小轨道宽度；单栏横向态为 flex 基准，支持视口内不得收缩到 4em 以下），有链接时 Since 右缘与链接左缘的间距 MUST 保持固定列间隙（实现值 8px，容差 1px），不得出现随视口增大的空白；无链接时不渲染占位，Since 右缘靠近该行右缘（允许 ≤8px 尾隙）。竖排态中，所有行的 Since 右缘 MUST 对齐到同一条竖直线（差值 ≤1px）。无年级的行 MUST 不渲染 Since 元素与任何占位文案，MUST NOT 影响其他行的槽位位置。
- **FR-006**: 横向行中，同一栏内所有成员链接的右缘 MUST 对齐到同一条竖直线（差值 ≤1px），并贴齐该栏右缘（扣除固定内距）；竖排态中，链接独占一行，其左缘 MUST 与姓名左缘对齐（差值 ≤1px）。成员链接标签仍按 `url` → `github` → `scholar` 取第一个非空字段，文案与箭头形态不变。
- **FR-007**: 无链接成员 MUST 不渲染链接锚点、隐藏链接文本或任何占位；姓名 MUST NOT 变为链接。
