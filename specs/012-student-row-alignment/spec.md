# Feature Specification: Team 页在读学生名单的列布局调整（三列固定、两侧空白相等、Since 列内居中、链接右对齐）

**Feature Branch**: `012-student-row-alignment`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "调整优化在读学生的列的布局。 since 在表格居中放置，个人主页链接右对齐。"

## 目标与范围

Team 页的在读学生名单（PhD Candidates 与 Master's Students）当前每行按「姓名（左）→ Since（右侧固定槽）→ 成员链接（最右）」排布：Since 紧贴行右侧并随视口变宽整体右移（011 FR-005），链接在横向行中右对齐；<480px 竖排时链接独占第 2 行并左对齐。

本特性调整这两个分组的行内列布局：

1. **三列固定宽度、两侧空白相等**：横向行（≥480px）每行分姓名列、Since 列、链接列。同一分组内三列宽度固定（姓名 3.5em / 63px，Since 默认 5em / 90px，必要时 5.5em / 99px，链接 6.5em / 117px），不随本行姓名长短或链接标签变化；姓名列内居左、Since 列内居中、链接列内居右；姓名列右缘到 Since 列左缘的空白，与 Since 列右缘到链接列左缘的空白相等（±1px）。
2. **空链接列保留**：无链接的行仍保留链接列宽度，不渲染占位；同一分组内所有行（无论有无链接）的三列位置一致，Since 中心落在同一条竖线上。
3. **对齐结果**：Since 位于自身 Since 列（默认 5em，必要时 5.5em）的中间，不再要求位于整行中点；由于姓名列比链接列窄 3em，Since 中心比行内容区中点偏左 1.5em（推导与定义见 FR-002 与 Assumptions），这是两侧空白相等的直接结果，不是缺陷。链接文字右缘贴齐行右缘内距。
4. **竖排结构不变，链接改为右对齐**：<480px 竖排态保持第 1 行姓名居左、Since 右对齐；链接独占第 2 行且文字右对齐。
5. **保持既有结构**：两栏/单栏切换、分组标题、名单顺序与切分、姓名 → Since → 链接的视觉顺序、字号、配色、分隔线、数据内容均不变。

**范围之外**：

- 两栏断点（≥768px）、32px 栏距、按年级升序的排序、左右栏切分公式与各栏条数；
- Graduates 名单、Faculty 卡片、导航、页脚与首页等其他区域；
- 学生数据（姓名、level、grade、url / github / scholar）与 "Since" 文案、链接标签映射、字号、配色、字体族、分隔线风格；
- 新增列标题行（如 Name / Since / Homepage 表头）、列间竖线、备注或其他装饰；
- 姓名超长导致的换行或溢出；当前数据最长 3 字，3.5em 姓名列可容纳。姓名换行不纳入本期验收；若发生，按契约 §5 视为姓名列内的已声明形态，不计入 SC-004 的「非预期换行」或布局破损；
- 新增折叠、筛选、分页、动效或交互。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 横向行三列固定、Since 列内居中、链接居右 (Priority: P1)

访问者在 ≥480px 视口浏览 Team 页任一在读分组时，每行从左到右依次是姓名、Since 年份、成员链接。同一分组内三列宽度固定，姓名的长短、链接的有无都不会改变列的位置；Since 在自己那一列里居中，姓名列右侧与 Since 列左侧的空白、Since 列右侧与链接列左侧的空白相等；链接贴齐行右缘。两栏态下，每一栏各行的 Since 都落在该栏的同一条竖线上。

**Why this priority**: 这是用户本次直接点名的诉求，也是列布局调整的核心；只调整对齐、不改结构即可独立交付价值。

**Independent Test**: 在 1440px 与 768px 视口逐行测量同一分组内 Since 文本中心的极差、Since 文本中心相对行内容区中点的偏移（应为中点左侧 27px±1px）、链接文字右缘与行右缘内距的偏差（以文字范围为准）；即使竖排态尚未验证，也能独立确认横向三列成立。

**Acceptance Scenarios**:

1. **Given** 视口 ≥768px 且该行无链接（当前全部 Master's 行与多数 PhD 行），**When** 该行渲染，**Then** Since 文本中心位于所在栏行内容区中点左侧 27px（±1px），且同一栏所有无链接行的 Since 中心极差 ≤1px。
2. **Given** 视口 480–767px 且该行无链接，**When** 该行渲染，**Then** Since 文本中心位于整行内容区中点左侧 27px（±1px）。
3. **Given** 该行有成员链接，**When** 该行渲染，**Then** 链接文字右缘与行右缘（扣除既有行内固定内距）偏差 ≤1px；Since 与链接的三列位置与同组无链接行一致（Since 中心极差 ≤1px），不因链接标签宽窄而移动，也不发生碰撞夹取。
4. **Given** 任一成员行，**When** 检查 DOM 与视觉顺序，**Then** 顺序仍为姓名 → Since → 链接，姓名保持纯文本，链接标签仍为 Homepage / GitHub / Scholar 之一。

### User Story 2 - 竖排条目中链接右对齐 (Priority: P1)

访问者在手机（<480px）打开 Team 页时，每条记录仍为竖排：第 1 行姓名居左、Since 右对齐；若成员有链接，第 2 行独占整行并右对齐，与第 1 行的右缘对齐；无链接的成员不渲染第 2 行。

**Why this priority**: 这是用户点名的第二项对齐规则；窄屏是当前链接唯一左对齐的形态，与桌面端不一致。

**Independent Test**: 在 375px 与 320px 视口检查 PhD 的 4 条有链接记录：链接文字位于第 2 行且文字右缘与行右缘内距偏差 ≤1px（量链接文字范围，不量占满整行的链接元素盒）；其余 26 条无链接记录只有 1 行。

**Acceptance Scenarios**:

1. **Given** 视口 <480px 且有链接的成员，**When** 该行渲染，**Then** 第 1 行为姓名（居左）与 Since（右对齐），第 2 行为链接且文字右对齐，链接文字右缘与第 1 行右缘偏差 ≤1px。
2. **Given** 视口 <480px 且无链接的成员，**When** 该行渲染，**Then** 仅 1 行（姓名与 Since），不渲染空链接行或占位。
3. **Given** 320px 最窄视口，**When** 浏览整页，**Then** 无重叠、截断、溢出或页面横向滚动。

### User Story 3 - 名册规模与既有结构在各视口保持稳定 (Priority: P2)

访问者在任意支持的视口浏览时，30 位在读学生（19 位博士、11 位硕士）各出现一次；两栏/单栏结构、分组标题、名单顺序、Since 文案、链接数量与字号均不变；调整对齐后不出现新的布局破损。

**Why this priority**: 对齐调整不应以回退 010 / 011 的双栏成果或破坏既有内容为代价；这是交付前的守门条件。

**Independent Test**: 在十一档视口统计学生条数、Since 文案、链接数量与分组结构，并逐档检查页面是否横向溢出、元素是否越界。

**Acceptance Scenarios**:

1. **Given** 任一支持视口，**When** 渲染 Team 页，**Then** 在读分组共 30 条记录（PhD 19、Master's 11）各出现一次，恰有 30 个 `Since <年份>` 文案与 4 个成员链接。
2. **Given** 视口 ≥768px，**When** 检查两个在读分组，**Then** 两栏结构、栏距、各栏条数（PhD 10 + 9、Master's 6 + 5）与调整前一致。
3. **Given** 十一档视口逐档检查，**When** 汇总布局破损，**Then** 破损计数为 0，且构建与类型检查通过。

### Edge Cases

- **横向行中的无链接行**（当前全部 Master's 行与多数 PhD 行）：链接列仍保留 6.5em 宽度，但不渲染占位、破折号或隐藏文本；该行三列位置与同组有链接行完全一致，Since 中心不因链接缺失而移动。
- **有链接行与 768px 窄双栏**：三列固定宽度合计 270px（Since 5em）或 279px（Since 5.5em），768px 行内容区 296px，两侧空白各 13px 或 8.5px；Since 与链接不重叠，不再需要碰撞夹取；链接标签宽窄不改变列位置。
- **长链接标签**：当前 4 个标签（Homepage / GitHub / Scholar）保持单行；标签宽度 MUST ≤117px，文字右缘贴齐行右缘内距，不得换行、截断或溢出链接列。
- **Since 单行与 5.5em 备选**：`Since <年份>` MUST 保持一行；若验收环境实测 Since 文本宽度超过 5em（90px；以文字范围测量，不以元素盒宽代替），Since 列 MUST 改为 5.5em（99px），姓名列与链接列不变，768px 两侧空白由 13px 变为 8.5px（仍 ≥8px）；MUST NOT 折行、缩小字号、截断或溢出列外。当前 Windows 约 85px、Linux 回退约 90px；若 5.5em 仍放不下，按缺陷处理。
- **缺年级成员**（当前无）：不渲染 Since 元素与占位；横向行中有链接时，链接 MUST 仍位于链接列（第 3 列），不因 Since 缺失而左移；不影响其他行 Since 的列位置。验收时可在浏览器中对该行做一次性 DOM 注入（临时移除 `.grade`，不改数据文件）并记录结果。
- **成员无链接 / 名单为空 / 仅 1 条记录**：无链接行保留链接列宽度但不渲染占位；名单为空时沿用既有 `"…coming soon."` 占位，不渲染网格行；仅 1 条记录时沿用既有 `.is-single` 单栏规则，行内容区为内容区整宽。后两种状态在当前数据（PhD 19 / Master's 11）中不会出现，且其行内几何已被 480–767px 单栏横向档的测量覆盖，**本期明确不单独验收**（不做 DOM 注入，不构造空名单）；若未来数据出现这两种状态，按既有分支与本文的三列规则执行，并在下一次布局变更时补测。
- **断点边界**：视口 ≥480px 为横向行（三列布局），≤479px 为竖排（Since 右对齐、链接右对齐）；按整数视口宽度验收；320px 为支持下限。
- **容器达到 1180px 上限（内容区 1132px）**：三列宽度不变，两侧空白随行宽增大但保持相等；Since 与行左缘的相对距离随空白增大，链接文字右缘仍贴齐行右缘。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 横向行（视口 ≥480px）中，信息视觉顺序 MUST 保持「姓名 → Since 年份 → 成员链接」，并 MUST 呈现为姓名列、Since 列、链接列三列；姓名 MUST 在姓名列内居左，Since MUST 在 Since 列内居中，成员链接 MUST 在链接列内居右；MUST NOT 新增列标题行、列间竖线或其他装饰。页面结构 MUST 保持现有的 `ul` / `li` 列表，MUST NOT 改为 `<table>`，也 MUST NOT 添加表格语义（如 `role="table"`、`th`、表头行）。
- **FR-002**: 横向行中，三列宽度 MUST 固定为姓名 3.5em（63px）、链接 6.5em（117px）；Since 列 MUST 为 5em（90px），若按 FR-011 判定 5em 无法容纳单行 Since，则 MUST 为 5.5em（99px）。同一分组内所有行 MUST 使用同一套列宽（不得混用 5em 与 5.5em），且 MUST NOT 随本行姓名长短或链接标签变化。姓名列右缘到 Since 列左缘的空白 MUST 等于 Since 列右缘到链接列左缘的空白（偏差 ≤1px）。Since 文本的可见水平中心 MUST 与 Since 列中心对齐（偏差 ≤1px）。「行内容区」指一行去掉左右各 24px 行内留白后的宽度；两栏态（≥768px）的「行」为所在栏的单行，单栏态（480–767px）的「行」为内容区整宽行；同一栏内所有行的 Since 中心 MUST 落在同一条竖直线上（偏差 ≤1px）。
- **FR-003**: 横向行中，成员链接的文字右缘 MUST 贴齐所在行右缘（扣除既有行内固定内距，偏差 ≤1px），标签 MUST 保持单行，标签宽度 MUST ≤ 链接列宽 6.5em（117px，±1px），且 MUST NOT 溢出链接列；无链接的行 MUST 仍保留链接列宽度，但 MUST NOT 渲染任何占位、破折号或隐藏文本。
- **FR-004**: 横向行 MUST NOT 采用碰撞夹取：Since 列位置 MUST NOT 因链接存在、链接标签宽窄或姓名长短而移动；有链接行与无链接行的 Since 中心 MUST 一致（偏差 ≤1px）。三列之间的空白 MUST ≥8px（768px 档：Since 5em 时 13px，Since 5.5em 时 8.5px），MUST NOT 出现姓名、Since、链接相互重叠。
- **FR-005**: 竖排态（视口 ≤479px）中，第 1 行 MUST 为姓名（居左）与 Since（右对齐，右缘与行右缘内距偏差 ≤1px）；有链接时第 2 行 MUST 由链接独占整行，链接文字 MUST 右对齐，链接文字右缘与第 1 行右缘（行内容区右缘）偏差 ≤1px；无链接时 MUST NOT 渲染第 2 行或占位。右对齐与右缘判定 MUST 以链接文字范围（text range）为准；链接元素占满整行，其元素盒右缘不得作为判定依据。
- **FR-006**: 本特性 MUST 对 PhD Candidates 与 Master's Students 两个在读分组一致生效；分组标题、名单顺序（年级升序）、左右栏切分公式与条数（PhD 10 + 9、Master's 6 + 5）、两栏断点与 32px 栏距 MUST 保持不变；验收时 MUST 在 767px 与 768px 实测确认单栏 / 双栏切换，并确认栏距为 32px。
- **FR-007**: 30 位在读学生（19 位博士、11 位硕士）MUST 各呈现一次且仅一次，姓名、`Since <年份>` 文案与链接标签 MUST 保持原样；缺失年级或链接时 MUST NOT 渲染占位内容，姓名 MUST NOT 变为链接。
- **FR-008**: 在支持的十一档视口（1920 / 1440 / 1280 / 1024 / 768 / 767 / 576 / 481 / 480 / 375 / 320px）下 MUST 无布局破损：元素重叠、文字截断、内容溢出、非预期换行（不含姓名列内已声明的超长姓名换行）、页面横向滚动均为 0。320px 为支持下限；窄于 320px 的视口不纳入支持与验收。
- **FR-009**: 构建与类型检查 MUST 通过；本特性 MUST 仅改动 Team 页在读学生行的列布局样式，MUST NOT 新增运行时依赖、脚本或组件，MUST NOT 修改学生数据文件、Graduates 名单、Faculty 区块或其他页面。
- **FR-010**: Since 文案、字号（18px）与链接标签的文案、字号 MUST 保持不变；本特性 MUST NOT 通过修改站点根字号或缩小字号来满足对齐要求。
- **FR-011**: `Since <年份>` MUST 保持一行，MUST NOT 换行、截断或省略。若验收环境实测 Since 文本宽度超过 5em（90px；以文字范围测量，不以元素盒宽代替），横向行的 Since 列 MUST 调整为 5.5em（99px），姓名列与链接列宽度不变，两侧空白仍 MUST 相等且 ≥8px；若 5.5em 仍无法容纳单行 Since，MUST 按缺陷处理并停止验收，不得通过缩小字号、折行或隐藏内容规避。

**与既有规范的关系**：本特性以「三列固定宽度（姓名 3.5em、Since 5em（必要时 5.5em）、链接 6.5em）+ 两侧空白相等」取代 011 FR-005 中「姓名列弹性增长带动第二列（5.5em 固定槽）随视口整体右移」的定位规则，并取代 011 FR-006 中「竖排态链接左缘与姓名左缘对齐」的规则；011 的其余条款（两栏结构、排序与切分、字号、无链接不渲染占位等）继续有效。

### Key Entities

- **在读学生条目**：姓名、入学年份（grade）、唯一链接（url / github / scholar 三选一，可为空）；本特性只改变条目在行内的水平位置，不改动内容。
- **行**：两栏态下为某一栏中的单行条目，单栏态下为内容区整宽的单行条目；包含姓名列、Since 列与链接列（链接为空时链接列仍保留宽度）。
- **名单区域**：分组标题 + 两栏（或单栏）条目构成，栏数随视口切换。

## Assumptions

- **「表格」指每条学生记录所在的整行**：两栏态以所在栏的行宽为准，单栏态以内容区行宽为准；「居中」指 Since 文本可见范围的水平中心与其所在 Since 列的中心对齐，不再指整行水平居中。因行内左右内距对称，行内容区中点与整行中点重合，下文统一以「行内容区中点」表述。由于姓名列 3.5em 比链接列 6.5em 窄 3em，两侧空白相等时 Since 中心必然位于行内容区中点左侧 1.5em（27px）；这是本方案的定义特征，不是偏差。这里的「两侧空白」比较的是列边界之间的空白（姓名列右缘—Since 列左缘、Since 列右缘—链接列左缘），不是姓名文字到 Since 文字的距离；姓名文字短于姓名列宽时，姓名列内右侧的留白不计入列间空白。由于列边界不可见，验收以 Since 中心相对行内容区中点的 27px 偏移作为等隙的可测量结果。该偏移只取决于姓名列与链接列的宽度差，Since 列取 5em 或 5.5em 均成立。
- **横向行与竖排态的边界沿用 011**：≥480px 为横向行，≤479px 为竖排条目；容器内距按全站断点（≤480px 为 16px），行内左右内距保持 24px（即「行内容区」为行盒去掉左右各 24px 后的宽度）。320px 为支持下限，窄于 320px 不纳入支持与验收。按整数视口宽度验收：小于 480px 与 ≤479px 是同一口径，CSS 中的 `max-width: 479.98px` 与这里的 ≤479px 等价；带小数的视口宽度（如 479.5px）不纳入验收。
- **当前数据快照**：19 位博士（4 人有链接）与 11 位硕士（0 人链接），全部有年级；共 30 个 Since 文案与 4 个链接，仅作为验收基准，不作为永久数据约束。
- **固定三列与两侧空白相等的取舍**：用户确认按 `checklists/layout.md` 的需求变更记录 D1–D3 及 2026-11-22 补充 S1–S3（S4 仅为清单内部归档项）执行。横向行三列基准为 3.5em / 5em / 6.5em（18px 下 63 / 90 / 117px），两侧空白相等；768px 行内容区 296px 时两侧各 13px，三列合计 270px。Since 必须单行；若验收环境实测超过 90px，Since 列改为 5.5em（99px），三列合计 279px，两侧空白各 8.5px，仍 ≥8px。链接列为空时仍保留 6.5em，因此同一分组所有行的 Since 落在同一条竖线上。代价是 Since 不再位于行内容区中点（固定偏左 27px；5em / 5.5em 均成立）；当前最长 3 字姓名（约 54px）有 9px 余量，姓名换行不纳入本期验收。取消原 FR-004 的碰撞夹取。
- **左右栏同理**：左右栏使用同一套行内样式，右栏有链接的行与左栏结果一致，不单独设验收项；SC-002 的 4 条链接行均在左栏，其结论同样适用于右栏。
- **不可达边界状态不单独验收**：名单为空与分组仅 1 条记录（`.is-single`）在当前数据中不会出现；本期沿用既有占位与单栏规则，不做 DOM 注入或构造数据，理由记录在 Edge Cases 与验收证据中。该决定不改变任何 FR / SC 的判定口径。
- **既有视觉体系不变**：颜色、字体族、分隔线、箭头、行高与链接悬停态沿用现有样式；不新增表头、竖线或背景。链接的鼠标悬停与键盘选中（focus-visible）样式沿用现有，不新增；键盘选中时的外框不得导致页面横向滚动；打印样式不纳入本期范围。
- **验收环境**：使用当前智能体工具自带的浏览器验收；页面缩放 100%，使用站点默认字体（本机可用字体），以该环境的实际渲染为准；其他浏览器或字体环境的测量只作参考，不作为通过或不通过的依据。
- **验收口径**：沿用项目十一档视口矩阵；200% 缩放与最小字号检查不纳入本期（与 007 / 010 / 011 口径一致）。
