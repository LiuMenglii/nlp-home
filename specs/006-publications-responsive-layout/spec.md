# Feature Specification: Publications 条目与年份导航响应式优化（Publications Responsive Layout）

**Feature Branch**: `006-publications-responsive-layout`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "Use Skill: speckit-specify 修改优化 Publications 界面：1. 修改不同分辨率下条目的布局行为：在宽屏时，如果一行放不下论文名称和期刊名称，则让期刊名称换行，并且将 CCF 标签和 LINK 标签对齐（也就是即使某一个是空的，这列空着，将其他的对齐）；在窄屏时，将期刊名称换行，CCF 标签与 LINK 标签在期刊名称的同一行，靠右对齐；再窄一点的布局也优化一下（目前我还没思路，请自行发挥）。2. 将19年及以前的标签合为一个。同时，手机上的标签显示看起来有点奇怪，请优化布局。"

## Clarifications

### Session 2026-10-23

- Q: 同一日期内论文标题如何比较排序？ → A: 按字符串字典序（`<` 逐字符比较），不引入 locale 规则；大小写、空格与标点的差异按字符编码自然决定。
- Q: 移动端吸顶的年份分组标题如何与站点顶部导航共存，并在计数增长时保持稳定？ → A: 标题紧贴站点粘性导航下方、不透明背景、固定行高、计数与年份同行（如 `2026 (20)`）；层级低于站点导航，三位数计数只增宽不增高。移动端年份导航 MUST 保留 DOM：`.year-nav` MUST 为 `display:none`，验收以计算样式与可见数量为准。
- Q: 仅有 arXiv 链接的论文是否必须填写 `date`？ → A: MUST 填写，取 arXiv 首次提交日期（v1）；无链接条目 MUST 留空。
- Q: 同一 DOI 条目同时存在正式出版日期与上线日期时，`date` 取哪个？ → A: 正式出版日期优先；无正式出版日期时取上线日期。
- Q: 标签空槽如何处理占位文本？ → A: 允许复用同宽隐藏标记，但 MUST 无可见或可读的占位文字；空槽 MUST 与可见标签同宽、不可见、不可聚焦，并对整个空槽设置 `aria-hidden`。

## 目标与范围

本特性覆盖 Publications 的**展示层**，并为论文数据新增日期字段（有链接必填、无链接留空）；展示层覆盖两处消费同一论文条目形态的界面：

1. **论文条目跨分辨率布局**（Publications 页全列表与主页 Publications 概览）：在宽屏、窄屏、很窄三档视口下，重新规定论文名称、期刊名称、CCF 标签与 LINK 标签的相对位置；CCF 与 LINK 按固定双槽对齐，某个标签缺失时保留空槽，使另一标签仍落在同一条列线上。
2. **年份导航与分组**（Publications 页）：将 2019 年及以前的所有年份标签合并为一个「2019 & Earlier」标签与分组；桌面端保留年份标签导航，手机端视觉隐藏顶部年份导航（DOM MUST 保留），改由吸顶的年份分组标题承担定位，消除标签墙。

本特性的边界：

- 论文条目的展示内容不变；本特性唯一的数据变更是为每条论文新增 `date` 字段（日期，`YYYY-MM-DD`；无链接条目可留空），用于组内时间排序；年份合并仍是展示层的分组规则。
- 期刊名称、论文名称、CCF 等级与链接的取值 **不变**。
- 配色、字体、字号、页面其他区块与其他页面 **不变**。
- 不新增页面、不新增运行时依赖或脚本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 论文条目在三档视口下排布稳定 (Priority: P1)

访客浏览 Publications（全列表或主页概览）时，论文条目在桌面宽屏、平板窄屏与手机很窄屏三档下都保持稳定、可预期的排布：宽屏下论文名称与期刊名称优先共行，放不下时期刊名称整体另起一行，CCF 与 LINK 仍固定在条目右侧的两条列线上；窄屏下论文名称独占第一行，期刊名称另起一行并与 CCF/LINK 同处第二行、标签靠右；很窄屏下论文名称、期刊名称、标签依次各占一行，标签靠右。无论某条论文缺少 CCF 或 LINK，标签列都不再左右漂移。

**Why this priority**: 这是用户本次最核心的诉求，直接决定 135 条论文在各类屏幕上的可读性与整齐度；当前条目在换行与标签缺失时会出现标签错位、标签簇掉落等观感问题，属于最直观的版式缺陷。

**Independent Test**: 在 1440px / 1280px / 1024px / 768px / 767px / 576px / 575px / 480px / 375px / 320px 视口打开 Publications 页，逐条核对宽屏、窄屏、很窄三档的标题、期刊名与标签位置是否符合 FR-002～FR-005；任一档可独立验收。

**Acceptance Scenarios**:

1. **Given** 视口 ≥768px（宽屏），**When** 浏览任一条目，**Then** 论文名称与期刊名称在可用宽度内能共行时共行；不能共行时，期刊名称整体另起一行置于论文名称下方、左边缘与论文名称左边缘对齐，MUST NOT 被挤在论文名称末行右侧；CCF/LINK 标签簇固定在条目右侧，不随期刊名称换行掉落到条目下方。
2. **Given** 视口 576px–<768px（窄屏），**When** 浏览任一条目，**Then** 论文名称独占第一行（占满条目内容宽度），期刊名称另起一行；CCF/LINK 标签簇与期刊名称同处第二行并靠条目右缘对齐，期刊名称在标签簇左侧的剩余宽度内换行。
3. **Given** 视口 <576px（很窄屏），**When** 浏览任一条目，**Then** 论文名称占第一行、期刊名称占第二行、标签簇占第三行并靠条目右缘对齐；任何内容不溢出条目、不引发页面横向滚动。
4. **Given** 某条目只有 CCF 没有 LINK、只有 LINK 没有 CCF、两者都有或两者都没有，**When** 在任一档浏览，**Then** 有标签时两条槽位均保留：缺失的一槽留空且不可见，另一标签与同类标签跨行对齐；两者都缺失时不渲染标签簇，也不留下空白占位行或空白区域。
5. **Given** 期刊名称很长（如 62 字符的期刊全名）或论文名称很长，**When** 在 320px 视口浏览，**Then** 文本在条目内正常换行收纳，无截断、无溢出、无横向滚动。

### User Story 2 - 年份标签合并与手机端整齐排布 (Priority: P2)

访客浏览 Publications 页的年份导航时，2026–2020 仍按年列出，2019 年及以前（2011–2019）合并为一个「2019 & Earlier」标签；列表中对应只有一个「2019 & Earlier」分组，组内按正式出版日期降序展示每条论文并保留各自的年份。桌面端（≥768px）保留年份标签导航；手机端（<768px）不显示顶部年份导航，改由吸顶的年份分组标题定位，页面按年份顺序滚动浏览。

**Why this priority**: 年份合并直接减少标签数量、降低手机端换行杂乱；属于本次用户明确点名的第二项诉求，但重要性次于 135 条论文条目的主体布局。

**Independent Test**: 打开 Publications 页，在 ≥768px 视口核对年份导航标签数量、顺序与计数，点击「2019 & Earlier」能否跳到合并分组；再在 375px 视口核对顶部不出现年份导航、8 个年份分组标题吸顶且可顺序到达、页面无横向滚动。可在不修改论文条目的情况下独立验收。

**Acceptance Scenarios**:

1. **Given** 当前论文数据与 ≥768px 视口，**When** 查看年份导航，**Then** 依次显示 2026、2025、2024、2023、2022、2021、2020、「2019 & Earlier」共 8 个标签；不存在单独的 2019、2018、2017、2016、2015、2014、2012、2011 标签。
2. **Given** 当前论文数据，**When** 查看「2019 & Earlier」标签与分组，**Then** 标签计数为 16，分组内恰好包含 2019 年及以前的全部 16 条论文，且组内按正式出版日期降序、同一日期按标题字母序排列；每条论文仍显示自身「期刊名 · 年份」。
3. **Given** 在 ≥768px 视口点击任一「2019 & Earlier」标签，**When** 页面跳转，**Then** 视口定位到「2019 & Earlier」分组标题，分组不被顶部导航遮挡。
4. **Given** 视口 <768px，**When** 浏览 Publications 页，**Then** 顶部不出现可见的年份导航或标签墙（`.year-nav` 计算样式为 `display: none`，DOM MUST 保留）；8 个年份分组标题在滚动时吸顶，用户可按年份顺序到达全部分组；页面本身不出现横向滚动。
5. **Given** 视口 ≥768px，**When** 查看年份导航，**Then** 标签按自然换行排布、左对齐，每个标签完整可读，计数可见。

### User Story 3 - 两处入口一致且无版式回归 (Priority: P3)

访客在主页 Publications 概览与 Publications 页看到同一形态的论文条目时，三档视口的排布规则一致；改动后两处在各验收视口下均无布局破损、无横向滚动，构建与部署流程正常。

**Why this priority**: 属于一致性与回归保障，不新增用户可见的正面价值，但作为交付门禁必须满足；优先级最低。

**Independent Test**: 分别在主页 Publications 概览与 Publications 页的 320px / 375px / 480px / 575px / 576px / 767px / 768px / 1024px / 1280px / 1440px 视口核对条目形态一致，并检查无重叠、截断、溢出与横向滚动；执行既有构建与 CI 检查。

**Acceptance Scenarios**:

1. **Given** 主页 Publications 概览与 Publications 页，**When** 在同一视口浏览，**Then** 两处论文条目遵循相同的宽屏/窄屏/很窄排布规则与标签双槽对齐规则。
2. **Given** 任一验收视口，**When** 浏览两处界面，**Then** 布局破损数为 0、页面横向滚动为 0。
3. **Given** 变更后的仓库，**When** 执行既有构建与 CI 门禁，**Then** 全部通过并可正常部署；除新增 `date` 字段并回填外，论文数据与数据结构定义无差异。

### Edge Cases

以下 EC-001～EC-005 为高风险边界，纳入验收门禁；其余为设计参考，不单独列为验收场景。

- **EC-001 空槽四类（FR-005 / SC-004）**：
  - 某条目只有 CCF、无 LINK：LINK 槽保留为空且不可见，CCF 仍落在 CCF 列；不得出现可见或可读的「Link」占位文字、空链接或可聚焦空元素；空槽容器 MUST 设置 `aria-hidden`。
  - 某条目只有 LINK、无 CCF（当前数据中 51 条）：CCF 槽保留为空，LINK 仍落在 LINK 列；不得因缺少 CCF 而让 LINK 左移；空槽容器 MUST 设置 `aria-hidden`。
  - 某条目 CCF 与 LINK 都没有（当前数据中 7 条）：不渲染标签簇、不保留空白列，也不新增第三行；条目文本区可正常使用整行宽度。
- **EC-002 320px 极窄视口（FR-001 / FR-004 / SC-003）**：标签簇与文字仍完整可见；无截断、无溢出、无重叠、页面无横向滚动；320px 以下设备不作要求（沿用 003 口径）。
- **EC-003 跨档切换（FR-001 / FR-003 / FR-004）**：手机横竖屏切换或视口跨越 768px / 576px 时，条目与年份分组标题切换为对应形态，不出现两档规则叠加或丢失。
- **EC-004 空合并组（FR-006 / SC-006）**：若没有任何 2019 年及以前的论文，则不渲染「2019 & Earlier」年份分组标题与计数 0；桌面年份导航也不渲染该标签。
- **EC-005 年份恰为 2019 或 2020（FR-006 / FR-007 / SC-006）**：2019 归入合并分组；2020 保持独立年份分组与独立标签，不得被合并。

其余设计参考（不作为独立验收门禁）：论文名称与期刊名称恰好能共行、论文名称很长但期刊名很短、期刊名称超过一整行宽度、很窄屏下无任何标签、桌面年份标签换行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 论文条目的视口分档 MUST 为：宽屏 = ≥768px；窄屏 = 576px–<768px；很窄屏 = <576px。验收视口 MUST 统一覆盖 1440px / 1280px / 1024px / 768px / 767px / 576px / 575px / 480px / 375px / 320px；320px 为最窄验收下限，<320px 不作要求。分档在 768px 与 576px 处为半开区间，无缝、无重叠。亚像素视口与分数 DPR 边界交由浏览器媒体查询处理，验收只取上述整数视口。
- **FR-002**: 宽屏（≥768px）下，每条论文条目 MUST 形成「左侧文本区 + 右侧标签簇」的两栏结构：文本区承载论文名称与期刊名称，标签簇固定在条目右侧，并以 CCF 槽（含隐藏占位）首行文字基线为锚点与条目第一行文字基线对齐，基线偏差 ≤1px；MUST NOT 因期刊名称换行而整体掉落到条目下方。论文名称与期刊名称 MAY 共行，条件是二者单行渲染宽度与固定间距之和不超过文本区可用宽度；不满足时期刊名称 MUST 整体另起一行，左边缘与论文名称左边缘对齐，MUST NOT 被压缩到论文名称末行右侧与标题争宽。期刊名称单行仍放不下时 MUST 在其所在行内换行。
- **FR-003**: 窄屏（576px–<768px）下，每条论文条目 MUST 为两行：第一行为论文名称，占满条目内容宽度；第二行为期刊名称与标签簇，期刊名称居左、标签簇贴条目内容右缘。期刊名称不换行时，标签簇 MUST 与期刊名称同行并靠右对齐；期刊名称换行时，标签簇 MUST 与期刊名称首行对齐，MUST NOT 垂直居中或下坠到末行。期刊名称 MUST 在第二行的剩余宽度内换行。没有标签时，期刊名称 MUST 使用第二行整行宽度。
- **FR-004**: 很窄屏（<576px）下，每条论文条目 MUST 为三行：第一行为论文名称，第二行为期刊名称，第三行为标签簇；第一、二行各占整行，标签簇 MUST 贴条目内容右缘对齐。某条目没有任何标签时 MUST 省略第三行，不保留空白行或占位间距。第三行的标签簇 MUST NOT 与期刊名称或论文名称重叠、溢出。
- **FR-005**: 标签簇 MUST 由两个槽位按固定顺序组成：左槽为 CCF 标签、右槽为 LINK 标签。当条目至少有一个标签时，两个槽位 MUST 均保留：存在的标签显示在其槽内，缺失的槽留空且不可见、无可见或可读的占位文字、无可聚焦空元素，空槽容器 MUST 设置 `aria-hidden`；同一条目内两标签在标签簇内垂直居中对齐，两者垂直中心偏差 ≤1px。跨条目比较，CCF 标签的左/右边缘 MUST 落在同一组竖线上、LINK 标签的左/右边缘 MUST 落在同一组竖线上，逐项偏差 ≤1px。两个标签都缺失时 MUST 不渲染标签簇、不保留空槽宽度。槽位宽度 MUST 归一化：CCF 槽以最宽 CCF 标签为基准、LINK 槽以 LINK 标签为基准，同类标签的最大宽度差 MUST <1px；MUST NOT 随当前条目是否显示该标签而变化。
- **FR-006**: 在 ≥768px 视口下，年份导航 MUST 显示 2020 年及以后每个存在论文的年份各一个独立标签，外加一个合并标签「2019 & Earlier」；合并标签 MUST 位于 2020 标签之后（顺序最后）。MUST NOT 再显示 2019 年及以前的独立年份标签。合并标签 MUST 展示其包含的论文总数（当前数据为 16）。若未来不存在 2019 年及以前的论文，则合并标签及其分组 MUST 不渲染。
- **FR-007**: 论文列表 MUST 按年份分组渲染：2020 年及以后每年一个分组、组标题为该年份；2019 年及以前全部论文合并为一个分组，组标题为「2019 & Earlier」，位置排在 2020 分组之后。合并分组内 MUST 包含全部 2019 年及以前的论文；所有分组内 MUST 按 `date` 降序排列，同一日期按标题字符串字典序升序（逐字符比较，不引入 locale 规则）；`date` 为空的条目 MUST 排在该组末尾并同样按标题字典序升序；每条论文 MUST 仍展示自身年份。桌面年份导航标签点击后 MUST 跳转到对应分组标题，并保持顶部粘性导航的锚点偏移。
- **FR-008**: 年份导航 MUST 按视口自适应：≥768px 时显示年份标签导航，标签自然换行、左对齐，标签文字完整可读，计数可见；<768px 时 MUST NOT 显示任何可见的年份导航或标签墙：`.year-nav` MUST 为 `display: none`，导航 DOM MUST 保留（验收以计算样式与可见数量为准，不删除节点）。年份分组标题 MUST 在滚动时吸顶：位置紧贴站点粘性导航下方，不透明背景，层级低于站点导航，任意滚动位置与站点导航下缘相接（间距 ≤4px）的吸顶标题数量 MUST ≤1。标题 MUST 为单行固定行高，年份与计数同行展示（如「2026 (20)」），计数位数增加只增宽不增高；标题 MUST NOT 遮挡论文条目标题或内容，分组结束时随分组滚出。两种形态均 MUST NOT 引起页面级横向滚动。
- **FR-009**: 论文条目的上述排布 MUST 同样适用于主页 Publications 概览：同一视口下两处条目遵循相同的分档规则、标题/期刊换行规则与标签双槽对齐规则。主页不显示年份导航，不受 FR-006～FR-008 影响。
- **FR-010**: 在各验收视口（见 FR-001）下，两处界面 MUST 无布局破损：无元素重叠、文字截断、内容溢出容器、非预期换行、页面横向溢出（页面底部不出现水平滚动条，整页可在屏幕宽度内完整显示）。沿用 003 FR-010 的判定口径，并按 Constitution v2.1.0 原则 VI 的五类布局破损定义判定。横向溢出判定 MUST 基于真实渲染并检查子元素边界（至少覆盖条目、标签簇与年份分组标题），MUST NOT 仅依赖 `scrollWidth` 或 `overflow-x: hidden`。
- **FR-011**: 本特性对论文数据的唯一改动 MUST 是新增 `date` 字段（ISO `YYYY-MM-DD`，无链接时可缺省、缺省即空值）并回填；其余字段与取值 MUST 不变。日期口径：有 DOI/正式出版页的 MUST 填写，优先取正式出版日期；无正式出版日期时取上线日期；仅有 arXiv 链接的 MUST 填写 arXiv 首次提交日期（v1）；无链接的 MUST 留空。除无链接条目外，`date` 缺失或格式非法 MUST 视为数据缺陷。`year` 继续表示分组与展示年份，`date` 仅用于组内排序，二者 MAY 不同（如在线优先出版）。年份合并 MUST 在展示层派生。MUST NOT 新增运行时依赖、运行时脚本或前端框架；视觉风格 MUST 保持简洁学术化，配色、字体、字号与其他区块版式不变（Constitution 原则 II/IV/V）。
- **FR-012**: 变更后站点 MUST 通过既有构建与 CI 门禁并正常部署至 GitHub Pages（Constitution 原则 III）。

### Key Entities

- **论文条目（Publication Item）**：展示论文名称、期刊名称、年份、CCF 等级与外部链接；本特性规定其在三档视口下的文本/标签排布、标签双槽结构与空槽规则；并为数据新增 `date` 字段用于组内时间排序，其余字段与取值不变。
- **标签簇（Badge Cluster）**：由 CCF 槽与 LINK 槽组成的固定双槽结构；决定同类标签跨条目的列对齐与缺失占位行为。
- **年份导航与年份分组（Year Nav / Year Group）**：Publications 页的年份跳转标签与对应论文分组；本特性规定 2019 年及以前合并为一个「2019 & Earlier」标签/分组，桌面保留年份标签导航，手机端视觉隐藏顶部导航（DOM MUST 保留）并改由吸顶分组标题定位。

## Success Criteria *(mandatory)*

- **SC-003**: 在 <576px 的验收视口下（含 375px、320px），100% 的论文条目满足 FR-004 三行形态；无标签条目不出现空白第三行；页面横向滚动为 0。

## Assumptions

- **分档取值**：宽屏 ≥768px、窄屏 576px–<768px、很窄屏 <576px，沿用站点 003 特性的 768px / 576px 临界点；其中本特性的「宽屏」覆盖 003 的「中等」与「宽屏」两档（两者采用同一套条目排布），「窄屏」对应 003 的 576–<768px 档。档位切换验证点取 767px / 575px。该分档只作用于论文条目，不改动其他组件。
- **「期刊名称」的范围**：指条目中展示的「期刊/会议名 · 年份」整体；换行规则作用于整个整体，不对「· 年份」单独拆行。
- **「2019 & Earlier」措辞**：站点界面语言为英文，合并标签与分组标题统一使用「2019 & Earlier」；计数沿用现有标签的「年份 + 数量」展示方式。
- **手机年份导航形态**：<768px 视觉隐藏顶部年份导航与标签墙（`.year-nav` 为 `display: none`，DOM MUST 保留）；年份分组标题在滚动时吸顶，固定单行行高，年份与计数同行显示，不透明背景且层级低于站点导航。桌面端（≥768px）保留原有年份标签导航。此为本轮对「手机上的标签显示看起来有点奇怪」的设计选择。
- **标题比较规则**：同一日期或 `date` 为空时，按标题字符串字典序（逐字符比较）排序；不区分语言环境的排序规则，大小写、空格与标点差异按字符编码自然决定。该项对验收影响很小，不做额外本地化处理。
- **很窄屏第三行的对齐**：标签簇沿用窄屏的右对齐口径，贴条目内容右缘，使三档下标签的右边缘位置一致；不采用左对齐。
- **两槽保留规则**：仅当条目至少有一个标签时保留双槽；两者都缺失时不保留空槽，以免产生无意义空白（当前数据中仅 7 条如此）。
- **槽位宽度来源**：CCF 槽以最宽 CCF 标签为基准、LINK 槽以 LINK 标签为基准归一化，同类标签最大宽度差 <1px；具体像素值由内容决定，spec 不规定固定像素。
- **年份合并与日期排序为展示层规则**：论文数据仅新增 `date` 字段（有链接必填、无链接留空），其余字段与数据结构约定不变；合并分组的计数、成员与组内排序由数据实时派生。
- **日期口径**：`date` 指论文的时间锚点，格式 `YYYY-MM-DD`。优先取出版社、期刊或会议论文集的正式出版日期；无正式出版日期时取上线日期；仅有 arXiv 链接的条目 MUST 使用 arXiv 首次提交日期（v1）；无链接条目 MUST 留空。当前数据中 66 条有 DOI、59 条仅有 arXiv、10 条无链接，因此预期 125 条有值、10 条为空；空值条目在组内排末尾。
- **共享展示**：主页 Publications 概览复用同一论文条目形态，因此本特性的条目排布规则自动适用于主页；主页没有年份导航，不涉及合并标签。
- **浏览器与设备下限**：跟随站点既有默认；320px 为最窄验收点，亚像素视口与分数 DPR 边界交由浏览器媒体查询处理，验收只取 FR-001 的整数视口；<320px 不作要求。
- **无障碍**：沿用 Constitution v2.1.0 的既有口径，本特性不新增无障碍要求；空槽不产生可聚焦元素或可见/可读占位文字，空槽容器 MUST 设置 `aria-hidden`。
