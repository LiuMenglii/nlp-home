## R1: 现状基线与身份不变量（FR-001 / SC-001 / SC-006）

**现状资产（`public/logo.svg`，逐字读取）**：

- 画布：`viewBox="0 19 140 105"`，内在尺寸 140×105，宽高比 **4:3**；内容 bbox ≈ `x 0–140, y 19–123.3`，几乎填满画布。
- 三色色块（`fill` 无描边）：橙 `#f7941d` 菱形 `M30 19 L60 59 L30 99 L0 59 Z`；绿 `#28ae6c` chevron `M30 19 L70 19 L100 59 L70 99 L30 99 L60 59 Z`；蓝 `#037ec2` chevron `M70 19 L110 19 L140 59 L110 99 L70 99 L100 59 Z`。三者**精确拼合**（绿/蓝的左边界分别与橙/绿的右边界完全重合），整体外轮廓为六边形：左尖 (0,59)、上边 (30,19)–(110,19)、右尖 (140,59)、下边 (30,99)–(110,99)。

- 右下尖角点缀：三角形 `M119.142 79.505 L110.176 123.319 80.505 89.858 Z`（蓝色，尖端朝下、与蓝色主体融合；原 draw.io 图的 `rotate(75,105,104)` 已并入坐标）。
- 三个白色辅助符号：①「文A」（`translate(19.5 49.5)`，约 20×20，橙色带）；②「大脑电路」（`translate(64.5 49.5)`，约 20×18.8，绿色带，含 ~10 段细碎路径）；③「钢笔」（原生 path，x≈105–124.5、y≈49–69，蓝色带，笔画约 1.3–3 单位）。

**光学对位量测**：各色带在 y=59 的横截面中点分别为 x=**30 / 80 / 120**；现状符号 bbox 中心为 x≈29.5 / 74.5 / 114.75，即绿色、蓝色符号相对所属色带横截面中点分别偏左 **5.5 / 5.25 单位**（= 色带高度 80 的 6.9% / 6.6%），与 spec SC-003 的 ≤5% 不符——这正是 spec Assumptions 中「光学对位不一致」的实证。

**身份不变量（每版候选与最终版 MUST 全部满足）**：

1. 三枚向右延展的箭头形色块，颜色顺序橙 → 绿 → 蓝，水平构图；
2. 至少一处白色辅助符号，表达语言/翻译、认知/大脑、书写/笔中的至少一种语义，且完整位于单一色带内；
3. 右下蓝色箭头尖角点缀存在（可重绘、可融合，不可删除）；
4. 六边形整体轮廓与扁平矢量语汇不变；画布宽高比相对现状（4:3）变化 ≤20%（放宽口径）、三色色相不变且明度/饱和度偏移 ≤20%（放宽口径）、无渐变；新旧并排判为同一标识。

**Decision**: 以上不变量即三版候选与新版设计的验收骨架；白符号数量按 spec 澄清取 1–3（三版候选均取 2），语义覆盖语言（文）与书写（笔）。

**Alternatives considered**: 把橙色菱形改为与其他两枚同构的 chevron 带——会改变左端的尖点轮廓与三色拼合关系，属"另一个标识"风险，否决；重新设计三色排列或方向——直接违反 FR-001，否决。

## R2: 几何现代化（FR-001 / FR-002 / SC-001）

**Decision**：

1. **保留既有几何骨架与三色比例**。外轮廓六边形顶点、两条分界折线、三色在 y=59 的 60 / 40 / 40 宽度全部沿用。比例并非任意值：设分界折线顶点为 `T`，其上顶点为 `T−30`（折线 Δx=30、Δy=40），且该上顶点必须落在顶边 x∈[30,110] 上，故 `T1 ≥ 60`、`T2 ≤ 140`——现有 60 / 40 / 40 是该约束下已验收的既有节奏。spec 澄清已把比例调整为授权杠杆：**候选 A/B 保持现状节奏**（「不大改」目标下最稳、辨识度连续），**色带重排作为候选 C 的探索杠杆移交 R10**（蓝色带加重、向右动势）。
2. **外轮廓圆角化**：把六边形轮廓定义为 6 个圆角（半径 **r=4**，凸圆弧相切，几何由路径坐标精确给出；`sweep-flag=1`），并用 `<clipPath>` 裁切三条色块。效果：外形四角与左右尖点统一圆润，而**内部分色边界保持锐利**；圆角只作用在外边缘，不会产生分色缝隙。
3. **叠绘顺序橙 → 绿 → 蓝**：三色路径本就精确拼合，按此顺序叠绘可让后一色覆盖前一色的共边抗锯齿，避免出现发丝状背景色接缝（原型放大核对无接缝）。
4. **右下尖角保留原三角形三个顶点**（位置/大小不变），三个顶点均作 **r=3** 圆角；其中底边两角的圆角落在蓝色主体内部、不影响可见轮廓，可见效果为尖端圆角。尖角仍从蓝色下边缘伸出、与主体融合，身份要素完整。
5. **画布不变**：logo 仍为 `viewBox="0 19 140 105"`（内在 140×105、4:3），favicon 仍为 `viewBox="-10 -21 160 160"`（内在 160×160）。圆角使内容 bbox 变为 x≈1–139、y≈19–119.8，对画布的覆盖率约 **98.5% × 96.0%**——无裁切、无异常留白（阈值 ≥90%，见契约），同时保持内在尺寸与宽高比与现状完全一致，顶栏渲染尺寸与布局零位移。
6. **不引入**任何渐变、阴影、描边、纹理、字体内文字或位图；色块 `fill` 为唯一着色手段。

**Rationale**: 在"不大改整体设计"的硬约束下，圆润外轮廓 + 锐利分色 + 圆角尖角是投入最小、观感提升最直接的现代化手段；保留整数网格与全部既有顶点坐标，使新旧叠图比对时几何偏差只在圆角处，身份可辨性最高。

**Alternatives considered**:

- 仅对四个 143° 内角圆角、保留左右尖点：更"箭头"、画布更贴合，但现代化观感弱于六角统一圆角，且与"更现代"目标有距离；原型比对后否决（作为备选记录）。
- 更大的圆角（r=6 或全圆角胶囊）：左右尖点被明显削圆（相切点距尖点约 4.5 单位），轮廓趋近"胶囊"，辨识度与"不大改"风险上升，否决。
- 内部分色折线也圆角：相邻色块需互相补偿圆角，易出现缝隙/重叠色阶，且小尺寸下会破坏三色边界清晰度，否决。
- 改变三色比例（如 70 / 40 / 30）：几何上可行（`T1 ≥ 60`、`T2 ≤ 140`），但会改变既有三色节奏与辨识度，收益低而风险高，否决；把橙色改为 chevron 带：会改变左端轮廓，否决。

## R3: 白色辅助符号系统与数量决策（FR-001 / FR-002 / FR-003 / SC-003）

**Decision（迭代 2 记录；迭代 3 由 R14 取代，见其开头说明）**: **保留 2 个**白色辅助符号——橙色带「文」（语言/翻译语义，锚点 `(30,59)`）、蓝色带「笔」（书写语义，锚点 `(120,59)`）；取消原「大脑电路」符号。spec 澄清（Q1）与 FR-001 明确允许 1–3 个、允许同语义合并/替换，本决策在其授权范围内。**三版候选均取 2 个符号且共用本节定义的形态与锚点规则**（A/B 用 18 单位框 / 2.7 笔画；C 按比例加重为 20 单位框 / 3.2 笔画、笔锚点随色带重排移至 `(117.5,59)`，见 R10）。

**依据（量测 + 原型比对）**：

- **小尺寸物理下限**：22px 高的顶栏中，18 单位光学框 = **3.8px**，2.7 单位笔画 = **0.57px**；64px 时分别 11.0px / 1.65px。任何"三个符号各占一个色带"的方案，在 22px 下都只能呈现为三团低对比白斑；其中大脑符号在原图中由 ~10 段 1–2 单位线构成（0.21–0.42px），必然先糊成不规则白团（正是 spec US2 要消灭的"糊块/脏边"）。
- **原型候选比对**（以同一 18 单位框、2.7 单位笔画光栅化到 25 / 64 / 110 / 192px 后目视）：文（4 笔）在 64px 清晰可读；钢笔轮廓（笔尖 + 笔身 + 笔缝）在 64px 可读；而"大脑轮廓"在 64px 读成「0/D」、「芯片」读成「花/齿轮」、「三节点电路」读成「Y」——均无法同时满足"64px 主形态可辨"与"25px 均匀点缀"。
- **对称与节奏**：文（x=30）与笔（x=120）关于标识水平中心 x=70 **完全对称**（±50 单位）；绿色带留白成为三色节奏的"呼吸位"，避免三团白斑拥挤。
- **语义覆盖**：语言/翻译（文）+ 书写/笔，覆盖 FR-001(b) 要求的至少一种语义；标识整体仍是"三色向右箭头 + 辅助符号"。

**统一符号系统（两个符号共用同一套语言）**：

| 参数 | 取值 | 说明 |
|------|------|------|
| 光学框 | 18×18 单位（墨迹外沿 ≤ ±8.8） | 两符号同尺寸；绿色带空置 |
| 笔画 | `stroke-width="2.7"`，`#ffffff` | 两符号完全一致，SC-003 笔画极差 **0%**（≤10%） |
| 端点/连接 | `stroke-linecap="round"`、`stroke-linejoin="round"` | 统一圆润端点，小尺寸下无尖锐碎屑 |
| 填充语言 | 无填充、纯描边（`fill="none"`） | 同一"线描"语汇；笔的笔缝/笔环为细节补充，25px 下并入主轮廓，不产生孤立碎线 |
| 锚点 | 文 `(30,59)`、笔 `(120,59)` | 均为所属色带在 y=59 横截面的中点；墨迹 bbox 中心偏差 ≤0.25 单位（≤0.3%，限值 5%） |
| 最小安全边距 | 文 ≥13.8 单位、笔 ≥7.1 单位 | 均 ≥ 色带高度 80 的 8%（6.4 单位），亦 ≥ 垂直带宽 32 的 20%；白色墨迹完整落在单一色带内（以真实墨迹外沿计算，不含空 bbox 角） |

**Rationale**: 把"三个各自为政的符号"收敛为"两个同构的符号 + 一处节制的留白"，是同时满足 25px 干净（US2）、64px 可辨（FR-003）与"更现代"（FR-002）的最短路径；这比保留三个符号再逐个瘦身更可控，也直接回应 spec 指出的"一个粗一个细、一个密一个散"。

**Alternatives considered**:

- 保留三个符号、全部重绘为统一系统：25px 下第三团白斑仍会与相邻色带边缘争夺对比度，且大脑/芯片/节点类候选在 64px 均不可读（原型证据），否决；如评审要求保留第三符号，回退方案见 R8。
- 只保留一个符号（如仅文）：绿色与蓝色带全空，标识的"辅助符号"分量过弱，且与"不大改"目标偏离，否决。
- 把笔旋转到与蓝色带同角度（53°）以换取更大尺寸：两符号朝向不一致、破坏统一性，且 25px 下旋转小图形更易糊，否决。
- 用实心填充图形提高小尺寸存在感：三个符号的光学重量差异（文 ~60 单位²、大脑实心 ~200 单位²）会直接违反"均匀"要求，否决。

**符号形态（目标坐标，契约固化）**：

- 文（原点在锚点）：上点 `M0 -7.2 V-5.9`；横 `M-6.8 -3.4 H6.8`；两撇捺 `M-5.8 0 L5.9 6.9`、`M5.8 0 L-5.9 6.9`。4 笔，语义"文/语言"。
- 笔（原点在锚点）：笔身闭合轮廓 `M-6.6 6.6 L-2.7 5.1 L6.4 -4 L4.2 -6.2 L-4.9 2.9 Z`；笔尖缝 `M-5.3 4.6 L-3.8 3.1`；笔环 `M2.1 -2.3 L4.3 -0.1`。语义"书写/笔"。
- 两符号的墨迹外沿（含 1.35 单位端点半径）均不超过 ±8.8 单位；坐标可作 ±0.5 单位微调以优化光学观感，但不得改变锚点与安全边距下限。

## R4: 色彩策略（FR-001 / SC-001）

**Decision**: **候选 A/B 三色逐字保留** `#f7941d`（橙）、`#28ae6c`（绿）、`#037ec2`（蓝），白色辅助符号 `#ffffff`，色偏 0%；**候选 C 使用统一微调杠杆**——三色同一方向做明度/饱和度微调（目标 +5–10%，如统一提亮或提饱和以获得"鲜活"观感），色相锁定、无渐变、无透明度、无叠色；spec 澄清已把偏移上限放宽至 **≤20%**（原 004 CHK021 口径 ≤10%），且放宽同样适用于最终合入版。C 的最终色值在实现阶段定型并记录于 `candidates/SELECTION.md`，按 HSL 逐色量测偏移 ≤20%。

**Rationale**: 色值是标识身份的一部分，现有三色在白色顶栏、浅色页脚与名栏浅色渐变上均已验证可辨（004）；A/B 逐字保留把色彩项风险降为零。放宽口径的价值在候选 C 兑现：给维护者一个"色彩也焕新"的真实选项，而非纸上杠杆；目标控制在 +5–10%（远低于 20% 硬上限）以保住 SC-006"同一标识"判定——同色相的轻度提亮/提饱和在并排下仍读作同一族色板。

**Alternatives considered**: A/B 也做色彩微调——候选间差异维度过多、评审信息量下降，且"利落/圆润"两版的价值恰在隔离"符号系统/圆角几何"两个单一变量，否决；C 用满 20% 偏移——并排色差过大会被 SC-006 评审者读作"另一个标识"，否决；引入渐变/阴影——直接违反 FR-001/FR-002 与 Constitution IV，否决。

## R5: favicon 同源简化（FR-004 / US2 / SC-002）

**Decision**: favicon **不在候选阶段逐版产出**（spec 澄清：选中后再派生）；选定版通过 SC-006 评审后，由其派生并**同一次变更**替换 `public/favicon.svg`：

- 沿用 `viewBox="-10 -21 160 160"` 方形画布与透明底（宽 140 内容在 160 方形中水平居中；高 80 的箭头主体在方形中垂直居中，上下各留 40 单位——**方形画布对宽幅标识必然产生上下留白，属 favicon 的规范性留白**，不计入"异常留白"）。
- 仅保留三条三色路径，并套用与选定候选**同一套圆角外轮廓与色值**（A：锐利轮廓原样；B：r=4；C：r=6 + 微调色值）→ 三色几何、色值、轮廓语汇完全同源。
- **不包含**白色辅助符号与右下尖角（沿用 004 既有简化策略：favicon 只保留"三色向右箭头主体"；尖角非 favicon 必需要素，且 16px 下会显著压缩三色可辨面积）。
- 无文字、无字体、无位图、无外部引用；16px 下要求橙/绿/蓝相互可区分、向右箭头轮廓可辨，深/浅标签栏背景均可辨（透明底，不依赖白色细节）。
- favicon 的验收仅按 SC-002 的 16px 口径执行；SC-006 不覆盖 favicon，无需单独评审（spec 2026-10-20 澄清）。

**Rationale**: 同源几何保证"favicon 与完整图标颜色与几何语汇同源"（FR-004）；沿用既有方形画布与既有简化策略，使 16px 可辨性风险最小、变更范围最小。

**Alternatives considered**: favicon 直接复用完整 logo（白色符号在 16px 下不可辨且会糊）——否决；favicon 也画尖角——16px 下压缩主体、可辨性下降，且与"同源简化"策略不符，否决；收紧 favicon 方形画布以放大主体——会改变 16px 下的既有观感且收益仅 1px 级，YAGNI 否决（保留为后续可选微调）。

## R6: 集成点与最小改动（FR-005 / FR-006 / FR-007 / FR-008）

**现状引用链（逐字核对）**：`src/data/site.json` 的 `logo: "/logo.svg"`、`favicon: "/favicon.svg"` → `Navbar.astro` 以 `withBase(site.logo)` 渲染 `<img class="brand-logo" alt="" width={32} height={32} />`，CSS `height: 1.2em; width: auto`；`BaseLayout.astro` 以 `withBase(site.favicon)` 渲染 `<link rel="icon" type="image/svg+xml">`；`content.config.ts` 的 `validateSiteBrand()` 在构建期校验两字段为站内绝对路径且文件存在于 `public/`。

**Decision**：

1. `public/logo.svg`、`public/favicon.svg` 原位替换（路径不变 → `site.json`、`content.config.ts`、`BaseLayout.astro` 零改动）。
2. `Navbar.astro` **仅**把 `img` 的 `width={32} height={32}` 改为 **`width={40} height={30}`**（140:105 = 4:3，与资源内在比例一致）：既修正"回退宽高比与实际资源不符"的既有隐患（CSS 加载前/加载失败时不致拉伸），也满足 FR-006"按原始宽高比展示"；渲染尺寸仍由 `height: 1.2em; width: auto` 决定，布局零变化。
3. 品牌区结构（左 logo + 右 "CIGMA"）、`alt=""`、回主页链接、`white-space: nowrap`/`flex: 0 0 auto`、不绑定灯箱/放大等行为**全部不变**。
4. **不新增**依赖、构建脚本、CI 步骤、CSS 类、页面或数据字段；`global.css`、`content.config.ts`、`BaseLayout.astro`、全部页面与数据文件零改动。

**Rationale**: 资产路径不变使本次成为"纯资产替换 + 一处比例修正"，改动面最小（Constitution V），并让 favicon/logo 继续受既有构建期存在性校验保护。

**Alternatives considered**: 重命名资产（如 `logo-v2.svg`）——需同步 `site.json` 与校验，且旧资产还需清理，收益为零，否决；把宽高比写进 CSS `aspect-ratio`——CSS 已有 `width:auto`，且新增属性无必要，否决；不动 `width/height`——回退比例与实际不符、且与 FR-006 的"原始宽高比"表述有出入，否决。

## R7: 验证方法（SC-001–SC-006 / FR-008 / FR-009）

**Decision**: 沿用 001–004 的验收工具链，不引入新框架：

0. **候选级验证（阶段一，FR-009）**：三版候选逐项过身份不变量清单（SC-001 口径，含放宽上限的逐色 HSL 量测；候选阶段的身份不变量核查由维护者在对比页评审时执行，实现期自查为其前置支撑）；浏览器打开 `candidates/comparison.html` 核对 4 行（现状/A/B/C）× 4 档（128 / 64 / 22 / 16px）渲染齐全、22px 列为白底顶栏模拟、16px 列为完整图标缩至 16px 的模拟渲染（不以 "favicon" 指代该档）；**候选阶段对 SC-002 / SC-003 仅作目视定性判断（以对比页三档渲染为据，不逐版量化验收），两者的量化验收仅针对选定版执行**（即本节第 2 / 3 步）；选定与 SC-006 评审结果记录于 `candidates/SELECTION.md`（流程见 R12）。
1. **机器门禁**：`npm run check`（astro check，0 error/warning/hint）+ `npm run build`（18 页静态构建）100% 通过；CI 的 `npx astro check` 不受影响。
2. **尺寸矩阵目视（选定版与最终资产，阶段二执行）**：用 `sharp`（Astro 图像管线间接提供，**不新增依赖**）把新旧 logo 分别光栅化到 16 / 22 / 64 / 128 / 256px、favicon 到 16 / 32px，新旧并排核对三色边界、白色点缀、尖角、无模糊/脏边/裁切；64px 以上逐个核对保留符号可辨；16px 核对三色可区分、箭头轮廓可辨；深色条带背景复核 favicon。
3. **SC-003 数值**：直接从 SVG 坐标量测——选定版两符号笔画宽度一致（A/B 均 2.7、C 均 3.2 → 极差 0%）；锚点与所属色带横截面中点偏差 ≤4 单位；真实墨迹到最近分色边界距离 ≥6.4 单位（= 80×8%，亦 ≥32×20%；C 按重排后的色带几何复核）。
4. **身份比对**：`git show HEAD:public/logo.svg` 取旧版，与选定版并排/叠图；逐条核对 SC-001 身份不变量清单（阶段二执行；阶段一的候选级比对在对比页内完成）。
5. **布局回归**：375 / 768 / 1024 / ≥1280px 四档 + 320px 下限 + 边界 575 / 767 / 1279px，覆盖 Home / News 列表与详情 / Team / Publications；核对品牌区不折断、不与导航重叠/截断、无横向滚动、logo 与文字等高、点击回主页、无放大/灯箱。
6. **构建期校验负向用例**：临时改名/删除 `public/logo.svg` 或改错 `site.json` 路径 → `npm run build` 报错中断并指明字段与路径 → 还原 → 构建恢复；确认 FR-008 的校验未被削弱。
7. **旧资产/旧引用检查**：`git status`/`git grep` 确认仅两份资产被替换、无旧图标文件或旧引用残留；`candidates/` 评审产物未进入 `public/` 或 `src/`；构建产物由 `npm run build` 重新生成。
8. **无障碍与缓存**：读屏可访问名仍由文字 "CIGMA" 提供（logo `alt=""`，装饰性）；favicon 缓存以强制刷新/新会话验收，不作为缺陷。
9. **范围外**：部署后线上渲染核对由 CI / 既有维护工作流承载（沿用 004 CHK037）。

**Rationale**: 本特性以视觉与几何一致性判定为主，自动快照的收益低于工具引入与维护成本；上述方法可复核 spec 的全部 SC 且零新增依赖。

**Alternatives considered**: 引入 Playwright 视觉快照——对 5 人课题组站点属过度工程（Constitution V），否决；引入 SVGO 等构建优化步骤——资产已 ≤2KB、无可优化收益，否决。

## R9: 宪法合规（数据 / 依赖 / 设计）

**Decision**: 变更分两段收敛——阶段一评审产物（3 候选 SVG + 对比页 + 选定记录）全部位于 `specs/005-modernize-logo-mark/candidates/`，不进入站点构建与交付物；阶段二仅限 2 份静态 SVG + `Navbar.astro` 一处宽高比属性。全程零新增依赖、零新增 JS、零数据字段、零构建链改动；资产为仓库内纯矢量、相对路径引用、无热链；保持扁平矢量，色板变化以 spec 放宽口径（色相锁定、L/S ≤20%）为限。

**Rationale**: 对应 Constitution I（以现有资产为唯一设计依据、微调值按口径量测记录、不臆造内容）、II（图标仍由 `site.json` 字段与既有组件引用，内容/展示分离；评审产物属特性文档）、III（站点构建产物与交付物零变化，`specs/` 不参与构建；构建期存在性校验保留，GitHub Pages 交付不变）、IV（无动效/装饰/新交互，对比页为零 JS 中性评审工具）、V（三候选与对比页为 FR-009 要求的最小工作流产物，候选间复用符号系统与格式规则控制成本）。逐条复核见 plan.md 的 Constitution Check 与 Post-design 复核。

## R10: 三版候选策略与探索跨度（FR-009 / FR-001 放宽口径）

**Decision**: 三版候选沿"现代化强度"单一维度展开，形成**保守 → 中度 → 大胆**的连续谱，让维护者的选定等价于一次强度决策；三版共用同一符号系统定义（R3）与格式规则，差异集中在可数的关键杠杆上。（保守/中度/大胆的跨度划分是**设计阶段的裁量决策，不构成 spec 需求**——spec 2026-10-20 澄清明确不定义三版之间的探索跨度；本表的划分方式是本计划的设计选择，迭代轮次重新生成候选时可另行裁量，但身份不变量与放宽口径仍为硬性门槛。）

| 杠杆 | 候选 A「利落」（保守） | 候选 B「圆润」（中度） | 候选 C「焕新」（大胆） |
|------|----------------------|----------------------|----------------------|
| 定位 | 仅符号系统化：检验"最小干预"能走多远 | 符号系统 + 圆润几何（R2–R5 定型设计） | 节奏 / 圆角 / 色彩 / 重量全面焕新 |
| 三色路径 | **逐字保留现状**（锐利轮廓、60/40/40） | 逐字保留现状 | 节奏重排：绿\|蓝分界折线顶点 `T2: 100 → 95`（y=59 宽度 60/35/45，橙色菱形逐字不动、蓝色带加重强化向右动势）；`T2 ∈ [90,100]` 内微调 |
| 外轮廓圆角 | 无（保持锐利六边形） | 六顶点 **r=4**（`clipPath`） | 六顶点 **r=6**（`r ∈ [5,7]`） |
| 右下尖角 | 逐字保留 | 三顶点 r=3 圆角 | 三顶点 r=4 圆角，位置保持、可 ≤5 单位微调与蓝色带下边缘更融合；不删除、不放大 |
| 色值 | 逐字 `#f7941d` / `#28ae6c` / `#037ec2`（偏移 0%） | 同 A（偏移 0%） | 三色统一 L/S 微调，目标 **+5–10%**（硬上限 ≤20%，色相锁定；最终 hex 记录于 SELECTION.md） |
| 白色符号 | 2 个：文 + 笔，18 单位框 / 2.7 笔画 | 同 A（R3 定型） | 2 个：文 + 笔，**20 单位框 / 3.2 笔画**（笔画 3.0–3.4），笔锚点随色带移至 `(117.5,59)` |
| 画布 | `0 19 140 105`（4:3，变化 0%） | 同 | 同（变化 0%） |
| 宽高比杠杆（≤20%） | 不使用 | 不使用 | **不使用**（刻意，见下） |

**画布宽高比三版均不动的理由**：±20% 宽高比杠杆虽已放开，但一旦使用将同时改变顶栏回退属性、品牌区天然宽度与 favicon 方形画布的适配，引入布局回归面；而现代化的收益主要来自符号系统、圆角、节奏与色彩，画布比例对这些无贡献。三版保持 140×105 使集成层（Navbar 回退 40×30、favicon 画布）完全恒定，`site-integration` 契约无需按选定版分支——这是用"杠杆不用"换"集成零风险"的显式取舍。

**受控对比设计**：A 与 B 仅差"圆角几何"一个变量（隔离圆角贡献）；B 与 C 的差值集中在节奏 / 色彩 / 重量三杠杆（探索放宽口径的增量收益）；三档尺寸并排（R11）使维护者在顶栏真实观感下做选定，而不是只看大图。

**Alternatives considered**:

- 三版分别探索三个正交方向（如一版改符号、一版改几何、一版改色彩）——单变量组合爆炸且每版现代化不完整，评审难以横向比较，否决；
- A 保留 3 个符号（仅统一线描）——R3 原型证据表明第三符号在 25px 下必然糊成白团（正是 US2 要消灭的缺陷），让一版"已知不合格"的候选浪费评审带宽，否决；
- C 改变画布宽高比（如 1.4:1）——收益仅 1–2% 的动势，代价是集成层分支与身份漂移，否决（见上）；
- C 合并为单符号——R3 已论证单符号使"辅助符号"分量过弱、偏离"不大改"，否决。

## R11: 对比页实现方案（FR-009 / US1 AS6）

**Decision**: `specs/005-modernize-logo-mark/candidates/comparison.html`，单一自包含 HTML：

1. **自包含与零依赖**：4 个图标（现状 + A + B + C）以内联 `<defs><g id="…">` 各定义一次、以 `<use href="#…">` 在各尺寸列引用；零 JS、零外部请求、系统字体、内联样式；现状图标以创建对比页时的 `public/logo.svg` 内容为内联快照（不运行时引用 `public/` 路径，保证页面可独立打开与存档）。
2. **结构**：标题 + 评审说明（判定口径 = SC-001 身份不变量清单；三档尺寸关注点：≥64px 保留符号逐个可辨 / 22px 三色边界与白色点缀干净 / 16px 三色可辨与向右箭头轮廓可辨）+ 四行（现状 / A / B / C）× 四档渲染（**128px、64px、22px 高、16px 高**；满足 FR-009"≥64px / 约 22px / 16px 三档"，多给一档大图便于形态比对）。
3. **22px 列**以白色顶栏模拟条（白底 + 底部细边框）呈现，贴近顶栏真实观感；**16px 列**为完整图标缩至 16px 高的模拟渲染，页内注明"favicon 将按选定版派生，此列为等比模拟，非 favicon 资产"。
4. **每行标注**：候选代号与名称、杠杆摘要、口径使用（宽高比 Δ / 色偏 Δ / 符号数 / 圆角 / 节奏），使评审可对照参数做判断。
5. **版式**：中性浅色、网格对齐、不加与评审无关的装饰（Constitution IV）；页面仅在浏览器本地打开，不部署、不构建。

**Rationale**: `<defs>` + `<use>` 使 4 图标 × 4 档 = 16 处渲染只维护 4 份几何定义，页面小且无复制漂移；自包含使对比页可脱离仓库环境存档与传阅（评审者无需启动站点）。

**Alternatives considered**: 为每档尺寸生成 PNG 贴图——引入光栅化脚本与产物文件、无法矢量无损缩放，否决；把对比页做成 Astro 页面——会进入站点构建与交付物，直接违反 FR-009"不进入站点交付物"，否决；引用 `public/` 相对路径加载现状图标——页面无法独立存档且隐式耦合站点目录，否决。

## R12: 选定、外部评审与 favicon 派生工作流（FR-009 / SC-006 / FR-004）

**Decision**: 五步工作流，失败路径闭环：

1. **候选自查**（实现阶段）：三版逐项过 R1 身份不变量清单 + R10 参数界限（含 C 的逐色 HSL 偏移量测）；对比页四档渲染正常。
2. **维护者选定**：打开 `comparison.html` 并排评审 → 从三版中选定一版 → 记录于 `candidates/SELECTION.md`（候选 id、选定人、日期、理由摘要、选定版关键参数与色值快照）。选定依据：身份不变量为硬性门槛，其外的取舍标准（现代感、小尺寸表现等）不作定义，明确交由维护者裁量（spec 2026-10-20）；候选评审对 SC-002 / SC-003 仅作目视定性判断（以对比页三档渲染为据，见 R7 第 0 步）。
3. **SC-006 外部评审**（仅针对选定版、合入前）：评审者为**未参与设计的实验室老师**（≥1 人，由维护者邀请；维护者本人与候选制作方均属"参与设计"，不得担任评审者）；评审者在无提示的并排对照下对"现状 vs 选定版"作出**两项判定**——"同一标识的现代化版本"（而非"另一个标识"）与"更现代、未大改整体设计"；两项判定由同一评审者作出，均须通过；结论记录于 `SELECTION.md`。
4. **通过 → 阶段二**：由选定候选派生 favicon（R5：同三色路径 + 同圆角轮廓 + 同色值、无符号无尖角、`-10 -21 160 160` 透明底）→ `public/logo.svg` + `public/favicon.svg` 同一次变更替换 + `Navbar.astro` 回退属性 40×30 → 门禁 / 尺寸矩阵 / 视口回归 / 负向用例（R7）；favicon 验收仅按 SC-002 的 16px 口径执行，SC-006 不覆盖 favicon、无需单独评审。
5. **失败路径 → 迭代候选**：维护者无法从三版中选定任何候选，或选定版未通过 SC-006 → **重新生成三版候选**（迭代后的三版仍 MUST 满足身份不变量与放宽口径）→ 重新进入对比评审与选定流程（重跑第 2 步）→ 仅对新选定版重跑第 3 步（不逐版盲评）；外部评审者不可得、评审者与维护者意见不一致、迭代轮数上限等评审流程异常不定义为需求，由维护者届时裁量（spec 2026-10-20）。

**时序约束**：favicon MUST NOT 在候选阶段逐版产出（FR-009）；logo 与 favicon MUST 在阶段二同一次变更中落位（FR-004）；SC-006 时点 = 维护者选定之后、代码合入之前。

**Rationale**: 把"设计决策权"交给维护者、"新旧判定权"交给未参与设计的实验室老师（SC-006：同一评审者作出"同一标识的现代化版本"与"更现代、未大改"两项判定），职责分离使"更现代化"与"不大改"两个主观目标各有兜底；SELECTION.md 作为单一事实源衔接两阶段（阶段二的资产核对、quickstart 的色值/参数检查都以它为准）。

**Alternatives considered**: 三版全部做 SC-006 盲评再选——spec 澄清 Q7 已明确仅评选定版，且逐版盲评成本高、信息重复，否决；选定记录口头传达不留档——阶段二的验收参数（尤其 C 的色值）无处核对，否决；选定后由对比页直接充当交付物——违反"不进入站点交付物"，否决。

## R13: 迭代 2——维护者反馈后的重新设计（FR-001 / FR-009 / SC-001）

**背景**：首轮三版（A 利落 53.1°/60-40-40/锐利、B 圆润 r=4、C 焕新 60/35/45 + 色彩 +5–10%）在对比页评审后未被维护者选定；维护者要求"重新设计，还可以做出更多的改变"。按 FR-009 的失败路径（T011）回到 T003 重新锁定共用参数并重生成三版候选——不是微调，而是把 spec 澄清 Q1 授权的放宽口径（色块比例、角度、圆角可调；白色符号可同义重绘/替换/合并）连同上限内的明度微调一起用满。

**Decision（本轮锁定的参数）**：

| 杠杆 | A「疾进」 | B「锋锐」 | C「极构」 |
|------|-----------|-----------|-----------|
| 分界折线水平 run `w` / 与水平夹角 | 27 / **55.98°** | 23 / **60.09°** | 21 / **62.3°** |
| 色带宽度（y=59）橙/绿/蓝 | **54 / 36 / 50** | **46 / 34 / 60** | **42 / 30 / 68** |
| 外轮廓圆角（真切线） | 六顶点 r=5 | 六顶点 r=6 | 左端 r=9、右端 r=3、其余 r=5 |
| 右下尖角 | 三顶点 r=2.5，随蓝带移位 | 三顶点 r=3，随蓝带移位 | 三顶点 r=3，随蓝带移位 |
| 色彩（色相锁定、≤20%） | 逐字 0% | **+10% L**（`#f8a138` / `#2cbf77` / `#038bd5`） | **−12% L**（`#eb8408` / `#23995f` / `#036fab`） |
| 白色符号 | 22 框 / 3.2 笔画，文 @27 / 笔 @115 | 22 框 / 3.2 笔画，文 @23 / 笔 @110 | 22 框 / 3.4 笔画，文 @21 / 笔 @106 |
| 画布 | `0 19 140 105`（4:3，变化 0%） | 同左 | 同左 |

**几何推导**：六边形顶点 (0,59)(`w`,19)(140−`w`,19)(140,59)(140−`w`,99)(`w`,99)；橙|绿折线自 `(w,19)` 经 `(2w,59)` 到 `(w,99)`，绿|蓝折线自 `(w+G,19)` 经 `(2w+G,59)` 到 `(w+G,99)`（`G` = 绿带宽度）。折线越陡（`w` 越小），左右尖端的内角越大（由 106° 增至 124.6°），而上下四顶点越尖（68° → 55.4°）——这正是"更利落的箭头"的来源：左右端变成圆润的尾部，锐度转移到上下沿的切角。

**为什么改用真切线圆角**：首轮 B/C 的 `clipPath` 沿用了"切点距尖端 0.75r / 距其它顶点 0.5r"的近似构造，圆弧与直边并不相切，放大查看会留下极轻的折点。迭代 2 改为严格相切（`t = r / tan(θ/2)`），并用**覆盖率 ≥90%** 反推半径上限：在 55–62° 的陡角下，r=9–12 的尖端会把内容宽度压到 90% 以下，故 A/B 取 5/6、C 仅在钝角左端取 9（该端内角 124.6°，切退仅 1.17 单位），右端保持 r=3 的箭头锐度。

**符号系统重做**：光学框 18 → **22 单位**（C 3.4 笔画）；文的上点由"与横画相接"改为留 0.6 单位间隙（64px 以上能读出「点 + 横 + 撇捺」四笔）；笔改为关于锚点对称的五点笔尖（墨迹 bbox 中心偏差 0.01）；两符号锚点仍严格落在所属色带 y=59 横截面中点。22px 下仍是两个干净的白点，但因笔画更重、框更大，顶栏观感更实。

**实测（几何 + 色彩，均为设计文件坐标）**：到分色边界最小距离 A 文 10.7 / 笔 9.7、B 8.5 / 15.0、C 7.2 / 19.0（≥6.4）；bbox 中心偏差 文 0.20 / 笔 0.01（≤0.25）；覆盖率 A 98.5%×96.6%、B 98.7%×96.1%、C 98.9%×96.1%（≥90%）；逐色 ΔL 0% / +9.6~10.1% / −11.7~−12.1%，ΔS ≤0.4%，ΔH ≤0.22°（≤20%、色相锁定）；三文件 1274 / 1273 / 1265 B（≤2KB）。

**Rationale**：首轮的问题不是某个参数不到位，而是"几乎不动"——分界角度、节奏、圆角与符号重量都停在现状附近，视觉上读作"微调"。本轮让三版在同一个身份骨架（三色向右 chevron + 两个白色符号 + 右下尖角 + 4:3）上沿"改动幅度"展开：A 只动几何、B 几何 + 提亮、C 把节奏 / 非对称圆角 / 加深色板 / 符号重量全部拉开。四档尺寸并排让维护者直接在顶栏真实观感下判断"够不够新"与"是不是同一标识"。

**Alternatives considered**：

- 继续在 53° / 60-40-40 上做小步微调——正是首轮被否的原因，否决。
- 用 ±20% 画布宽高比杠杆（如 140×96）——会同时改变顶栏回退比例、favicon 方形画布适配与集成层分支，收益低于角度 / 节奏杠杆，本轮仍不用（保留为后续可选）。
- 把三色改为更大的色相偏移（如偏青 / 偏红）——违反 FR-001 色相不变，否决。
- 保留 3 个白色符号——R3 的原型证据仍成立（第三符号在 22px 必糊），否决。
- 一次性给出六版候选——FR-009 明确"三版候选"，迭代应替换而非堆叠，否决。

**适用范围**：R13 的参数是迭代 2 三版候选与后续选定版的事实源；R1 / R2（六边形骨架、扁平语汇）、R5（favicon 同源简化）、R6 / R7（集成与验证方法）、R8 / R9（风险与宪法）继续有效。候选阶段仍只做目视定性判断，SC-002 / SC-003 的量化验收仅针对选定版。


## R14: 迭代 3——恢复「文 / 脑 / 笔」三符号（FR-001 / FR-002 / FR-009 / SC-003）

**背景**：迭代 2 的三版都只保留 2 个白色符号（文 + 笔），把原图标中的「大脑电路」符号去掉了。维护者在对比评审中直接追问："为什么所有的设计都在去掉大脑电路的图标？"——在课题组（NLP = 语言 + 认知）的语义里，认知/大脑不是可裁剪的第三元，只留文 + 笔会把标识读成"翻译 / 写作工具"；三版一致地删掉它，等于收敛到一枚通用语言图标，反而降低辨识度。维护者选定思路：**文 / 脑 / 笔 各占一带**。

**决策（本轮参数）**：

| 杠杆 | A「疾进」 | B「锋锐」 | C「极构」 |
|------|-----------|-----------|-----------|
| 分界折线 `w` / 夹角 | 27 / 55.98° | 23 / 60.09° | 21 / 62.3° |
| 色带宽度（y=59）橙/绿/蓝 | **54 / 42 / 44** | **46 / 42 / 52** | **42 / 42 / 56** |
| 外轮廓圆角 | r=5 | r=6 | 左 9 / 右 3 / 其余 5 |
| 白色符号（各占一带） | 文 @27 / 脑 @75 / 笔 @118 | 23 / 67 / 114 | 21 / 63 / 112 |
| 符号笔画 | 2.8 | 2.8 | 3.0 |
| 光学尺寸（墨迹） | 文 17.2×18.3 · 脑 20.6×15.0 · 笔 18.7×18.4 | 同左 | 同左（+0.2） |
| 色彩 | 逐字 0% | +10% L | −12% L |
| 画布 | 140×105（4:3，0%） | 同左 | 同左 |

**为什么必须重绘而不是搬回 004 的大脑**：004 的大脑电路由 74 条路径命令、约 1.25–1.87 单位的细线构成；直接搬回会同时破坏两件事——(1) SC-003 的"主体笔画宽度极差 ≤10%"（1.87 vs 2.8 ≈ 33%）；(2) 22px 下细线碎成互不相连的白点，比现状更脏（spec 已把"绿色符号糊成白团"列为要修的问题）。因此按 Q1 的"同语义重绘"处理：**单线脑形 + 中央裂**，2.8 圆头笔画，深 V 形中央裂（从顶部凹入至 y≈−3.8）承担"两半球"的读法，底部保留 1.0 单位小凹；裂的末端与底沿留 1.0 单位间隙，64px 以上仍可读出"两半球 + 裂"，22px 下收成一个均匀白点。

**为什么绿带统一 42**：一个白符号"占一带"时，中带的可用宽度受 chevron 斜率挤压——在 y 偏离 59 达 8–10 单位处，带的横截面比中线窄 `2×(w/40)×Δy`（A 最多约 6.8 单位）。旧迭代的 36/34/30 绿带放不下 20.6 宽的脑符号（切角处安全边距 <6.4）；把绿带统一到 42 后，脑符号到橙|绿、绿|蓝两条折线的最小距离为 A 7.09 / B 7.84 / C 8.10（≥6.4），且三版的中带宽度一致，脑符号无需按候选改形。

**颜色与比例仍按候选分化**：绿带一致 → 橙/蓝带承担节奏差异：A 橙带最宽（54）、推进起点最平缓；B 近均衡偏蓝（46/52）；C 蓝带最重（42/56）+ 非对称圆角 + 加深 12%。这样三版在"三符号 + 42 中带"的新约束下仍拉开 A→B→C 的跨度，而不是退化成三枚几乎相同的图标。

**实测（设计文件坐标）**：墨迹到分色边界最小距离 A 11.73 / 7.09 / 7.38、B 9.52 / 7.84 / 11.70、C 8.21 / 8.10 / 13.88（≥6.4）；bbox 中心偏差 文 y0.18 / 脑 0.00 / 笔 0.00（≤0.25）；笔画极差 0%；覆盖率 A 98.6%×96.7%、B 98.7%×96.1%、C 99.0%×96.1%；逐色 ΔL 0% / +9.8~10.2% / −11.7~−12.1%，ΔS ≤0.4%，ΔH ≤0.22°；三文件 1544 / 1543 / 1535 B（≤2KB）。

**Rationale**：身份不变量只要求"至少一处"辅助符号，因此删掉大脑在形式上合规——这正是 checklist 抓不到的问题（FR-001 的口径漏洞）。本轮的修正不是再加一条检查项，而是把语义完整性放回设计约束：三符号各占一带、同一套笔画语言、统一的 y=59 锚点，既恢复认知语义，也让三带在视觉上等权。

**Alternatives considered**：

- 只保留脑 + 笔（去掉文）——维护者选定的是三符号各占一带，且语言语义同样不可缺，否决。
- 直接搬回 004 大脑电路再放大——违反 SC-003 笔画极差、22px 更脏，否决。
- 把脑放进最宽的蓝带、笔放绿带——中带 42 仍放得下笔，但会打乱"橙=语言 / 绿=认知 / 蓝=书写"的现状对应，且 22px 下绿带符号更小，否决。
- 为容纳脑符号把三版绿带都拉到 48+——中带过宽会吃掉 A 的"橙带主导"与 C 的"蓝带主导"，跨度收窄，否决。
- 保持 2 符号、仅把"文"换成"脑"——语义仍缺一元，且维护者已明确三符号，否决。

**适用范围**：R14 是迭代 3 三版候选与后续选定版的事实源；R13 的角度 / 圆角 / 色彩参数、R1 / R2 的骨架与扁平语汇、R5 的 favicon 同源简化、R6 / R7 的集成与验证、R8 / R9 的风险与宪法继续有效。候选阶段仍只做目视定性判断，SC-002 / SC-003 的量化验收仅针对选定版。
