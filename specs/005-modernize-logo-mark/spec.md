# Feature Specification: 课题组图标现代化（Logo Mark Modernization）

**Feature Branch**: `005-modernize-logo-mark`

**Created**: 2026-10-17

**Status**: Draft

**Input**: User description: "修改课题组图标，让他更加现代化。但不大改整体的设计。"

## Clarifications

### Session 2026-10-17

- Q: 三个白色辅助符号（文A / 大脑电路 / 钢笔）的改动边界？ → A: 允许更大幅度的改造——色块比例、角度、圆角可调整，三个白色辅助符号可同语义重绘、替换或合并（数量可少于 3）；但整体 MUST 仍呈现为「三色（橙→绿→蓝）向右箭头 + 辅助符号」的同一标识，不得变成另一个标识。
- Q: 顶栏约 25px 下的呈现策略？ → A: 单一完整图标 + 小尺寸优化——顶栏继续使用完整标识，不新增小尺寸专用资产；验收以「三色边界清晰、白色点缀均匀干净」为准，不强制约 25px 下逐个符号可辨；64px 以上保留的符号可逐个辨认。
- 说明：右下蓝色箭头尖角点缀按身份要素保留（可重绘、可与主体更融合，不删除）；三色色相与橙→绿→蓝顺序、向右方向为不可变项。
- Q: 三个候选版本的探索跨度如何设定？ → A: 三版候选均须符合身份不变量标准；数值类软性约束可适当放宽，且放宽同样适用于最终合入版（不只是候选阶段）。
- Q: 放宽后的数值上限？ → A: 翻倍——整体宽高比相对现状变化 ≤20%，三色明度/饱和度偏移 ≤20%（色相不变、不引入渐变仍为硬性约束）。
- Q: 候选版本的评审载体？ → A: 并排对比页——单一 HTML 对比页内含现有图标与三版候选并排，每版同时展示 ≥64px、顶栏实际尺寸（约 25px）、16px（标签页尺寸）三档渲染；对比页为评审用临时产物，不进入站点。
- Q: favicon 是否随候选同步产出？ → A: 选中后再派生——对比页 16px 一行展示完整图标缩至 16px 的模拟渲染；favicon 在选定后按 FR-004 从选定版派生，候选阶段不逐版产出。
- Q: 用户选定后 SC-006 外部评审的安排？ → A: 选定后做——维护者从三版中选定后，由未参与设计的评审者对选定版做新旧并排判定（SC-006 现有口径），通过后合入；评审仅针对选定版，不逐版盲评。

### Session 2026-10-20

- Q: 三版候选之间的探索跨度（保守/中度/大胆的差异化）是否定义为需求？ → A: 不定义为需求——有意留给设计阶段裁量。
- Q: 维护者无法选定任何候选，或选定版未通过 SC-006 时的恢复路径？ → A: 迭代候选——重新生成三版候选，并重新进入对比评审与选定流程。
- Q: 维护者选定候选的评判依据？ → A: 身份不变量为硬性门槛，其外的取舍标准（现代感、小尺寸表现等）明确交由维护者裁量，不在 spec 中定义。
- Q: 候选评审阶段是否同时适用 SC-002 / SC-003？ → A: 候选阶段仅经对比页三档渲染做目视定性判断，不逐版量化验收；SC-002 / SC-003 的量化验收仅针对选定版执行。
- Q: SC-006 评审者由谁担任、资格边界与通过规则？ → A: 评审者为实验室老师（由维护者邀请，未参与设计）；维护者本人与候选制作方均属"参与设计"，不得担任评审者；"同一标识的现代化版本"与"更现代、未大改整体设计"两项判定由同一评审者作出，均须通过。
- Q: "favicon" 一词的双义使用如何处理？ → A: 统一措辞——"favicon" 统一指选定后按 FR-004 派生的标签页图标资产；候选对比页的 16px 档统一称"完整图标缩至 16px 的模拟渲染"，不以 favicon 指代该尺寸档。
- Q: 评审流程的异常场景（外部评审者不可得、评审者与维护者意见不一致、迭代轮数上限）？ → A: 不定义相关内容——不作为需求，由维护者届时裁量。
- Q: 选定后派生 favicon 的验收安排？ → A: 仅按 SC-002 的 16px 口径验收；SC-006 不覆盖 favicon，无需单独评审。
- Q: 顶栏图标实际渲染高度的口径？ → A: 勘误修正——顶栏实际高度为约 22px（`1.2em` × `1.15rem` × 16px 根字号；rem 相对 html 根元素解析，`global.css` 仅设 body 18px，此前「约 25px」系把 rem 误按 body 18px 计算所致）；本特性内顶栏尺寸口径统一修正为约 22px（FR-003 / FR-009 / SC-002 / US2 及对比页模拟档、光栅矩阵与验收预期同步修正；2026-10-17 会话记录中的「约 25px」保留为历史原文）。
- Q: 图标在站点内的实际渲染背景口径？ → A: 勘误修正——完整图标在站点内仅渲染于白色顶栏（`Navbar.astro` 品牌区），favicon 渲染于浏览器标签页（深/浅背景）；「浅色底栏、名栏浅色渐变」系沿用 004 资产契约的资产级可辨性口径（[004 contracts/site-branding.md](../004-homepage-branding-refresh/contracts/site-branding.md)；research.md R4 引用保留），并非图标的实际渲染位置——US1-AS4、Assumptions 与 logo-mark 契约渲染验收矩阵的相关表述已收敛为实际消费场景。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同一个标识，更现代的图形 (Priority: P1)

课题组维护者以现有图标为基础，同时产出三版候选标识（均满足身份不变量与放宽口径），经并排对比页评审后由维护者选定一版作为新版课题组标识：访客仍能一眼认出这是同一个课题组——橙、绿、蓝三枚向右延展的箭头形（chevron）色块、至少一处白色辅助符号（语言/翻译、认知/大脑、书写/笔中的语义）与右下的蓝色箭头尖角点缀都还在——但新版可以更大幅度地焕新：色块的比例、角度、圆角，以及辅助符号的形态都可以重新推敲（符号可同语义重绘、替换或合并），使整体更干净、更统一、更像今天的设计；不再有在常用尺寸下看不清的碎线，符号之间也不再"一个粗一个细、一个密一个散"。

**Why this priority**: 图标是课题组最基础的身份资产，顶栏与浏览器标签页都在消费它；只要图标本身成立，本特性就能独立评审与交付，小尺寸可辨（US2）与全站落地（US3）都以它为前提。

**Independent Test**: 将新版图标与现有图标（大尺寸）并排比对，按"身份不变量清单 + 并排目视"判定是否为同一标识的现代化版本；无需改动页面即可独立评审。

**Acceptance Scenarios**:

1. **Given** 现有图标与新版图标并排（大尺寸），**When** 对照查看，**Then** 身份不变量均在——三枚向右延展的橙→绿→蓝色块（顺序与方向不变）、至少一处表达语言/认知/书写语义的白色辅助符号、右下蓝色箭头尖角点缀——整体轮廓可辨认为同一标识。
2. **Given** 白色辅助符号经过重绘、替换或合并，**When** 查看新版图标，**Then** 辅助符号仍能读出语言/翻译、认知/大脑、书写/笔中的至少一种语义，数量为 1–3 个且不互相堆叠竞争。
3. **Given** 新版图标，**When** 检查其构成，**Then** 未引入无关图形、文字或装饰，未引入渐变、阴影、发光、3D、纹理、动效或描边滥用（保持扁平矢量）。
4. **Given** 新版图标，**When** 置于白色顶栏（图标的实际站点渲染背景）上，**Then** 图形清晰可辨，白色符号完整落在色带内、未越界到浅色或透明区域。
5. **Given** 未参与设计的评审者，**When** 并排查看新旧图标，**Then** 判定新版是"同一标识的现代化版本"，而不是"另一个标识"。
6. **Given** 三版候选并排对比页，**When** 评审，**Then** 页内含现有图标与三版候选，每版展示 ≥64px / 约 22px（顶栏实际高度）/ 16px（完整图标缩至 16px 的模拟渲染）三档尺寸渲染，三版均通过身份不变量清单核查；维护者从三版中选定一版后方进入全站替换。

### User Story 2 - 小尺寸下依然干净利落 (Priority: P2)

访客在任意页面的顶栏（图标实际渲染高度约 22px）与浏览器标签页（约 16px 的 favicon）看到图标时，整体观感干净、有意图：顶栏里三色边界清晰，白色符号是均匀、经过设计的点缀，而不是糊成不规则白斑或带脏边；标签页里橙/绿/蓝三色区域可相互区分、向右延展的箭头轮廓可辨。缩放到较大尺寸（如 64px 以上）时，保留的每个白色辅助符号仍能逐个辨认。

**Why this priority**: 顶栏与标签页是访客接触图标最频繁、尺寸最小的两个场景；现有图标在这两个尺寸下细节损失严重（绿色符号糊成白团、笔形符号几乎消失），若不解决，"更现代"在实际使用中不可感知。

**Independent Test**: 按顶栏实际尺寸（约 22px 高）、16px 标签页尺寸与 64px 以上大尺寸分别渲染新版图标，目视确认干净度、三色可辨性与符号可辨性；可与旧版同尺寸渲染并排对照。

**Acceptance Scenarios**:

1. **Given** 新版图标按顶栏实际尺寸（约 22px 高）渲染，**When** 查看，**Then** 三色边界清晰，白色符号呈现为均匀、有意的点缀，没有糊块、脏边或锯齿感。
2. **Given** 新版 favicon 按 16px 渲染，**When** 在浏览器标签页查看，**Then** 橙/绿/蓝三色区域可相互区分，向右延展的箭头轮廓可辨。
3. **Given** 新版图标放大到 64px 以上，**When** 查看，**Then** 保留的每个白色辅助符号的主形态均可逐个辨认。
4. **Given** 新版 favicon 与新版完整图标，**When** 并排查看，**Then** 二者颜色与几何语汇同源，favicon 未塞入小尺寸下不可辨的细节。
5. **Given** 高像素密度屏幕，**When** 查看图标，**Then** 边缘清晰，无模糊、裁切或变形。
6. **Given** 透明底的 favicon 置于深色或浅色标签栏背景，**When** 查看，**Then** 三色仍可区分（不依赖白色细节）。

### User Story 3 - 全站一致替换，既有版式不被打扰 (Priority: P3)

访客浏览任意页面（主页、News 及其详情、Team、Publications）时，顶栏与浏览器标签页都换成新图标，旧图标不再出现；顶栏品牌区仍是"左 logo + 右文字 CIGMA"，logo 与文字等高、点击回到主页、不被放大，页面其余排版与本次改版前一致。

**Why this priority**: 图标只有真正落到全站才产生价值；但它依赖前两项产出，且改动面小、可独立验收，故优先级最后。

**Independent Test**: 逐一打开全部页面，核对顶栏与标签页图标、品牌区行为与改版前一致；并在四档视口与 320px 下限检查布局无破损。

**Acceptance Scenarios**:

1. **Given** 任意页面，**When** 页面加载完成，**Then** 顶栏显示新图标、标签页显示新 favicon，不再引用或显示旧图标。
2. **Given** 顶栏品牌区，**When** 与改版前对比，**Then** 结构（左 logo + 右 CIGMA）、logo 与文字的等高关系、点击返回主页的行为、logo 为装饰性图形（不被点击放大/灯箱）均保持不变。
3. **Given** 375px / 768px / 1024px / ≥1280px 视口与 320px 最窄下限，**When** 查看顶栏与页面，**Then** 品牌区不折断、不与导航项重叠/截断、页面无横向滚动，既有布局无破损。
4. **Given** 仓库既有的检查与构建流程，**When** 执行，**Then** 全部通过；资源缺失时既有构建期校验仍会报错中断；未新增依赖。
5. **Given** 读屏软件，**When** 访问品牌区，**Then** 可访问名仍由文字 "CIGMA" 提供，logo 仍为装饰性图形（与现状一致）。

### Edge Cases

- **白色符号越界**：若重绘、替换或合并后符号超出彩色色带，白色图形落到透明或浅色背景上将不可见——新版 MUST 确保每个白色辅助符号完整位于所属色带内并保留安全边距。
- **符号合并/替换后语义丢失**：合并或替换不得使辅助符号退化为无法识别的白色色块；MUST 仍能读出语言/认知/书写中的至少一种语义，且辅助符号总数 MUST 为 1–3 个，不得堆叠多个互相竞争的新符号。
- **小尺寸下的细小笔画**：圆角化、统一笔画或重新设计轮廓后，细线在约 16–22px 渲染下可能融合成块——须通过简化细节、调整笔画粗细或留白避免，而不是保留不可辨的装饰性碎线。
- **比例/圆角调整过度**：色块比例、角度或圆角调整后，整体轮廓若明显偏离原标识，将被判为"另一个标识"——宽高比须保持在允许范围内，并 MUST 通过新旧并排比对确认身份不变。
- **浏览器缓存旧 favicon**：替换后浏览器可能短暂显示旧标签页图标，属于缓存行为而非交付缺陷；以强制刷新或新会话验收，仓库内不得残留旧图标资产或其引用。
- **深色标签栏/收藏夹**：favicon 为透明底，三色在深、浅两种标签栏背景上均需可辨；不要求白色细节在其中可见。
- **读屏与图片加载失败**：logo 为装饰性图形（空替代文本），品牌区可访问名由文字 "CIGMA" 提供（沿用现状，不新增要求）。
- **缺失或路径错误的资源**：既有构建期校验会报错并中断构建（本次不改变该行为）。
- **评审流程异常**：外部评审者不可得、评审者与维护者意见不一致、候选迭代轮数上限等评审流程异常，本轮不定义处理规则，由维护者届时裁量。
- **范围外场景**：深色模式、打印、灰度/单色、极小尺寸（小于 16px）、动画或视频中的图标、分享卡片/头像/PWA/触屏图标等新使用场景，本轮均不作要求。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 新版图标 MUST 保留以下身份不变量：(a) 三枚向右延展的箭头形色块，颜色顺序橙 → 绿 → 蓝、方向向右，整体为横向构图；(b) 至少一处白色辅助符号，表达语言/翻译、认知/大脑、书写/笔中的至少一种语义，并完整位于单一彩色色带内；(c) 右下蓝色箭头尖角点缀（可重绘、可与主体更融合，MUST NOT 删除）；(d) 整体轮廓在新旧并排比对下可辨认为同一标识。新版 MAY 调整色块的比例、角度与圆角，MAY 对白色辅助符号做同语义重绘、替换或合并（辅助符号总数 MUST 为 1–3 个）；MUST NOT 改变三色的顺序与向右方向，MUST NOT 新增无关图形、文字或装饰，MUST NOT 改变整体意象；整体宽高比 MUST 与现状基本一致（允许 ±20% 调整）；三色色相 MUST 保持不变，明度/饱和度偏移 MUST ≤20%，且 MUST NOT 引入渐变。
- **FR-002**: 新版图标 MUST 通过统一的视觉语言体现"更现代"：保留的白色辅助符号 MUST 采用同一套笔画/填充、端点与圆角处理、疏密程度（并排不得出现"一个粗一个细、一个密一个散"的失衡）；每个符号 MUST 在其所属色带内视觉居中，与色带边缘保持均匀的安全边距；细节 MUST 做减法——在顶栏显示尺寸下不可辨的碎线不应保留；MUST 保持扁平矢量（无渐变、阴影、发光、3D、纹理、动效或描边滥用），MUST NOT 增加装饰性元素（Constitution IV）。"更现代"的判定沿用半客观口径：身份不变量清单 + 新旧并排目视比对（SC-001 / SC-003 / SC-006）。
- **FR-003**: 新版图标 MUST 在顶栏实际显示尺寸（约 22px 高）下保持干净：三色边界清晰，白色符号呈现为均匀、有意的点缀，无糊块、脏边、锯齿或裁切；MUST 在约 16px 的标签页尺寸下保持三色可区分、向右箭头轮廓可辨；MUST 在 64px 以上尺寸下使保留的每个白色辅助符号可逐个辨认；白色辅助符号 MUST 完整落在所属色带内且保留安全边距，MUST NOT 越界到透明或浅色背景，MUST NOT 跨越色带边界；图形 MUST 在高像素密度屏幕上清晰，无模糊、变形或依赖位图的失真。顶栏与较大尺寸 MUST 由同一份完整图标资产覆盖，MUST NOT 新增顶栏专用的小尺寸简化资产（favicon 的同源简化不属此列）。
- **FR-004**: favicon MUST 为新版图标的同源简化版本（沿用现有策略：保留三色向右箭头主体，不要求白色辅助符号），颜色与几何语汇 MUST 与完整图标一致；MUST 为纯矢量、透明背景、不依赖字体或外部资源；MUST 与完整图标在同一次变更中更新，MUST NOT 保留与新版图标不一致的旧图标或旧引用；favicon 无需单独评审（SC-006 不覆盖 favicon），验收仅按 SC-002 的 16px 口径执行。
- **FR-005**: 两份图标资产 MUST 为纯矢量、单一自包含文件（无外部引用、无字体依赖、无内嵌位图），画布边界 MUST 贴合图形内容（无裁切、无异常留白；favicon 方形画布对宽幅标识的居中留白为规范留白，不属异常留白），可无损缩放；MUST 存放在仓库内并通过既有站点配置引用（不改变配置结构、不新增字段）；MUST NOT 引入任何运行时或构建依赖。
- **FR-006**: 图标替换 MUST NOT 改变顶栏品牌区的结构、行为与既有版式规则：仍为"左 logo + 右文字 CIGMA"、logo 与文字等高、整体链接回主页、logo 为装饰性图形且不被点击放大；新版图标 MUST 按其原始宽高比展示，MUST NOT 被拉伸、压缩或裁切；图标替换 MAY 带来不超过宽高比允许范围（±20%）的天然宽度变化，但 MUST NOT 引起导航换行、重叠、截断、挤压或页面横向滚动；字体、字号、间距、配色与页面其余布局 MUST 保持不变；全部页面 MUST 一致呈现。
- **FR-007**: 本轮变更 MUST 仅限图标资产本身及其必要的展示尺寸适配；MUST NOT 改动课题组命名、文案、字体、颜色变量、页面布局或任何其他内容；MUST NOT 新增页面、路由或图标使用场景（如分享卡片、头像、PWA/触屏图标、动效版本）。
- **FR-008**: 替换后 MUST 通过仓库既有的检查与构建门禁（100% 通过），站点品牌数据校验（图标资源存在性与路径合法性）MUST 继续生效；页面 MUST 在四档验收视口（375px / 768px / 1024px / ≥1280px）及 320px 最窄下限下无布局破损（沿用既定口径：元素重叠、文字截断、内容溢出、非预期换行、页面横向溢出）。
- **FR-009**: 设计阶段 MUST 同时产出三版候选标识，三版均 MUST 满足 FR-001 身份不变量（含 ±20% / ≤20% 放宽口径），候选阶段的身份不变量核查由维护者在对比页评审时执行；三版之间的探索跨度（保守/中度/大胆的差异化）不作为需求定义，由设计阶段裁量。三版候选与现有图标 MUST 通过单一并排对比页呈现供维护者选定，页内每版 MUST 同时展示 ≥64px、约 22px（顶栏实际高度）、16px 三档尺寸下的渲染效果（16px 一行为完整图标缩至 16px 的模拟渲染，favicon 按选定版派生，不在候选阶段逐版产出）；候选评审阶段对 SC-002（小尺寸干净）与 SC-003（视觉一致性）仅作目视定性判断（以对比页三档渲染为据，不逐版量化验收），两者的量化验收仅针对选定版执行。维护者 MUST 从三版中选定一版，选定依据除身份不变量（硬性门槛）外不作定义，交由维护者裁量；选定版 MUST 通过 SC-006 外部评审（评审者为未参与设计的实验室老师，由维护者邀请；维护者本人与候选制作方均属"参与设计"，不得担任评审者）后方可进入全站替换（US3）。若维护者无法从三版中选定任何候选，或选定版未通过 SC-006，MUST 迭代候选——重新生成三版候选并重新进入对比评审与选定流程。对比页为评审用临时产物，MUST NOT 进入站点交付物，不构成 FR-007 所禁止的新增页面、路由或图标使用场景。

### Key Entities

- **LogoMark（课题组完整图标）**: 用于顶栏与大尺寸展示的课题组图形标识。关键属性：身份不变量（三枚向右箭头形色块的顺序与方向、1–3 个白色辅助符号及其语义、右下蓝色箭头尖角点缀）、可调属性（色块比例/角度/圆角、符号形态、色值微调）、扁平度、宽高比、在各使用尺寸下的观感与可辨性。
- **FaviconMark（标签页简化图标）**: 由 LogoMark 派生的同源简化版本，用于浏览器标签页。关键属性：三色箭头主体、透明背景、简化程度（不要求白色符号）、与 LogoMark 的同源性、约 16px 下的可辨性。
- **BrandAssetSet（品牌资产对）**: LogoMark 与 FaviconMark 的成对关系及其约束。关键属性：同源一致性、仓库内存储、经既有站点配置引用、构建期存在性校验、不得残留旧资产或旧引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 身份不变量清单 100% 通过——箭头形色块数量为 3、顺序橙→绿→蓝、方向向右；白色辅助符号数量为 1–3 个且至少表达语言/认知/书写中的一种语义；右下蓝色箭头尖角点缀在；三色色相不变且明度/饱和度偏移 ≤20%；整体宽高比相对现状变化 ≤20%；无无关图形与新增装饰；并排比对判为同一标识。
- **SC-002**: 顶栏实际尺寸（约 22px 高）下三色边界清晰、白色符号均匀有意、无糊块/脏边/锯齿；16px favicon 下三色可区分且向右箭头轮廓可辨；64px 以上保留的每个辅助符号可逐个辨认（目视 + 放大核对）。
- **SC-003**: 视觉一致性达标——保留的白色辅助符号统一采用同一种笔画/填充语言（并排目视无"一粗一细"失衡）；主体笔画或等效笔画宽度极差 ≤10%；各符号视觉中心与所属色带中心偏差 ≤色带高度的 5%；符号与色带边缘（含分色边界与外轮廓）的最小安全边距 ≥色带高度的 8%（以新版设计文件测量）。
- **SC-004**: 全站 4 类页面（Home / News 含详情 / Team / Publications）的顶栏与标签页均呈现新图标；仓库内无旧图标资产残留或被引用；顶栏品牌区无导航换行、重叠、截断或挤压，图标比例微调带来的宽度变化 ≤20%，且不引起页面横向滚动。
- **SC-005**: 既有检查与构建门禁 100% 通过；320px 至 ≥1280px 各验收档位无布局破损；无新增依赖；构建期资源校验的负向用例（临时移除或改错资源）仍能报错并中断构建。
- **SC-006**: 评审者为未参与设计的实验室老师（至少 1 人，由维护者邀请）；老师在无提示的并排对照下判定新版为"同一标识的现代化版本"，并确认"更现代、未大改整体设计"——两项判定由同一评审者作出，均须通过。时点：在维护者从三版候选中选定之后、合入代码之前，仅针对选定版。

## Assumptions

- 范围界定："图标"指课题组图形标识（完整 logo）及由其派生的浏览器标签页 favicon；不含文字标识 "CIGMA"、顶栏"logo + 文字"组合方式、命名体系与页面布局——这些已在 004 特性中确定，本轮保持不变。
- "更现代化、不大改整体设计"定义为：允许对色块比例、角度、圆角与白色辅助符号做更大幅度的重绘、替换或合并，但身份不变量（三色向右箭头、至少一处辅助符号、右下蓝色尖角）与整体轮廓必须保持，不重新设计意象。判定沿用 004 的半客观口径（要素级客观清单 + 并排目视比对）。
- 三色色相、排列顺序（橙 → 绿 → 蓝）与向右方向是身份核心，必须保留；允许在色相不变的前提下对明度/饱和度做 ≤20% 的统一微调（005 会话放宽，原 004 CHK021 口径为 ≤10%），不引入渐变。
- 白色辅助符号可以是 1–3 个：允许同语义重绘、替换或合并；但不得全部删除，且合并/替换后仍须读出语言/翻译、认知/大脑、书写/笔中的至少一种语义。
- 顶栏图标显示高度由既有"与 CIGMA 文字等高"规则决定（当前实际约 22px：`1.2em` × `1.15rem` × 16px 根字号，rem 相对 html 根元素解析），本轮不改变该规则，新版图标必须在该尺寸下保持干净；顶栏图标尺寸不作放大处理（放大将改变品牌区高度与既有版式，不属"不大改"范围）。
- 顶栏与较大尺寸使用同一份完整图标资产，不引入顶栏专用小尺寸资产；favicon 仍为同源简化版（简化程度可随新版几何调整）。
- 现有图标在顶栏尺寸下的主要问题是：三个白色符号笔画粗细差异大（文A 粗、笔形细）、大脑符号细节过密（小尺寸糊成白团）、光学对位不一致；本轮以"干净、统一"为主要改进方向，不追求在该尺寸下让所有符号都清晰可读。
- 站点无深色模式；完整图标的实际渲染背景为白色顶栏（浅色），favicon 另须在浏览器深/浅标签栏背景可辨（US2）；深色页面背景、打印、灰度/单色不作要求。
- 不新增 apple-touch-icon、PWA/触屏图标、分享卡片图、头像或动效版本等使用场景；不制作多种配色变体。
- 浏览器对旧 favicon 的缓存可能短暂保留旧图标，不作为缺陷；以强制刷新或新会话验收。
- 无障碍要求沿用 004 口径（logo 为装饰性图形、可访问名由文字提供，不新增对比度/缩放/SVG 语义要求）。
- 现有图标为课题组自有资产，可自由改造并在仓库内分发（沿用 004 CHK029）。
- 现有图标的设计依据与逐字取色见 [004 research.md R1](../004-homepage-branding-refresh/research.md)；部署后线上渲染核对由 CI / 既有维护工作流承载，不属本特性任务（沿用 004 CHK037）。
