# Contract: Team 页响应式布局行为（team-responsive-layout）

**Date**: 2026-10-15（refresh，同步 spec 2026-10-15 澄清） | **Spec**: [spec.md](../spec.md) | **消费方**: Team 页实现与验收（[quickstart.md](../quickstart.md)）、主页回归验证 | **视图实体与数据映射**: [data-model.md](../data-model.md)

本特性契约对象有三：① **Team 页（`/team/`）与主页（`/`）教师区块的响应式布局行为**——"UI 契约"（界面在不同视口下 MUST 呈现的排布规则），后续样式改动的回归基线；② **数据契约**——`graduates.json` 内容按权威源《2026年招生介绍-G3.pptx》合并（FR-011，目标状态见 [data-model.md §1](../data-model.md)）；③ **构建期校验契约**——teachers `photo` 非空时引用文件 MUST 存在，缺失即构建中断（FR-016）。字段级数据约定维持 [001 data-model.md](../001-homepage-rebuild/data-model.md)（含 002 回填的 `github` / 毕业生 `url`），schema 字段定义不变。

断点具体数值以 spec FR-001 为唯一规范源，本契约引用不复述。

## 2. 教师卡片头部排布（FR-003 / CHK008 / CHK009）

- **≥576px**：`.teacher-head` 横向——照片在左、`姓名 / 职称 / 研究方向` 在右；姓名（`h3`）在上、职称（`.teacher-title`）在其下、方向标签紧随其后。照片固定 120×150。
- **<576px**：`.teacher-head` 纵向——照片**水平居中**（于卡片内容区上方，CHK008）；其下信息区为两列 Grid（`1fr auto`）：姓名居左、职称**右对齐**于同一行；研究方向标签区域紧随该行之下、**最大宽度 = 卡片内容区宽度**（占内容整宽，CHK009/CHK038）、左对齐。
- 任一档 MUST NOT 溢出卡片、截断内容或引发横向滚动。
- 无照片（`photo` 为空）：头部仍按上述档位排布，不因缺图错位（边缘用例）；`photo` 非空但文件缺失：构建期报错中断，不渲染破图上线（FR-016）。

## 3. 研究方向标签收纳（FR-004）

- 优先以**整标签为单位**换行（标签之间断行、标签内文字不断开；由 `flex-wrap` 承担）。
- **仅当单个标签自身宽度超过可用行宽时**，才在该标签内文字换行收纳（`max-width:100%` + `overflow-wrap: break-word`）。
- 任何档位 MUST NOT 溢出卡片、截断文字或引发横向滚动。
- **MUST NOT** 依赖 `white-space: nowrap` 防溢出。

## 4. Graduates 排布（FR-006 / CHK010 / FR-008 / FR-009）

- **≥768px**：维持既有**五列混合对齐**形态——第 1/2/3 列（姓名 / 学位 / 毕业年份）左对齐固定轨道，第 4 列（去向）`minmax(0,1fr)` 居中且列内可换行，第 5 列（链接）标签右对齐固定轨道；列表满宽、行左右 padding 对称（24px）。本次窄屏改动 MUST NOT 对其引入回归（FR-009）。
- **<768px**：**三段式**——
  - **第 1 行**：姓名居左；右侧自右向左依次为**毕业年份**与**学位**——年份右对齐贴行右缘、**其容器宽度与年份数字等宽**（CHK010）；学位位于年份左侧、**与年份之间留一个空格间距**、**学位文字右对齐**；
  - **第 2 行**：去向（跨整宽、**左对齐**）；
  - **第 3 行**：外链标签 `Homepage↗` / `GitHub↗`（如有，跨整宽、**左对齐**——取代 002 窄屏链接右对齐的既有做法）。
- **缺失字段**（FR-008）：`year` 为空 → 第 1 行右侧仅展示学位（右对齐贴行右缘）、不渲染年份；`url` 与 `github` 皆空 → 不渲染第 3 行；均不渲染占位文本或符号（如 N/A、—），不残留空行。空列/空行靠布局自动塌缩。
- 去向文字较长或中英混排：在所在行内换行，不溢出、不破坏三行左起点节奏。
- **数据内容**（FR-011）：条目集合 5 → 14 条（更新 5 + 新增 9，目标状态见 data-model §1）；匿名新条目（`year=null`、无链接）按上述缺失字段规则呈现；毕业生与在读学生重复内容不做去重。

## 5. 跨区块列对齐（FR-007 / CHK035）

- **<768px**：毕业生条目的姓名起始位置 MUST 与在读学生条目的姓名起始位置一致——二者左边缘落在同一条竖直线上（起始位置一致，跨区块列对齐）。
- 实现依据：同一容器内容左缘 + **相同的 24px 左右内边距**（毕业生 `li` `padding: 10px 24px` 与在读学生 `li` `padding: 8px 24px`，自现状 44px 统一收窄、左右对称，两处 MUST 一起修改）。
- 验收测量：DevTools 读取两姓名 `getBoundingClientRect().left`，差值 ≤ 1px（SC-004）。

## 6. 共享组件与回归范围（FR-012 / CHK034）

`TeacherCard.astro` 同时服务 Team 页（`detailed`）与主页 Team 概览（`compact`）：

- 头部按档排布与标签收纳规则随组件改动**同步生效于主页**（US3 AS2）；
- 主页 `.teacher-grid` 同步采用 US1 的 3/2/1 分档（US3 AS2）；
- 主页实例**展示的内容（字段与数据）可与 Team 页不同**，但布局行为 MUST 与 Team 页一致——分栏数量、卡片头部按档排布、标签收纳三者 MUST 一致（CHK034）；
- 主页在各验收档位下 MUST NOT 出现新的布局破损（SC-006）。
- `StudentGroup.astro` 本特性仅改 `li` 内边距（44→24px，FR-007 组成部分），其余零改动，并作为 FR-007 对齐基准。

## 7. 溢出保证（全视口）

- 各验收档位（≥1280 / 1279 / 1024 / 768 / 767 / 576 / 575 / 375px，覆盖至 320px）下，Team 页与主页无横向滚动（页面底部不出现水平滚动条、整页在屏幕宽度范围内完整显示）、内容不被裁切。
- 布局破损判定口径（CHK011/CHK012）：元素重叠、文字截断、内容溢出容器、非预期换行、页面横向溢出。

## 8. 构建期校验（FR-016 / SC-009）

- 教师 `photo` 字段非空时，其引用的图片文件 MUST 存在于 `public/teachers/`（`/teachers/<文件名>` 形态，禁嵌套路径与 `..`）；缺失或形态非法 → 构建**报错并中断**，报错信息定位数据文件、教师姓名与缺失路径。
- `photo` 为空不校验（缺照片为合法展示状态）。
- 该校验随 `astro build` 与 CI 执行；负向用例（临时构造缺失引用 → 构建失败 → 还原 → 构建恢复）为验收必测项。

## 9. 不变量（本特性 MUST NOT 改变）

- **数据不变量（FR-015）**：除 `graduates.json` 内容（FR-011，以 PPTX 为权威源）与 teachers `photo` 存在性校验逻辑（FR-016 显式例外）外，其余数据文件（teachers / students / publications / gallery / site）、全部 schema 字段定义、构建配置、CI 流程零改动；
- 页面展示的信息集合：教师/在读学生全部字段与链接取值原样不变；毕业生条目按 FR-011 更新（内容准确性以《2026年招生介绍-G3.pptx》为准，真名/年份/链接待补齐前以匿名 + `null` 显式留空）；
- 视觉基调不变（色板、卡片风格、正文字号 ≥18px）；零新增 JS 与运行时依赖（FR-013）；
- 既有 `body { overflow-x: hidden }` 防线保留；
- 既有的在读学生两端分布、学生 `GitHub↗` 标签、毕业生 ≥768px 五列形态与 `Homepage↗`/`GitHub↗` 标签、毕业生排序规则（002 FR-012）等行为不变（仅条目集合扩大至 14 条）。
