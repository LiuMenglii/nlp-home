# Feature Specification: Team 页多分辨率响应式布局（Team Responsive Layout）

**Feature Branch**: `003-team-responsive-layout`

**Created**: 2026-10-14

**Status**: Draft

**Input**: User description: "写出更完整的不同分辨率下的行为布局：1. 教师介绍——宽屏下每行展示三个教师框；中等宽度下每行两个；较低宽度下每行一个；很低的宽度下仍将老师的姓名、职称、研究方向放在图片右侧（类似图一），单个研究方向如果一排写不下就在框内换行。2. 毕业生部分在窄屏幕的行为：第一行姓名居左、学位与年份右对齐，第二行去向，第三行 Homepage；使毕业生姓名在垂直方向上与上方在读学生姓名对齐。"

## 目标与范围

本特性为 Team 页（`/team/`）补齐**按视口宽度分档的响应式布局行为**，覆盖两处：

1. **Faculty 教师卡片**：随视口宽度改变每行卡片数量（宽屏 3 / 中等 2 / 窄 1 / 很窄 1），并规定四档下卡片头部的内部排布（宽屏、中等、窄档为照片在左、信息在右；很窄档为照片水平居中在上、姓名与职称同行）与研究方向标签的换行收纳规则。
2. **Graduates 毕业生列表**：规定窄屏（<768px）下的条目排布（姓名 + 右对齐的学位/年份 / 去向 / 链接），并使其姓名与上方在读学生姓名对齐。

本特性以表现层（模板 + 样式）改动为主；数据改动仅限毕业生数据——依据《2026年招生介绍-G3.pptx》完善毕业生名单（FR-011/FR-015），其余数据不改动。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 教师卡片分栏随宽度响应 (Priority: P1)

访客在不同宽度的屏幕上浏览 Faculty 部分：宽屏（≥1280px）每行三张卡片；中等（768px–<1280px）每行两张；窄（576px–<768px）与很窄（<576px）每行一张。卡片头部随档位给出稳定排布：宽屏、中等、窄档保持「照片在左、姓名/职称/研究方向在右」的横向排布（类似图一）；很窄档改为「照片水平居中置于上方；其下姓名与职称同行——姓名居左、职称右对齐；研究方向标签紧随其下」。当某个研究方向标签在一行内放不下时，收纳规则明确、不溢出。

**Why this priority**: 教师分栏数量直接决定 Faculty 信息的浏览密度与空间利用，是本特性用户最首要的明确诉求；当前宽屏每行仅两张、同档内留白偏多，属最直观的观感缺陷。窄档保留照片在左的横向排布，修复了移动端卡片头部堆叠造成的头图与信息割裂。

**Independent Test**: 在 ≥1280px / 1279px / 1024px / 768px / 767px / 576px / 575px / 375px 各验证视口打开 Team 页 Faculty 部分，逐档统计每行卡片数量（1279 / 767 / 575 为边界紧下方的档位切换验证点）；在 576px 档核对头部照片在左、信息在右；在 375px 档核对照片水平居中在上、姓名与职称同行且职称右对齐；对超长研究方向标签核对换行收纳是否溢出。

**Acceptance Scenarios**:

1. **Given** 视口 ≥1280px，**When** 浏览 Faculty，**Then** 每行展示 3 张教师卡片，同行卡片等宽、无多余空轨道。
2. **Given** 视口 768px–<1280px，**When** 浏览 Faculty，**Then** 每行展示 2 张教师卡片，同行卡片等宽。
3. **Given** 视口 576px–<768px，**When** 浏览 Faculty，**Then** 每行展示 1 张教师卡片，且卡片头部照片在左、姓名/职称/研究方向在右（名字在照片右侧，横向排布）。
4. **Given** 视口 <576px（含 375px），**When** 浏览 Faculty，**Then** 每行展示 1 张教师卡片，且卡片头部照片水平居中置于上方、其下姓名与职称同行（姓名居左、职称右对齐）。
5. **Given** 任一档位且某位老师的研究方向标签文字较长，**When** 展示，**Then** 标签优先以整标签为单位换行；仅当单个标签自身宽度超过可用宽度时，标签内文字换行收纳；任何情况下不溢出卡片、不截断、不引发横向滚动。

### User Story 2 - 毕业生条目窄屏布局 (Priority: P2)

访客在窄屏（<768px）浏览 Graduates 部分时，每个毕业生条目采用紧凑且整齐的三段式排布：第一行左侧为姓名，右侧自右向左依次为毕业年份与学位——年份右对齐至行右缘、其容器宽度与年份数字等宽；学位位于年份左侧、与年份之间留一个空格、学位文字右对齐；第二行显示去向；第三行显示外链标签（Homepage / GitHub，如有）。毕业生姓名的左起始位置与上方在读学生姓名的左起始位置处于同一条竖直线上，形成跨区块的整齐列对齐。

**Why this priority**: 属对既有窄屏毕业生形态的精修，提升移动端可读性与视觉一致性；窄屏用户群体小于桌面宽屏，且既有形态已可用（非阻断性缺陷），故优先级次于教师分栏。

**Independent Test**: 在 <768px（如 375px）视口打开 Team 页，核对某毕业生条目：第一行左侧是姓名、右侧自右向左为「学位 年份」——年份贴行右缘且其容器与数字等宽、学位与年份之间隔一个空格且文字右对齐；去向独占第二行；链接独占第三行；再比对毕业生姓名与上方在读学生姓名的左边缘是否落在同一条竖直线上。

**Acceptance Scenarios**:

1. **Given** 视口 <768px，**When** 展示某有年份、有链接的毕业生条目，**Then** 第一行左侧为姓名、右侧为「学位 + 年份」（年份右对齐至行右缘且其容器宽度与数字等宽，学位居年份左侧、与年份间隔一个空格且文字右对齐）；第二行为去向（左对齐）；第三行为外链标签（左对齐）。
2. **Given** 某毕业生无毕业年份，**When** 展示，**Then** 第一行右侧仍展示学位（右对齐），不渲染年份占位、不出现多余分隔符或符号。
3. **Given** 某毕业生无任何外链标签，**When** 展示，**Then** 不渲染第三行（链接行），不出现空行残留。
4. **Given** 视口 <768px，**When** 对比毕业生姓名与上方在读学生姓名，**Then** 二者左边缘处于同一条竖直线上（起始位置一致）。
5. **Given** 视口 ≥768px，**When** 浏览 Graduates，**Then** 仍然保持既有五列混合对齐形态（姓名/学位/年份左对齐、去向居中、链接列右对齐），本次窄屏改动不引入桌面形态回归。

### User Story 3 - 跨档位无破损与共享组件一致 (Priority: P3)

访客在各验收档位（含边界切换验证点，见 FR-001）浏览 Team 页全部区块时，页面无任何布局破损、无横向滚动、无内容被裁切；共享的教师卡片组件在主页概览区块同步生效（随组件改动更新），主页在同一组档位下同样不出现新的布局破损。

**Why this priority**: 属回归保障与一致性要求，不新增用户可见的正面价值，仅避免改动波及既有页面；优先级最低但当作为交付门禁。

**Independent Test**: 在各验收档位浏览 Team 页全部区块与主页教师卡片区块，核对无重叠、无截断、无溢出容器、无非预期换行、无横向滚动。

**Acceptance Scenarios**:

1. **Given** 各验收档位（≥1280px / 1279px / 1024px / 768px / 767px / 576px / 575px / 375px，见 FR-001），**When** 浏览 Team 页（Faculty、在读学生、Graduates），**Then** 布局破损数为 0，页面无横向滚动。
2. **Given** 主页教师卡片概览区块，**When** 应用本次改动后浏览各验收档位，**Then** 卡片同样遵循 US1 的分栏与头部排布，且主页无新的布局破损。

### Edge Cases

- 很窄档（<576px，覆盖至 320px）：卡片头部为照片水平居中在上、姓名与职称同行（姓名居左、职称右对齐）；研究方向标签在标签内换行收纳，绝不溢出卡片或引发横向滚动。
- 窄档（576px–<768px）：卡片头部保持照片在左、信息在右；单张卡片占满内容宽度，研究方向标签在同一行放不下时按 FR-004 收纳。
- 教师卡片无照片（`photo` 为空）：头部右侧信息正常排布，不因缺图产生错位。
- 教师照片字段非空但引用的图片文件缺失：构建期报错并中断构建（FR-016），不会带破图上线。
- 研究方向标签文字过长：优先整标签换行（标签间断行、标签内文字不断开）；仅当单个标签自身宽度超过可用宽度时，标签内文字换行；任何情况下不溢出、不截断。
- 毕业生去向文字较长或中英混排：在窄屏去向行内正常换行，不溢出容器、不破坏与其余两行的左起始对齐。
- 毕业生缺年份或缺链接：对应内容不渲染，不产生多余空行、占位文本或符号（如 N/A、—）。
- 毕业生条目与在读学生条目内容重复（同一人两处出现）：按各自数据源原样展示，不做去重或交叉处理（FR-011）。
- 共享教师卡片组件：主页实例随组件改动同步更新展示，主页 MUST NOT 出现新的布局破损（FR-012）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 视口分档口径：宽屏 = ≥1280px；中等 = 768px–<1280px；窄 = 576px–<768px；很窄 = <576px。验收档位 MUST 覆盖 ≥1280px / 1024px / 768px / 576px / 375px，并 MUST 含各边界紧下方的档位切换验证点 1279px / 767px / 575px；并向更窄覆盖至 320px 仍无破损，<320px 设备不作要求（取代 001/002 的旧四档口径）。
- **FR-002**: Faculty 教师卡片的分栏 MUST 按视口分档取值：≥1280px 每行 3 张；768px–<1280px 每行 2 张；576px–<768px 每行 1 张；<576px 每行 1 张。同一行内的卡片 MUST 等宽（判定：同行相邻卡片外缘宽度之差 ≤ 1px）；除末行外 MUST NOT 出现半满轨道或多余空轨道（「行」按网格行轨道计——除最后一行外，每行的卡片数量 MUST 等于该档位列数；末行允许不满）。
- **FR-003**: 教师卡片头部排布 MUST 按视口分档取值：宽屏、中等、窄档（≥576px）保持「照片在左、姓名/职称/研究方向在右」的横向排布（名字在照片右侧）；很窄档（<576px）采用「照片水平居中置于卡片内容区上方；其下姓名与职称同行——姓名居左、职称右对齐；研究方向标签紧随该行之下、占卡片内容整宽（标签区域最大宽度 = 卡片内容区宽度）并左对齐」。任一档位 MUST NOT 溢出卡片、截断内容或引发横向滚动。
- **FR-004**: 教师卡片内的研究方向标签收纳 MUST 遵行：优先以整标签为单位换行（标签之间断行、标签内文字不断开）；仅当单个标签自身宽度超过可用宽度时，采用该标签内文字换行收纳；任何档位 MUST NOT 溢出卡片、截断文字或引发横向滚动。
- **FR-005**: 教师卡片的全部内容（照片、姓名、职称、研究方向、邮箱、主页链接、简介 bio）MUST 在各验收档位下完整可见于卡片内，不被裁切。
- **FR-006**: 窄屏（<768px）下 Graduates 每个条目 MUST 采用三段式排布：第一行左侧为姓名，右侧自右向左依次为毕业年份与学位——年份右对齐至行右缘且其容器宽度与年份数字等宽；学位位于年份左侧、与年份之间留一个空格间距、学位文字右对齐；第二行为去向（左对齐）；第三行为外链标签 Homepage/GitHub（如有，左对齐）。≥768px 档位维持既有五列混合对齐形态不变（见 FR-009）。
- **FR-007**: 窄屏（<768px）下，Graduates 条目的姓名起始位置 MUST 与在读学生条目的姓名起始位置一致——二者左边缘落在同一条竖直线上，形成跨区块列对齐。量化口径（2026-10-15）：两个列表的条目相对各自容器内容左缘的左内边距为同一固定值；验收测量：读取两姓名左边缘 X 坐标（如 DevTools `getBoundingClientRect().left`），差值 ≤ 1px。该固定内边距取 24px——两个列表条目的左右内边距统一收窄为 24px（自现状 44px 收窄，左右对称），此为 FR-007 的组成部分，两处（graduates / students 条目样式）必须一起修改。
- **FR-008**: 缺失字段 MUST 留空、缺失不渲染，且 MUST NOT 渲染任何占位文本或符号：某毕业生 year 为空时第一行右侧仍展示学位（右对齐）、不渲染年份；`url` 与 `github` 均为空时不渲染第三行（链接行），不残留空行。
- **FR-009**: ≥768px 的 Graduates 列表 MUST 保持既有五列混合对齐形态（姓名 / 学位 / 毕业年份左对齐，去向居中，链接列标签右对齐，见 002 FR-003），本次窄屏改动 MUST NOT 对其引入回归；<768px 三段式形态见 FR-006（两档在 768px 处互补、不重叠）。行内距由 FR-007 统一收窄为 24px 属预期变更，不计为回归。
- **FR-010**: Team 页 MUST 在各验收档位（≥1280px / 1024px / 768px / 576px / 375px 及边界切换验证点，见 FR-001）下无布局破损——无元素重叠、文字截断、内容溢出容器、非预期换行、页面横向溢出（即页面不出现水平滚动条、整个页面可在屏幕宽度范围内完整显示；沿用 001 布局破损判定口径）。
- **FR-011**: 毕业生数据 MUST 依据《2026年招生介绍-G3.pptx》「G3 组学生就业情况」表（共 14 条）按以下合并策略完善 `src/data/graduates.json`（2026-10-15 确认）：
  - **新增收录**：PPTX 中尚未收录的 9 条——`name` 用 PPTX 原文（如「许同学」）、`degree` 按类型映射（硕士→master、博士→phd）、`destination` 按毕业去向列录入（原文「->」规范化为「 → 」，即箭头前后各补一个空格）、`year` 置 null、`url`/`github` 留空（真名、毕业年份、链接待正式上线前获得后补齐）；
  - **更新重叠**：既有 5 条与 PPTX 重叠（佀/杨/谭/温/刘），其 `destination` MUST 按 PPTX 毕业去向列更新（如刘源鑫 → 「北京大学 → 小米mimo」），`year` 与 `url` 保留 JSON 现值不动；
  - 毕业生条目与在读学生条目内容重复时 MUST NOT 做去重或交叉处理（CHK037）。
- **FR-012**: 共享的教师卡片组件在主页概览区块的实例 MUST 随本次改动同步生效；主页实例展示的内容（字段与数据）可与 Team 页不同，但其布局行为 MUST 与 Team 页一致——分栏数量、按档头部排布、标签收纳三者 MUST 与 Team 页一致；主页在各验收档位下 MUST NOT 出现新的布局破损。
- **FR-013**: 视觉风格 MUST 保持简洁学术化；MUST NOT 引入装饰性动效或新的运行时依赖（Constitution 原则 IV/V）。
- **FR-014**: 变更后站点 MUST 通过既有构建与 CI 门禁（数据校验 + 构建检查）并正常部署（Constitution 原则 III）。
- **FR-015**: 数据改动 MUST 仅限毕业生数据内容（`src/data/graduates.json`，见 FR-011）；其余数据文件（teachers / students / publications / gallery / site 等）MUST NOT 修改；所有数据 schema（`src/content.config.ts` 字段定义）MUST NOT 修改。其余实现改动 MUST 仅通过页面模板与样式完成（Constitution 原则 II；FR-016 的构建期校验为显式例外）。
- **FR-016**: 构建期数据完整性校验：教师 `photo` 字段非空时其引用的图片文件 MUST 存在；缺失时构建 MUST 报错并中断。该校验逻辑是 FR-015「仅模板与样式」限制的显式例外，随本特性一并交付。

### Key Entities

- **教师卡片（TeacherCard）**：展示一位老师的照片、姓名、职称、研究方向标签、邮箱与主页链接；本特性规定其分栏数量与按档位的头部排布（≥576px 照片在左 / <576px 照片居中在上）、标签换行收纳规则。数据源不变。
- **毕业生条目（Graduate）**：展示姓名、学位、毕业年份、去向与外链标签；本特性规定其窄屏三段式排布及姓名与在读学生姓名的列对齐。数据源为 `graduates.json`，本特性依据《2026年招生介绍-G3.pptx》完善其条目内容（FR-011），schema 不变。

## Assumptions

- **分档映射**：宽屏 = ≥1280px（每行 3 张）、中等 = 768px–<1280px（每行 2 张）、窄 = 576px–<768px（每行 1 张）、很窄 = <576px（每行 1 张）。该映射取代 001/002 旧四档口径，属本次设定的默认验收口径。
- **窄与很窄档均为每行 1 张**：两档差别落在卡片头部——窄档保持「照片在左、信息在右」横向排布；很窄档改为「照片居中在上；姓名与职称同行（姓名居左、职称右对齐）」，取代既有 ≤640px 视口的上下堆叠行为。
- **很窄档（<576px）研究方向标签落位**：已确认为「紧随姓名/职称行之下、占卡片内容整宽、左对齐」，换行收纳遵 FR-004（优先整标签换行，仅单标签自身超宽时才在标签内换行）。
- **窄屏毕业生第三行（链接标签）取左对齐**：姓名、去向、链接三者共用同一左起始位置，仅「学位 + 年份」右对齐。此取代替 002 中窄屏链接右对齐的既有做法；如实际期望链接仍靠右，请在后续澄清中提出。
- **毕业生窄屏分界沿用 <768px（已确认）**：与教师卡片的分档（窄从 576px 起）相互独立，两处各自取值（见 FR-006/FR-007）。
- **「姓名在垂直方向上对齐」的释义**：理解为毕业生姓名与在读学生姓名的**左边缘落在同一条竖直线上**（起始位置一致），而非上下行的位置对齐。
- 除毕业生数据（本特性依据《2026年招生介绍-G3.pptx》完善，见 FR-011/FR-015）外，其余数据条目（教师、在读学生等）仍为占位数据，将在正式审批上线前获得并更新，不属于本特性范围。
- 更长内容（超长姓名/去向/研究方向标签、中英混排）不作为显式需求（2026-10-15 裁定）；布局以实际收录数据为准正常展示，无溢出、无横向滚动仍由 FR-010 保障。
- 浏览器/平台支持不作显式规定，跟随站点既有默认；亚像素/分数边界宽度（如 1279.98px）不作为需求，交由实现所用 CSS 媒体查询的固有行为处理；320px 以下设备不作要求。
- 站点技术栈、构建流程与部署方式不变；视觉色板、字体与整体学术风格不变（Constitution 原则 III/IV）。
- 本特性不引入语义化 HTML 结构与基础无障碍（a11y）要求（Constitution v2.0.0 已移除无障碍底线）。
