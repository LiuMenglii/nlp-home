# Feature Specification: Team 页 PhD Candidates 双栏布局

**Feature Branch**: `010-team-phd-two-column-layout`

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description: "修改Team页面的布局：当前PhD Candidates的表格太空了，请将它写成两栏（也就是将这一片区域做一个分栏处理），同时在页面收窄时退化为一栏。然后把 since 写在表格的第二列，主页的链接写在右侧。"

## 目标与范围

当前 Team 页的 PhD Candidates 名单以单列铺满整个内容区，9 条记录之间横向空白过大，信息密度偏低。本特性把这一片区域改为左右两栏（每栏内部仍按现有顺序逐条排列），同时在横向行（两栏与 ≥480px 单栏）中重排每行内部的信息位置：

1. **姓名**固定在行首（第一列）；
2. **Since 年份**移到第二列，同一栏内各行左缘对齐；
3. **个人主页链接**（Homepage / GitHub / Scholar 中按既有规则选出的唯一标签）贴齐所在栏的右缘。

页面收窄到无法舒适容纳两栏时，整个名单退回单栏；单栏在 ≥480px 仍为横向三列，视口 <480px 时沿用现状的竖排条目（第 1 行姓名与 Since，第 2 行链接），信息顺序保持不变。

**范围之外**：

- Master's Students 分组（当前无在读学生，显示占位文案）的布局与样式；
- Graduates 名单、Faculty 卡片、站点导航、页脚与首页的任何版式；
- 学生数据本身（姓名、level、grade、note、url / github / scholar）、分组内排序规则、链接标签映射与文案；
- 增删成员、修改 "Since" 文案、修改配色、字体、字号、分隔线风格；
- 新增折叠、筛选、分页、动效等交互；
- 列标题行（如 Name / Since 表头）、列间竖线或其他额外装饰。

## Clarifications

### Session 2026-11-20

- Q: 双栏退化为单栏的断点如何选取？边界精度如何验收？ → A: 与教师名片变为单列（每行一张）的断点保持同一阈值：视口 ≥768px 为两栏、<768px 为单栏；按整数视口宽度验收，不考虑次像素级别的边界行为。
- Q: 记录数为 n 时，两栏各放多少条？ → A: n 为偶数时两栏均分（n/2 与 n/2）；n 为奇数时左栏为 floor(n/2)+1 条、右栏为 floor(n/2) 条（除号向下取整）；n=1 时只有左栏 1 条，不渲染空的右栏。
- Q: 窄屏的「竖排表格」形态是否保留，阈值取多少？ → A: 保留现状设计：视口 <480px 时每条记录改为竖排两行（第 1 行姓名居左、Since 右对齐；第 2 行链接独占一行、与姓名左缘对齐），阈值沿用现状媒体查询（<480px 竖排、≥480px 横向行）；≥768px 仍为两栏。
- Q: spec 中季慧山的年级描述与数据不符，如何处理？ → A: 以 `src/data/students.json` 为准修正：季慧山有 `Since 2021`、无链接；无年级者为李江楠、刘曦雨、刘正宵（6 条 Since、8 个链接不变）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 宽屏下 PhD Candidates 呈左右两栏 (Priority: P1)

访问者在视口宽度 ≥768px 打开 Team 页时，PhD Candidates 的 9 位同学分布在左右两栏：两栏等宽、顶线一致，每栏各约半个内容区宽；分组标题仍横跨整个内容区，位于两栏上方。相比现状，单条记录不再横跨整行，姓名与链接之间的距离明显缩短。

**Why this priority**: "表格太空"是本特性的直接动因；两栏排布是消除横向空旷感的核心结果，也是用户在需求中点名的第一项。

**Independent Test**: 在 1440 / 1280 / 1024 / 768px 四档视口打开 Team 页，测量两栏宽度、条数分布与顶线位置；即使行内列顺序尚未调整，也能独立确认两栏结构成立。

**Acceptance Scenarios**:

1. **Given** 视口宽度 ≥768px，**When** 浏览 Team 页 PhD Candidates 区域，**Then** 9 条记录按 5 条左栏、4 条右栏分成两栏，两栏宽度差 ≤1px。
2. **Given** 视口宽度 ≥768px，**When** 对比两栏容器，**Then** 两栏顶线一致（差值 ≤1px），栏间保留固定间隔，任何一条记录都不再横跨整个内容区。
3. **Given** 分组标题 "PhD Candidates"，**When** 页面渲染，**Then** 标题只出现一次，横跨内容区全宽并位于两栏上方，不随栏数变化而复制。

---

### User Story 2 - 每行按「姓名 → Since → 右侧链接」分层 (Priority: P1)

访问者浏览任一栏时，每行的信息从左到右依次为姓名、Since 年份、个人链接；Since 在第二列，各行左缘对齐；链接贴齐所在栏右缘，各行右缘对齐。没有年级或没有链接的成员不显示占位内容，但其余字段的位置保持不变。

**Why this priority**: 这是用户明确要求的行内信息重排；它决定名单是否仍然读得顺、对得齐，与两栏结构同等重要。

**Independent Test**: 在 1440px 视口逐行检查 9 条记录：确认视觉顺序为姓名 → Since → 链接；抽查有年级、无年级、有链接、无链接四种组合；用元素外接矩形核对 Since 左缘与链接右缘的对齐。

**Acceptance Scenarios**:

1. **Given** 任一有年级的成员（如张瀚文），**When** 该行渲染，**Then** 显示顺序为姓名、`Since 2020`、右侧链接，Since 位于姓名右侧的第二列位置。
2. **Given** 同一栏内的两个有年级成员，**When** 比较其 Since 文本元素，**Then** 两者左缘水平差值 ≤1px（第二列对齐）。
3. **Given** 任一有链接的成员，**When** 比较其链接元素与所在栏右缘，**Then** 链接右缘与栏右缘（扣除固定内距）差值 ≤1px；标签文案仍为 Homepage / GitHub / Scholar 之一，不新增或改写。
4. **Given** 李江楠、刘曦雨、刘正宵（无年级、有链接），**When** 该行渲染，**Then** 第二列为空，不出现 "Since" 占位或破折号，链接仍贴齐右侧。
5. **Given** 季慧山（有 Since 2021、无链接），**When** 该行渲染，**Then** 第二列显示 `Since 2021`，右侧区域为空，不出现空链接、隐藏链接文本或其他伪造内容。
6. **Given** 姓名，**When** 检查可点击区域，**Then** 姓名仍为纯文本，唯一链接出口仍为右侧标签。

---

### User Story 3 - 页面收窄时退化为单栏与竖排条目 (Priority: P2)

访问者在窄屏（手机）打开 Team 页时，PhD Candidates 退回单栏：480–767px 保持横向行（姓名 → Since → 右侧链接），每条记录横跨内容区；<480px 沿用现状的竖排条目——第 1 行姓名居左、Since 右对齐，第 2 行链接独占一行并靠左。两种窄屏形态都不出现半栏、空白第二栏或横向滚动。

**Why this priority**: 两栏在窄屏会挤压信息；退化规则保证移动端可读性。竖排阈值沿用现状（<480px），保证本次分栏改动不改变已上线的手机阅读形态。

**Independent Test**: 在 767 / 576 / 481 / 480 / 375 / 320px 六档视口检查：仅一栏、9 条记录顺序不变；481 / 480px 为横向行且链接靠右；375 / 320px 为竖排两行（姓名与 Since 同行、链接下一行靠左）；无重叠、截断、溢出与页面横向滚动。

**Acceptance Scenarios**:

1. **Given** 视口宽度 <768px，**When** 浏览 PhD Candidates，**Then** 9 条记录以单栏、自上而下呈现；不渲染空的第二栏，也不出现两栏压缩后的半宽列。
2. **Given** 480px ≤ 视口宽度 < 768px，**When** 检查任一行，**Then** 姓名居左、Since 紧随其后、链接靠右，链接右缘与内容区右缘（扣除固定内距）差值 ≤1px。
3. **Given** 视口宽度 <480px，**When** 检查任一行，**Then** 第 1 行姓名居左、Since 右对齐（右缘与内容区右缘扣除固定内距的差值 ≤1px），第 2 行链接独占一行、左缘与姓名左缘对齐（差值 ≤1px）；无年级/无链接成员不渲染占位。
4. **Given** 320px 最窄视口，**When** 浏览整页，**Then** 无元素重叠、文字截断、内容溢出、非预期换行或页面横向滚动。

### Edge Cases

- **PhD 名单为空**：沿用既有 "PhD candidates coming soon." 占位文案，占满内容区整行，不渲染空的第二栏。
- **仅 1 条记录**：单栏呈现且记录占满内容区整宽（≥768px 时同样不得只占半栏），不为了凑两栏而渲染空栏。
- **记录数决定两栏分布**：n 为偶数时均分（如 n=8 → 4 + 4）；n 为奇数时左栏比右栏多 1 条，即左栏 floor(n/2)+1、右栏 floor(n/2)（当前 n=9 → 5 + 4）；n=1 时仅左栏 1 条并占满内容区整宽，不渲染空栏。
- **成员无年级**（当前为李江楠、刘曦雨、刘正宵）：横向行中第二列留空，不渲染 "Since" 或破折号占位；竖排态第 1 行仅姓名、不渲染占位；该行链接位置按对应形态的规则处理，行高与同形态其他行一致。
- **成员无链接**（当前为季慧山）：横向行中右侧区域留空；竖排态不渲染第 2 行；不渲染链接锚点、隐藏文案或占位符。
- **成员有备注（note）**：备注仍需展示，且不得把链接挤出栏右缘或与姓名、年份重叠（当前数据无备注）。
- **姓名或标签超长**：姓名（含无空格拉丁字符串）MUST 在所属栏的姓名槽内换行收纳，不得越入 Since 列、溢出栏边界、相互重叠或撑宽页面；链接标签本身保持单行。
- **断点边界**：视口 768px 按两栏呈现，767px 及以下按单栏呈现；480px 及以上为横向行，479px 及以下为竖排条目；按整数视口宽度验收，不考虑次像素级别的边界行为。
- **内容区被 1180px 上限约束**：超宽视口下两栏宽度不再继续增大，仍等宽、顶线一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 视口宽度 ≥768px 时，PhD Candidates 名单 MUST 以左右两栏呈现；两栏 MUST 等宽（宽度差 ≤1px），顶线一致（差值 ≤1px），并保留明确栏间距（实现值 32px）。该阈值为整数视口宽度，与教师名片变为单列（每行一张）的断点一致。
- **FR-002**: 视口宽度 <768px 时，同一名单 MUST 退化为单栏；其中 480px ≤ 视口 < 768px 时每条记录横跨内容区整宽并保持横向三列；视口 <480px 时 MUST 沿用现状竖排条目（第 1 行姓名居左、Since 右对齐，第 2 行链接独占一行、靠左）。两种形态 MUST NOT 保留空栏或半宽列。边界按整数视口宽度验收，不考虑次像素级别的行为。
- **FR-003**: 记录数为 n（n ≥ 2）时 MUST 按现有显示顺序拆分并保持顺序：n 为偶数时两栏各 n/2 条；n 为奇数时左栏 floor(n/2)+1 条、右栏 floor(n/2) 条（向下取整）；左栏自上而下先排列前 floor(n/2)+1 条（n 为偶数时为前 n/2 条），其余按同一顺序进入右栏。n=1 时仅左栏 1 条并占满内容区整宽，不渲染空栏。现有排序规则（年级降序 → 无年级在最后 → 同级保持数据文件顺序）MUST NOT 改变。
- **FR-004**: 信息视觉顺序 MUST 为「姓名 → Since 年份 → 个人链接」。横向行（≥480px）中：姓名在最左侧，`Since <年份>` 位于第二列，个人链接贴齐所在栏右缘；竖排态（<480px）中：第 1 行为姓名（左）与 Since（右对齐），第 2 行为链接（左对齐）。
- **FR-005**: 横向行中，同一栏内所有行的 Since 文本 MUST 左对齐到同一条竖直线（水平差值 ≤1px）；竖排态中，所有行的 Since 右缘 MUST 对齐到同一条竖直线（差值 ≤1px）。无年级的行 MUST 不渲染 Since 元素与任何占位文案，MUST NOT 影响其他行的槽位位置。
- **FR-006**: 横向行中，同一栏内所有链接标签的右缘 MUST 对齐到同一条竖直线（差值 ≤1px），并贴齐该栏右缘（扣除固定内距）；竖排态中，链接独占一行，其左缘 MUST 与姓名左缘对齐（差值 ≤1px）。标签仍按 `url` → `github` → `scholar` 取第一个非空字段，文案与箭头形态不变。
- **FR-007**: 无链接成员 MUST 不渲染链接锚点、隐藏链接文本或任何占位；姓名 MUST NOT 变为链接。
- **FR-008**: 两栏的左、右外缘 MUST 与内容区左右边缘对齐（差值 ≤1px）；左栏姓名的左缘 MUST 仍与 Graduates 名单姓名左缘同线（沿用 24px 对称内距），该跨区块对齐 MUST NOT 因分栏而失效。
- **FR-009**: 单栏（<768px）状态下，行内顺序与对齐 MUST 与 FR-002、FR-004、FR-005、FR-006 的对应条款完全一致，不引入第二套规则；两种形态下每行均横跨内容区整宽。
- **FR-010**: 全部 9 条记录 MUST 完整呈现且仅呈现一次：6 条 `Since` 文案（2020/2021/2022）、8 个链接标签；不得丢失、重复或改写任何成员信息。
- **FR-011**: 本特性 MUST 只影响 Team 页 PhD Candidates 区域；学生数据文件、Master's Students 分组、Graduates 名单、Faculty 区块与其他页面 MUST 保持不变；MUST NOT 新增运行时依赖、脚本或组件。
- **FR-012**: 构建与类型检查 MUST 通过；在支持的十一档视口（1920 / 1440 / 1280 / 1024 / 768 / 767 / 576 / 481 / 480 / 375 / 320px）下 MUST 无布局破损（元素重叠、文字截断、内容溢出、非预期换行、页面横向滚动）。

### Key Entities

- **PhD 成员条目**：姓名、入学年份（grade，可为空）、唯一链接（url / github / scholar 三选一，可为空）、备注（note，可为空）；本特性只改变其展示位置，不改变数据。
- **双栏名单区域**：由分组标题 + 两栏（或单栏）条目构成；栏数随视口宽度在 2 与 1 之间切换，单栏在 <480px 进一步切换为竖排条目。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 1440、1280、1024、768px 四档视口下，9 条记录按 5 + 4 分布为两栏，两栏宽度差 ≤1px、顶线差 ≤1px，单条记录宽度不超过内容区一半（容差 1px）。
- **SC-002**: 在 767、576、481、480px 四档视口下，名单为单栏横向行、共 9 条，链接靠右；在 375、320px 下为单栏竖排（第 1 行姓名与 Since、第 2 行链接靠左）；六档均无空栏、半宽列或页面横向滚动。
- **SC-003**: 9/9 条记录的阅读顺序为姓名 → Since → 链接（竖排态为第 1 行姓名与 Since、第 2 行链接）；全页恰有 6 条 Since 文案与 8 个成员链接标签，0 丢失、0 重复、0 伪造占位。
- **SC-004**: 双栏与 ≥480px 单栏横向行中，同栏 Since 左缘差值 ≤1px、链接右缘差值 ≤1px；<480px 竖排态中，Since 右缘差值 ≤1px、链接左缘与姓名左缘差值 ≤1px；各形态下列外缘与内容区边缘差值 ≤1px，姓名左缘与 Graduates 姓名左缘差值 ≤1px。
- **SC-005**: 十一档视口逐项检查，布局破损计数为 0（元素重叠、文字截断、内容溢出、非预期换行、页面横向滚动）。
- **SC-006**: 站点构建与类型检查通过；变更仅涉及 Team 页 PhD Candidates 的展示实现，学生数据、其他分组与其他页面零改动。

## Assumptions

- **断点与教师名片一致（768px）**：用户明确要求分栏断点与教师名片变为单列（每行一张）的断点相同，即 ≥768px 两栏、<768px 单栏；按整数视口宽度验收，不验收次像素边界。768px 视口的内容区约 720px，两栏各约 344px，行内可用宽度较紧；实现 MUST 通过收紧姓名列、Since 列与字段间距来保持「姓名 → Since → 链接」单行三列，MUST NOT 以截断、隐藏链接、缩小字号或破坏页面布局的方式换取两栏。
- **竖排阈值与现状一致（480px）**：用户要求保留现有「窄屏竖排表格」设计，阈值沿用现状媒体查询——视口 <480px 为竖排两行（第 1 行姓名与 Since、第 2 行链接靠左），480px 及以上为横向行；按整数视口宽度验收（479px 及以下竖排、480px 及以上横向）。竖排态不改变姓名、Since、链接的文案与阅读顺序。
- **栏内填充采用列优先且按公式均分**：先填满左栏再续到右栏；n 为偶数时两栏各 n/2 条，n 为奇数时左栏 floor(n/2)+1 条、右栏 floor(n/2) 条（当前 9 条为左 5、右 4），保证按年级排序的阅读连续性。
- **"主页的链接"**指成员唯一的个人链接标签，沿用既有 Homepage / GitHub / Scholar 映射与文案，不新增加第二个链接。
- **Since 文案保持不变**：第二列仍显示 `Since <年份>`（而非裸年份），不加列标题行。
- **备注**：当前数据 9 人均无备注；若未来出现备注，按既有展示习惯保留，不得导致链接离开右缘或文字重叠。
- **当前数据快照**：PhD Candidates 共 9 人，其中 6 人有年级、8 人有链接；排序与链接标签矩阵以 2026-11-20 的 `src/data/students.json` 为准，仅作为验收基准，不作为永久数据约束。
- **Master's Students**：当前为空分组，保持既有占位文案与单列样式，不在本特性范围内；其未来若新增成员，沿用何种行内布局另行决策。
- **验收口径**：沿用项目既有十一档视口矩阵（含 1440px）与真实浏览器渲染；200% 缩放与最小字号检查不纳入本期（与 007 口径一致）。
